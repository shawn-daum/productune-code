- (2026-06-08) T-PATCH-066 — Sandboxed-iframe artifact app-shortcuts: a renderer-only postMessage bridge (re-dispatch synthetic KeyboardEvent on window) is statically sound but its iframe→parent leg is not headless-verifiable and a macOS Electron default menu accelerator can swallow keys (e.g. cmd+W) before the frame sees them. RESOLUTION (shawn): capture shortcuts in the Electron MAIN process via webContents `before-input-event` → IPC → renderer handlers, sidestepping iframe focus routing entirely; plus promote the clicked pane to active on iframe focus (D1). Renderer-only bridge is not worth a 4th iteration. Reference point for any future webview/iframe keyboard-routing work.

- (2026-06-08) T-PATCH-066 — Electron OOPIF sandboxed iframe keyboard: ONLY menu accelerators reach app shortcuts when focus is INSIDE the sandboxed iframe. before-input-event (host frame) AND renderer window-keydown both miss the OOPIF (keys go to the iframe's own renderer process). Proof: cmd+F (menu accel) works after clicking in the iframe; cmd+T/W (before-input-event) don't. Register all app shortcuts as menu accelerators (sendToFocused('menu:*')).
