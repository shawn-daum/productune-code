## Request

**팀 공유용 "얇은 티켓 + 브랜치 룰" 문서 (shawn 승인, 2026-07-16)**: productune에 비의존적인 단독 md — 팀 동료가 prdt/dogany 없이도 그대로 따라할 수 있는 cross-repo git·티켓 규칙. 팀은 한 repo를 공동 관리하지 않고 각자 repo를 관리하므로, repo가 달라도 동일하게 적용되는 규칙이어야 함.

승인된 구도:

- **두 모드 명기** — repo 성격 따라 선택:
  - **솔로 모드**: trunk — main 상주, push = 배포 게이트
  - **팀 모드**: **dev 상주 + main = 배포 전용**. feature branch → PR → dev · **dev → main merge = 배포 행위** · main 직접 push 금지 · tag는 main에
- **branch**: `feat/T-NNN-slug` · `fix/T-NNN-slug` — 수명 며칠 이내, merge 후 삭제
- **commit**: Conventional Commits + 티켓 id — `feat: ... (T-NNN)`
- **ticket**: 얇게 4요소 — id · status(open/done) · Request · Acceptance, md 파일 하나
- **deploy**: main tag 기준 · rollback = 이전 tag
- 배경 컨텍스트(선택 반영): 코드/메타 git 분리 패턴 — 메타는 선형 단일 타임라인, 코드만 branch

## Acceptance

- Standalone md at `docs/artifacts/team-git-ticket-rules.md` — no prdt/productune dependency in its instructions; a teammate can adopt it on any repo as-is.
- Covers both solo and team modes with the approved rules above (dev-resident/main-deploy for team).
- Thin ticket format specified with a copy-pasteable template.
