## Request

**v1.2 메인 트랙 (shawn 결정, 2026-07-16)**: prdt 관리 프로젝트의 **실행 코드 / 메타 분리** — GitHub(origin)에는 실제 돌아가는 코드만 올라가도록.

- **문제**: prdt 프로젝트는 한 working tree에 실행 코드(`packages/` 등)와 코드 메타(`docs/` 티켓·wiki·PRD·retro, `.prdt/` 상태, `briefs/` 등)가 섞여 있고 전부 origin에 push됨. productune 자체도 tracked 파일 604(docs) vs 461(code)로 메타가 절반 이상.
- **방식 (shawn 결정, 2026-07-16)**: **메타 전용 로컬 git** — 메타 파일군을 코드 repo 추적에서 제외하고, prdt가 별도 로컬 git으로 자동 커밋/관리. 히스토리 보존(doctrine: markdown is source of truth), origin에는 코드만. 메타의 원격 백업은 옵션으로 열어둠.
- **범위**: prdt **CLI + GUI 둘 다** 이 방식으로 동작 — 신규 프로젝트 init 시 기본 적용 + 기존 프로젝트 마이그레이션 경로 제공.
- **경계 질문 (PRD에서 확정)**:
  - 메타/코드 경계 정의 — `docs/`, `.prdt/`, `briefs/` 외 무엇까지? (예: `DEPLOY.md`·`README.md`는 코드 쪽? `.productune/`은?)
  - 메타 git 자동 커밋 시점/단위 (턴 종료? stage 전환? 티켓 변경?)
  - 코드 repo `.gitignore` 관리 주체 (prdt가 주입/유지)
  - 기존 origin에 이미 push된 메타의 처리 — 이후 추적 제거만 vs 히스토리 rewrite
- 상세 스코프는 v1.2 PRD에서 확정.

## Acceptance

- prdt 관리 프로젝트에서 메타 변경이 코드 repo(origin) 커밋/`git status`에 나타나지 않는다.
- 메타는 별도 로컬 git에서 히스토리와 함께 조회 가능하다.
- CLI·GUI 어느 쪽에서 작업해도 동일하게 동작한다.
