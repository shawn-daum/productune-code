## Request

**GUI UX 이슈 (shawn, 2026-07-13)**: GUI가 "prdt discipline hook을 설치할 수 없어요 — 이 기기에서 prdt install.sh(packages/core/scripts)를 먼저 실행하세요"라고 사용자에게 쉘 스크립트 실행을 요구함.

- 발생 경위: T-336이 새 hook(`prdt-user-prompt.sh`)을 추가 → GUI onboarding이 등록하려는데 `~/.prdt` 미러에 파일이 없어(install.sh 미실행 기기) 안내만 띄우고 중단.
- 문제: 기획자(비개발자)가 주 사용자인 GUI가 터미널 작업을 요구하는 것은 제품 UX로 부적절. hook 스크립트 원본은 앱이 이미 알고 있는 리소스이므로 자가 설치가 가능해야 함.
- 방향 (설계 판단): GUI onboarding이 hook 파일 미러링/settings 등록까지 스스로 수행 (install.sh와 동일한 결과, 멱등). 실패 시에만 지금의 안내로 fallback. 단 사용자 커스텀 settings 무클로버 원칙은 install.sh와 동일하게 유지.

## Acceptance

- On a machine where `~/.prdt` lacks a newly-added hook, the GUI installs/mirrors it itself (idempotent, no clobbering of user-custom settings) and registers it — no terminal instruction shown in the normal path.
- The install.sh path and the GUI path converge on identical results; re-running either is a no-op.
- The terminal-instruction message appears only when self-install genuinely fails (permissions etc.).
