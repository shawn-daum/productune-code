## Request

**T-336 진단 중 발견된 별건 (hanta)**: PO가 v1 빌드 **전체를 티켓 0개로** 진행함.

- 증거: hanta tickets 디렉토리 빈 상태, `turns.jsonl` 전 라인 `ticket_id: null`, 그런데 dispatch는 정상 발생. inbox append도 0회.
- 유력 원인: migration이 "0 tickets"로 시드한 것이 ticketless 흐름을 정상처럼 보이게 만든 듯 — contracts 위반이고, ship 단계의 stage-exhaustion 신호("open tickets 0 → 다음 단계 제안")를 영구히 눈멀게 함.
- 진단 필요: PO가 왜 contracts의 "deliverable work gets a ticket"을 한 번도 이행하지 않았는지 (migration 컨텍스트가 면죄부가 됐는지, habit 문구 갭인지), 그리고 재발 방지 수단 (habit 강화 / doctor 경고 / hook backstop 등 비례 판단).

## Acceptance

- (진단 후 상세화) Root cause identified with evidence (hanta transcript/turns.jsonl).
- A PO dispatching deliverable work without an open ticket is reliably surfaced or prevented (proportionate mechanism).
- Migration-seeded projects ("0 tickets") do not normalize ticketless flow.
