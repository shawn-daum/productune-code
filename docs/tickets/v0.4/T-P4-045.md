## §1 Decision

Explorer = ActivityBar 의 **Explorer** 탭이 활성일 때 LeftSidebar 가 렌더하는 분기.
T-P4-040 의 4 탭 (`explorer | search | git | settings`) 중 `explorer` 탭이 default.
`<LeftSidebar>` 안에서 `activeActivity === 'explorer'` 일 때 `<ExplorerPane>` mount.

```
ActivityBar(Tab=explorer)  →  LeftSidebar
                                └─ ExplorerPane
                                    ├─ Header (projectDir basename, refresh, show-hidden toggle)
                                    └─ FileTree (recursive)
```

이전 구조 (T-P3 / T-P4 이전) 의 "현재 폴더 표시" 와 search icon 은 ActivityBar 의 `explorer` / `search` 두 탭으로 흡수됨. 본 plan = `explorer` 분기.

## §2 표시 source

- **Root**: 현재 열린 `projectDir` (workspace 의 `cwd`). multi-root 미지원 (단일 root).
- **Scan strategy**: lazy. root 즉시 fetch, 하위 folder 는 expand 시 fetch. 1 회 fetch 후 in-memory cache (watch invalidate 시 갱신).
- **Default exclude** (hard-coded baseline, 추후 config 화 가능):
  - `.git/`
  - `node_modules/`
  - `.next/` `dist/` `dist-electron/` `build/` `out/` `.turbo/` `.cache/` (build artifact 류)
  - `.DS_Store`
- **`.gitignore` honor**: phase4 R5 = baseline exclude 만. `.gitignore` 파싱은 §9 open question (추후 ticket).
- **Hidden files** (`^\.`): default hide. Header 의 `show hidden` toggle 로 reveal. toggle state = workspace store ephemeral (persist 미정 — open question).

## §4 file 클릭 → openTab dispatcher

T-P4-046 dispatcher 호출 규약 (가정, 검증 §검증):

```ts
openTab(kind: 'markdown' | 'preview' | 'image' | 'binary',
        payload: { path: string; readonly?: boolean }): void
```

| extension | kind | payload extras |
|---|---|---|
| `.md`, `.mdx` | `markdown` | `{ path }` |
| `.html`, `.htm` | `preview` | `{ path }` (T-P4 mockup 처럼 iframe sandbox) |
| `.png` `.jpg` `.jpeg` `.gif` `.webp` `.svg` | `image` | `{ path }` |
| `.json` `.yml` `.yaml` `.txt` `.log` `.ts` `.tsx` `.js` `.css` | `markdown` | `{ path, readonly: true }` (read-only markdown viewer 로 텍스트 표시 — 별도 code viewer 미도입) |
| 그 외 (binary) | `binary` | `{ path }` (placeholder pane: "Binary file. Cannot preview.") |

매핑 table = `ExplorerPane` 내부 helper `resolveTabKind(path)`. 추후 확장 시 한 곳만 수정.

이미 열린 동일 path tab → dispatcher 가 focus reuse (T-P4-046 책임). Explorer 는 단순 호출만.

## §6 fs-watch + refresh

- `chokidar` 또는 electron main 의 `fs.watch` 기반 watcher 를 main process 에 둔다 (renderer 직접 watch 금지 — 권한/안정성).
- main → renderer IPC: `explorer:fs-changed` event with `{ type: 'add'|'change'|'unlink'|'addDir'|'unlinkDir', path }`.
- renderer = **debounce 500ms** 누적 → tree partial refresh:
  - `addDir` / `unlinkDir` → 부모 folder children 재fetch.
  - `add` / `unlink` → 부모 folder children 재fetch.
  - `change` → metadata 만 갱신 (tree 구조 영향 없음, badge/dirty mark 미도입 R5).
- **Exclude 패턴은 watcher level 에서도 적용** (node_modules 변경 무시 — perf 필수).
- manual refresh button (Header `↻`) → 전체 tree 무효화 + root 재fetch.

## §8 Acceptance criteria (ticket spec 후보)

1. ActivityBar 의 `Explorer` 탭이 active 일 때 LeftSidebar 에 `<ExplorerPane>` 가 렌더된다.
2. `projectDir` 가 설정된 상태에서 root 의 file/folder 가 tree 로 표시된다 (default exclude 적용).
3. folder row click 시 expand/collapse 가 토글되고 lazy fetch 로 children 이 로드된다.
4. file row click 시 §4 매핑 table 에 따라 `openTab(...)` 가 호출된다 (.md → markdown, .html → preview, image → image, binary → binary placeholder, 기타 텍스트 → markdown read-only).
5. 동일 file 재클릭 시 새 tab 이 추가되지 않고 기존 tab 이 focus 된다 (T-P4-046 위임).
6. fs 변경 (add/unlink/change of file or folder) 이 500ms 이내 debounce 후 tree 에 반영된다 — `node_modules` 변경은 무시된다.
7. show-hidden toggle 이 dotfile (`^\.`) 표시를 토글한다.
8. context menu (right-click) 4 항목 (Open / Reveal in OS / Copy Path / Copy Relative Path) 이 동작한다.
9. `projectDir` 미설정 상태에서 empty state 와 `Open Folder…` 버튼이 표시된다.
10. 모든 사용자 가시 문자열은 `workspace.explorer.*` 키로 i18n 처리되어 있다 (ko/en/ja 3 언어 모두 키 존재 — `check-locale-keys.js` 통과).

## §9 Open questions

1. **`.gitignore` honor** — R5 = baseline exclude 만. `.gitignore` 파싱 (ignore 패키지 등) 도입 시점 / 별도 ticket?
2. **show-hidden persist** — toggle 이 세션 ephemeral 인가, workspace settings 에 persist 인가?
3. **keyboard navigation** — R5 에 ↑/↓/←/→/Enter 포함? 아니면 R6 로 분리?
4. **context menu Reveal label** — platform 분기 vs 통일 문구?
5. **drag-drop / write 작업** (rename/delete/new) — 별도 phase 로 분리하는 것이 맞는가? (현재 §5 = read-only)
6. **대용량 directory** (10k+ files) — virtualize (react-window 등) 도입 임계? R5 = 미도입 가정.
7. **projectDir 변경 detection** — workspace store 의 `projectDir` 변경 시 ExplorerPane 가 자연스럽게 react 하는지 (zustand subscribe) — 구현 시 확인.
8. **active file highlight source** — TabBar 의 active tab path 와 동기화? (recommended yes — store 에서 derive)

## §10 Implementation notes (개발자 참고용, design 의견)

- ExplorerPane component 위치 후보: `packages/gui/src/components/explorer/ExplorerPane.tsx` + `FileTree.tsx` + `FileRow.tsx` + `FolderRow.tsx` 분리.
- main process IPC 채널: `explorer:listDir(path)` / `explorer:watch(path)` / `explorer:unwatch()` / `explorer:reveal(path)`.

- tree state 관리 = zustand 의 `explorerStore` (또는 workspaceStore 확장) — `tree: Map<path, NodeMeta>`, `expanded: Set<path>`, `showHidden: boolean`.
- a11y: `role="tree"` / `role="treeitem"` / `aria-expanded` / `aria-level` / `aria-selected`.
- perf: row virtualization 미도입 (R5). 1 folder 당 100~500 노드 가정.
