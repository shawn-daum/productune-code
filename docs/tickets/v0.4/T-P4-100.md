# T-P4-100: Workspace shell — Side section + PO Chat width drag-resize

> WorkspaceShell 의 좌측 Side section 과 우측 PO Chat 을 **마우스 드래그로 폭 조절 가능**하게 바꾼다. 가운데 main tab detail 영역은 남는 폭을 유연하게 가져가고, 사용자는 좌/우 2개 handle 로 자신에게 맞는 밀도로 작업한다.

---

## §1 Background

### 1.1 사용자 요청 verbatim (2026-05-12)

> "1. Side section,(tab detail, po chat) 이 두개의 width를 마우스 드래그로 조절할 수 있으면 좋겠어."

### 1.2 현재 상태

`packages/gui/src/views/WorkspaceShell.tsx` 는 현재 outer shell column 폭을 고정값으로 사용한다.

```ts
// current
gridTemplateColumns: chatPanelVisible
  ? '48px 240px 1fr 340px'
  : '48px 240px 1fr 0px'
```

즉:

- **LeftSidebar** = 240px 고정
- **MainPanel (tab detail)** = 남는 폭 전체
- **ChatPanel (PO Chat)** = 340px 고정

이 상태에서는:

1. Project / Team / Settings 쪽 row label 이 길 때도 좌측 폭을 늘릴 수 없음
2. PO Chat 을 넓혀 긴 답변을 읽거나, 반대로 좁혀 main tab detail 을 더 크게 볼 수 없음
3. MainPanel 내부 split-pane(T-P4-046) 는 drag-resize 가 되는데, **workspace 바깥 shell만 고정 폭**이라 interaction 일관성이 깨짐

### 1.3 목표

사용자 mental model 은 이미 IDE 류 제품과 동일하다:

- 좌측 sidebar ↔ center 사이 경계는 drag 가능
- center ↔ right chat 사이 경계도 drag 가능
- 사용자가 조절한 폭은 다음 진입 때도 유지

본 ticket 은 이 outer shell resize behavior 를 phase4 UI 원칙에 맞게 정의한다.

## §2 Scope

### Sub-area A — WorkspaceShell outer column width model

`WorkspaceShell.tsx` 의 고정 column 폭을 **user-adjustable pixel width** 로 전환한다.

#### 기본값

- LeftSidebar default = **240px**
- PO Chat default = **340px**
- ActivityBar = **48px 고정 유지**
- MainPanel = **remaining flexible width**

#### width ownership

폭 state 는 **WorkspaceShell local UI state** 로 둔다.

- 이유 1: 이 값은 pane tree/domain data 가 아니라 purely shell-layout concern
- 이유 2: 현재 이 값을 참조하는 surface 가 `WorkspaceShell` 뿐이라 zustand 전역화 이점이 작음
- 이유 3: chat minimize/restore 와 outer grid 계산이 모두 같은 컴포넌트 안에 있어 동기화가 단순함

#### column model

drag handle 2개가 추가되므로 개념적으로는 다음 6-column shell 이 된다.

| col | 의미 |
|---|---|
| 1 | ActivityBar (48px fixed) |
| 2 | LeftSidebar (resizable) |
| 3 | left resize handle (4px hit area) |
| 4 | MainPanel / tab detail (flex) |
| 5 | right resize handle (4px hit area; chat visible 때만) |
| 6 | ChatPanel (resizable; panelVisible=true 때만) |

> 핵심: **가운데 tab detail 폭은 직접 state 로 저장하지 않는다.** 좌/우 edge column 만 조절하고 center 는 남는 폭을 받는다.

### Sub-area B — LeftSidebar resize interaction

LeftSidebar 와 MainPanel 사이에 **vertical col-resize handle** 을 추가한다.

#### interaction

- mouse down on handle → drag 시작
- drag 중 `sidebarWidth` live update
- mouse up → drag 종료 + 최종값 persist
- drag 중:
  - `document.body.style.cursor = 'col-resize'`
  - `document.body.style.userSelect = 'none'`
- drag 종료 시 cursor / userSelect 원복

#### bounds

- sidebar min = **200px**
- sidebar max = **420px**
- center 보호폭(min guard) = **480px**

즉 실제 허용 폭은 다음 조건을 동시에 만족해야 한다.

- `200 <= sidebarWidth <= 420`
- `centerWidth >= 480`
- chat visible 시에는 `chatWidth` 도 그 순간 값 유지

사용자가 drag 로 center 를 사실상 0px 로 밀어버리는 상황은 허용하지 않는다. bound 에 닿으면 handle movement 가 멈춘 것처럼 느껴져야 한다.

### Sub-area C — PO Chat resize interaction

MainPanel 과 ChatPanel 사이에도 동일한 **vertical col-resize handle** 을 추가한다.

#### interaction

- mouse down on handle → drag 시작
- drag 중 `chatWidth` live update
- mouse up → drag 종료 + 최종값 persist
- handle visual / cursor 동작은 Left handle 과 동일

#### bounds

- chat min = **280px**
- chat max = **560px**
- center 보호폭(min guard) = **480px** 동일 적용

#### chat collapse 정합

- `panelVisible === false` 이면:
  - right handle 숨김
  - chat column = 0
- 사용자가 이전에 조절한 `chatWidth` 값은 **기억 유지**
- FAB / minimize 로 다시 열면 마지막 사용자 폭으로 복원
- **drag 로 min width 도달했다고 panel auto-close 되면 안 됨** — collapse/expand 는 기존 minimize/FAB action 만 담당

### Sub-area D — Width persistence

사용자 조절 폭은 `localStorage` 에 persist 한다.

#### key scope

- `workspace.shell.sidebarWidth`
- `workspace.shell.poChatWidth`

프로젝트별 key 분리는 하지 않는다.

- 이유: 이 값은 문서/프로젝트 데이터가 아니라 **user workspace preference** 에 가깝다.
- 다른 프로젝트로 이동해도 같은 화면 밀도를 기대하는 것이 더 자연스럽다.

#### persistence rules

- mount 시 localStorage read
- 숫자 파싱 실패 / NaN / 음수 / bounds 밖 값 → default fallback
- restore 시에도 **현재 viewport 기준으로 다시 clamp**
- write timing = **drag end(mouse up)** 기준 권장
  - mousemove 마다 localStorage write 는 불필요한 write spam 이라 지양

### Sub-area E — Handle affordance / visual behavior

handle 은 main pane split(T-P4-046) 와 같은 family 로 느껴져야 한다.

#### visual spec

- hit area = **4px**
- default = transparent
- hover = subtle visible feedback (`rgba(255,255,255,0.06)` 정도)
- active drag = 더 강한 feedback (`rgba(255,255,255,0.12)` 또는 accent line)
- cursor = `col-resize`

#### behavior spec

- drag 중 layout 가 live reflow 된다 (drop 후 한 번에 튀는 방식 X)
- LeftSidebar / MainPanel / ChatPanel 내부 scroll state 는 유지
- text selection, bubble highlight, accidental drag image 생성 없어야 함
- mouseup 이 component 바깥에서 일어나도 drag state 는 정상 종료되어야 함 (`window` listener 패턴)

> 구현 helper 는 신규 `ColumnResizeHandle` 로 분리해도 되고, `main/ResizeHandle.tsx` 의 drag pattern 을 재사용해도 된다. 단 **pane-tree ratio resize 와 outer shell pixel resize 는 서로 다른 책임** 이므로 store/path 모델까지 억지로 공유할 필요는 없다.

## §3 UX expectations

### 3.1 Familiar

사용자는 이미 T-P4-046 main split-pane 에서 drag-resize 경험을 갖고 있다. Outer shell 도 같은 affordance 를 가져야 “이 앱은 경계선은 끌어서 조절한다”는 규칙이 일관된다.

### 3.2 Few Things

새 기능이지만 새로운 button / menu / settings row 를 추가하지 않는다.

- sidebar-edge handle 1개
- chat-edge handle 1개

딱 2개의 invisible affordance 만 추가하고, 사용자가 필요할 때만 발견하면 된다.

### 3.3 Predictability

- 왼쪽 handle 은 sidebar 폭만 바꾼다
- 오른쪽 handle 은 chat 폭만 바꾼다
- center 는 언제나 남는 폭을 받는다
- chat minimize 는 폭 조절과 별개다

즉 하나의 gesture 가 하나의 결과만 만든다.

### 3.4 Feedback

drag 시작/진행/종료가 모두 눈에 보여야 한다.

- hover 시 handle 존재가 드러남
- drag 중 cursor 변화 + live width 변화
- bounds 도달 시 더 이상 밀리지 않아 즉시 피드백

### 3.5 Escape

사용자가 잘못 조절해도 치명적 상태가 되면 안 된다.

- min/max clamp
- center 보호폭
- chat reopen 시 default 아님, **마지막 정상 폭** 복원
- localStorage 값이 깨져도 default 로 안전 복귀

## §4 Acceptance

- [ ] **A1. default parity** — 첫 진입 시 LeftSidebar 240px, PO Chat 340px 로 시작한다. 기존 사용자 저장값이 없을 때 현재 UI 와 동일한 기본 밀도다.
- [ ] **A2. left drag** — LeftSidebar 와 MainPanel 사이 handle drag 로 sidebar 폭이 live 변경된다. mouseup 후에도 새 폭이 유지된다.
- [ ] **A3. right drag** — MainPanel 과 PO Chat 사이 handle drag 로 chat 폭이 live 변경된다. mouseup 후에도 새 폭이 유지된다.
- [ ] **A4. bounds** — sidebar 는 200~420px, chat 은 280~560px 범위에서만 움직인다. drag 로 center 영역이 480px 미만으로 무너지지 않는다.
- [ ] **A5. persistence** — 앱/프로젝트를 나갔다 다시 들어와도 마지막 sidebar/chat 폭이 복원된다. 저장값이 비정상일 때는 default 로 fallback 한다.
- [ ] **A6. chat collapse** — PO Chat minimize 시 right handle + chat column 이 함께 사라진다. 다시 열면 마지막 `chatWidth` 로 복원된다.
- [ ] **A7. no accidental side effects** — drag 중 text selection, bubble selection, tab drag, pane split drag 와 충돌하지 않는다.
- [ ] **A8. live content reflow** — drag 중 LeftSidebar row ellipsis, MainPanel tabs/content, ChatPanel bubble wrap 가 즉시 재배치된다. mouseup 뒤에 한 번에 점프하는 방식이 아니다.
- [ ] **A9. no new content changes** — LeftSidebar / ChatPanel 의 정보 구조나 copy 는 바꾸지 않는다. 본 ticket 은 width interaction 만 다룬다.

## §7 Risks

| risk | 설명 | guard |
|---|---|---|
| layout collapse | 저장된 폭 또는 과도한 drag 로 center 가 너무 작아질 수 있음 | center min guard 480px + restore 시 clamp |
| drag conflict | outer handle drag 와 MainPanel 내부 split/tab drag 가 겹칠 수 있음 | handle hit area 분리 + drag state 분리 + window mouseup cleanup |
| persistence corruption | localStorage 값이 문자열/NaN/과거 실험값일 수 있음 | parse 실패 시 default fallback |
| collapse gap | chat minimize 후 4px 빈 handle gap 이 남을 수 있음 | `panelVisible=false` 때 right handle column 도 0 처리 |
| visual discoverability | handle 이 너무 invisible 하면 사용자가 못 찾을 수 있음 | hover feedback 제공, cursor 즉시 변경 |

## §9 QA scenarios

1. **default load**  
   앱 진입 → sidebar 240 / chat 340 기본폭 확인

2. **left resize**  
   sidebar-right edge drag → Project/Team/Settings content 가 live reflow 되는지 확인 → mouseup 후 폭 유지

3. **right resize**  
   chat-left edge drag → bubble wrap / input row width 가 live reflow 되는지 확인 → mouseup 후 폭 유지

4. **chat collapse / restore**  
   chat minimize → right handle/gap 사라짐 확인 → FAB 또는 reopen → 마지막 chat 폭 복원 확인

5. **persistence**  
   임의 폭으로 조절 후 workspace 재진입 → 마지막 값 복원 확인

6. **guard rails**  
   handle 을 끝까지 밀기 → min/max 및 center 보호폭에서 멈추는지 확인

7. **regression**  
   MainPanel 내부 split-pane resize / tab drag / Chat send / LeftSidebar scroll 동작 회귀 없는지 확인
