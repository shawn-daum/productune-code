# T-P4-102 — v1 탭 = TicketDashboardView (ticket-review reuse, not kanban)

## §1 Background

### 1.1 발단 — 사용자 dogfood 피드백

v0.4 진행 중, 사용자가 사이드패널 현재 버전(v1) row를 클릭했을 때 열리는 탭이
"버전 히스토리 — v1" 헤더를 가진 kanban board임을 인식. 이는 두 가지 문제를 동시에 드러냄:

1. **탭 타입 mismatch** — 현재 버전 row가 `version-history` type으로 열리지만, 실제로 보여주는 내용은 ticket dashboard 패턴임.
2. **VersionHistoryView 내부 kanban 분기** — `if (isCurrentVersion)` 블록이 kanban board를 VersionHistoryView 안에 embed시키고 있어 view 책임이 불분명함.

### 1.2 T-P4-097 §2(a) 결정 오류 — 전제가 틀렸다

T-P4-097은 `ticket-review` 재사용(Option A1)을 다음 이유로 기각했다:

> "ticket-review = 단일 ticket detail viewer. 의미 mismatch." → ✘ 부적합

그러나 코드를 확인한 결과:

```ts
// packages/gui/src/components/workspace/main/panes/TicketReviewTab.tsx
export default function TicketReviewTab({ props: _props }: Props) {
  const poState = useWorkspace((s) => s.poState)
  return <TicketDashboardView poState={poState} />
}
```

`ticket-review` tab type의 실제 renderer = **`TicketDashboardView`** (전체 kanban board, 6 status column).
단일 ticket detail viewer가 아니다. 따라서 T-P4-097 §2(a)의 기각 사유 자체가 사실 오류.

### 1.3 올바른 결론

**Option A1 채택**: 현재 버전 row click → `ticket-review:{versionId}` tab open + `versionFilter` prop으로 해당 버전 티켓만 scope. 신규 TabType 추가 없음. 신규 component 없음. VersionHistoryView = 과거 버전 전용 linear card view로 단순화 (~300 line 감소).

### (b) TicketDashboardView — `versionFilter` prop 수용

`TicketDashboardView.tsx`에 `versionFilter?: string` prop 추가.
`TicketReviewTab.tsx`가 `tabProps.versionFilter`를 읽어 전달.

```ts
// TicketDashboardView.tsx — Props 변경
interface Props {
  poState: PoState | null
  versionFilter?: string    // 신규 — 설정 시 해당 version 티켓만 표시
}

// allTickets useMemo 수정 (~4 line)
const allTickets = useMemo(() => {
  const raw = collectAllTickets(poState, scannedTickets)
  if (!versionFilter) return raw                             // 기존 전체 board 경로 보존
  return raw.filter((t) => t.version === versionFilter)     // 버전 필터 적용
}, [poState, scannedTickets, versionFilter])
```

```ts
// TicketReviewTab.tsx — versionFilter 전달 (~2 line 추가)
export default function TicketReviewTab({ props: tabProps }: Props) {
  const poState = useWorkspace((s) => s.poState)
  const versionFilter = tabProps?.versionFilter as string | undefined
  return <TicketDashboardView poState={poState} versionFilter={versionFilter} />
}
```

**기존 tab 동작 보존 확인**:

| 진입처 | versionFilter | 동작 |
|---|---|---|
| `ticket-review:board` (activity bar / mount) | undefined | ALL tickets ✓ |
| `ticket-review:{ticketId}` (quick-open) | undefined | ALL tickets ✓ |
| `ticket-review:v1` (현재 버전 row — NEW) | `'v1'` | v1 tickets only ✓ |

**Tab id 충돌 없음**: `'board'` ≠ version regex(`^v\d+`), `'T-P4-xxx'` ≠ version regex. ✓

**defaultTitle 확인**: `ticket-review` case returns `props?.ticketId ?? 'Tickets'`. 신규 경로는 `openTab` 4번째 인자(`versionId`)를 명시 전달 → defaultTitle 폴백 미도달. tab strip 제목 = `v1`. ✓

## §3 Acceptance Criteria

1. **현재 버전 row click** → main pane에 `ticket-review:{versionId}` 탭 열림. 이미 열려 있으면 focus.
2. **탭 strip 제목** = versionId 문자열 그대로 (예: `v1`). "버전 히스토리" 문자 없음.
3. **탭 내부 헤더** = `t('workspace.tickets.title')` (예: "작업" / "Tickets"). `VersionHistoryView` header 없음.
4. **kanban board 내용** = 해당 version 티켓만 표시 (`versionFilter` 적용). 다른 버전 티켓은 나타나지 않음.
5. **기존 `ticket-review:board`** (activity bar icon) = ALL tickets 그대로. 동작 변화 없음.
6. **기존 `ticket-review:{ticketId}`** (quick-open) = versionFilter 없음. 기존 동작 유지.
7. **과거 버전 row click** = `version-history` type tab 열림. 기존 linear card view 그대로. kanban 없음.
8. **VersionHistoryView** = `if (isCurrentVersion)` 분기 없음. kanban 관련 component / style / type 코드 전부 삭제됨.
9. **version rename** (`v0.1` → `v1`) 발생 시 열린 `ticket-review:v0.1` tab이 `ticket-review:v1` (title: `v1`)로 in-place swap됨.
10. **신규 TabType 없음.** `workspace.ts` TabType union 변경 없음.
11. **신규 파일 없음.** 기존 5개 파일 변경만.

## §6 §1.5 Self-Check (Design System UX Principles)

| Sub-rule | 검증 | 결과 |
|---|---|---|
| **§1.5.1 Few Things** | v1 tab = `TicketDashboardView` 그대로. 신규 component 없음. 신규 tab type 없음. 사용자가 배울 새 패턴 없음. `versionFilter` prop으로 scope만 좁힘 — 같은 board 패턴. | ✓ pass |
| **§1.5.2 Familiar** | `ticket-review` tab type = 이미 activity bar `'tickets'` icon에서 열리는 것과 동일. "v1 클릭 → tickets board 열린다" = 직관적. "버전 히스토리 — v1" 낯선 label 제거 → 단순화. | ✓ pass |
| **§1.5.3 Predictability** | 현재 버전 row click → 항상 ticket dashboard (v1 filter). tab title = version id로 명확 구분. 과거 버전 row click → 기존 "버전 히스토리" tab (변경 없음). 동작 일관성 유지. | ✓ pass |
| **§1.5.4 Feedback** | row click → tab open (즉시 시각 변화). selected 표식 변경 (기존 메커니즘). `versionFilter`로 티켓 scope 좁혀지므로 "v1 티켓만 보이는" 상태 명확. | ✓ pass |
| **§1.5.5 Escape** | tab X 클릭 = 닫기 (기존). transient close 시 tab 자동 닫기 없음 — 사용자 명시 close 유지. row click = non-destructive. | ✓ pass |

**Anti-pattern 점검**:

- ~~"action with no visual feedback"~~ → row click 시 tab open 즉각 (기존 동작 그대로). ✓ 없음
- ~~"같은 tab type에 두 가지 다른 header 패턴"~~ → 제거됨. `ticket-review` = 항상 `TicketDashboardView` header. `version-history` = 항상 `VersionHistoryView` header. 명확 분리. ✓ 없음
- ~~"VersionHistoryView가 context에 따라 kanban / linear 두 가지 뷰 전환"~~ → 제거. VersionHistoryView = linear only. ✓ 없음
- ~~"탭 제목 '버전 히스토리'인데 내용은 kanban board" (title-content mismatch)~~ → 제거됨. v1 tab = `ticket-review` type + TicketDashboardView = 의미 일치. ✓ 없음

design-direction `§reduce-surface` 준수: 기존 type/component 재사용, 신규 surface 추가 없음. Tab type count: 변경 없음. VersionHistoryView에서 kanban 코드 ~300 line **순감소**. ✓

### §1 Background — 왜 mismatch 가 발생했나

#### 1.1 T-P4-097 §2(a) 에서 채택된 결정 (now wrong)

T-P4-097 은 "현재 버전 클릭 → 어떤 tab?" 을 결정할 때 옵션 A1 을 다음 이유로 기각했다:

그리고 **A3** (`version-history` tab + 2 tab id 분리, `version-current:{id}` + kanban 분기 유지) 을 채택했다.

#### (b) TicketDashboardView — versionFilter prop 수용 여부

**Decision**: `TicketDashboardView` 에 `versionFilter?: string` prop 추가. `TicketReviewTab` 이 `props.versionFilter` 를 읽어 전달.

**근거 — 코드 확인 결과**:

현재 `TicketDashboardView` props:
```ts
interface Props {
  poState: PoState | null
  // versionFilter 없음 — 전 버전 ALL 티켓 표시
}
```

현재 `collectAllTickets` 로직:
- `poState.current_task` → `version: poState?.current_version` 으로 자동 태깅
- `useTicketScan` 결과 → `ticket.version` 필드 기반 grouping 없음, ALL 표시

**변경 spec**:

```ts
// TicketDashboardView.tsx
interface Props {
  poState: PoState | null
  versionFilter?: string    // 신규 — 설정 시 해당 version 티켓만 표시
}

export default function TicketDashboardView({ poState, versionFilter }: Props) {
  // ...
  const allTickets = useMemo(() => {
    const raw = collectAllTickets(poState, scannedTickets)
    if (!versionFilter) return raw                                // 기존 전체 board path 보존
    return raw.filter((t) => t.version === versionFilter)        // 버전 필터 적용
  }, [poState, scannedTickets, versionFilter])
  // ...
}
```

```ts
// TicketReviewTab.tsx
export default function TicketReviewTab({ props: tabProps }: Props) {
  const poState = useWorkspace((s) => s.poState)
  const versionFilter = tabProps?.versionFilter as string | undefined
  return <TicketDashboardView poState={poState} versionFilter={versionFilter} />
}
```

**기존 tab 동작 보존 확인**:
- `ticket-review:board` (WorkspaceShell — activity bar) → `props` = undefined → `versionFilter` = undefined → ALL tickets. ✓
- `ticket-review:{ticketId}` (QuickOpen / VersionHistoryView kanban card click) → `props.ticketId` 있음, `props.versionFilter` = undefined → ALL tickets. ✓
- `ticket-review:v1` (NEW — current version) → `props.versionFilter = 'v1'` → v1 tickets only. ✓

**Tab id 충돌 검증**:
- `ticket-review:board` — `'board'` 는 T-P4-095 version regex (`^v\d+(\.\d+)?$`) 불통과 → 충돌 없음
- `ticket-review:T-P4-xxx` (ticket id) — `'T-'` prefix, version id 와 패턴 비분리 → 충돌 없음
- `ticket-review:v1` (version id) — `'v' + digits` 패턴, ticket id 와 충돌 없음 ✓

**`defaultTitle` 확인** (workspace.ts line 502):
```ts
case 'ticket-review': return (props?.ticketId as string) ?? 'Tickets'
```
`ticket-review:v1` 의 경우 `props.versionFilter = 'v1'`, `props.ticketId` = undefined → defaultTitle = `'Tickets'`. 그러나 `openTab` 4번째 인자 (`title`) = `versionId` = `'v1'` 이 **명시 전달**되므로 tab strip 제목 = `v1`. defaultTitle 폴백 경로 미도달. ✓

**header title 확인**: `TicketDashboardView` header = `t('workspace.tickets.title')` ("작업" / "Tickets"). "버전 히스토리" 문자 없음 ✓.

### §7 §1.5 self-check (design-system UX principles)

| Sub-rule | 검증 | 결과 |
|---|---|---|
| **§1.5.1 Few Things** | v1 tab = `TicketDashboardView` 그대로. 신규 component 없음. 신규 tab type 없음. 사용자가 배울 새 패턴 없음. versionFilter 로 scope 만 좁힘 — 같은 board 패턴. | ✓ pass |
| **§1.5.2 Familiar** | `ticket-review` tab type = 이미 activity bar `'tickets'` icon 에서 열리는 것과 동일. 사용자 입장에서 "v1 클릭 하면 tickets board 열린다" = 직관적. "버전 히스토리 — v1" 이라는 낯선 label 제거 → 단순화. | ✓ pass |
| **§1.5.3 Predictability** | 현재 버전 row click → 항상 ticket dashboard with v1 filter. tab title = version id 로 명확 구분. past version row click → 기존 "버전 히스토리" tab (변경 없음). 동작 일관성 유지. | ✓ pass |
| **§1.5.4 Feedback** | row click → tab open (즉시 시각 변화). selected 표식 변경 (기존 메커니즘). `versionFilter` 로 티켓 scope 좁혀지므로 "v1 티켓만 보이는" 상태 명확. | ✓ pass |
| **§1.5.5 Escape** | tab X 클릭 = 닫기 (기존). transient close 시 tab 자동 닫기 없음 — 사용자 명시 close 유지. row click 비-destructive. | ✓ pass |

**Anti-pattern 점검**:
- ❌ "action with no visual feedback" → row click 시 tab open 즉각 (기존 동작 그대로). ✓ 없음
- ❌ "같은 tab type 에 두 가지 다른 header 패턴" → 제거됨. `ticket-review` = 항상 `TicketDashboardView` header. `version-history` = 항상 `VersionHistoryView` header. 명확 분리. ✓ 없음
- ❌ "VersionHistoryView 가 context 에 따라 kanban / linear 두 가지 뷰 전환" → 제거. VersionHistoryView = linear only. ✓ 없음
- ❌ "버전 히스토리 탭 제목인데 내용은 kanban board" (title-content mismatch) → 제거됨. v1 tab = `ticket-review` type + TicketDashboardView = 의미 일치. ✓ 없음

**설계 원칙 위배 없음 확인**: design-direction §reduce-surface — 기존 type/component 재사용, 신규 surface 추가 없음. Tab type count: 변경 없음. Component count: VersionHistoryView 에서 kanban 코드 ~300 line **감소** (surface reduction, not addition). ✓
