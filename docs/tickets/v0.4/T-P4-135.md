## §2 Acceptance

### A1. Search executed across all 4 scope sources
Designer impl turn reads surviving mattpocock + phuryn skill dirs (post-archive), performs WebFetch search for external skill repos, and compiles findings per gap (G3 / G4 / G7).

### A2. Candidate table emitted in `docs/artifacts/v0.4/T-P4-135/plan.md`

Table schema per gap:

| Gap | Skill name | Source repo | Description summary | productune fit | Recommendation |
|:--|:--|:--|:--|:--|:--|
| G3 | `<name>` | `<repo>` | `<frontmatter desc>` | high/medium/low | adopt/skip |

- **productune fit** criteria:
  - `high` — directly applicable to productune GUI / CLI / docs context; minimal adaptation needed
  - `medium` — partially applicable; some productune-specific tuning needed
  - `low` — generic or off-domain; not worth installing
- **Recommendation** = designer's call; user overrides at decision gate.

At minimum one row per gap (even if recommendation = skip and no install). If no external candidate found for a gap → note `"no match found — candidate for author-self in Batch 3"`.

### A3. User decision recorded
After user reviews plan.md table, decisions (adopt / reject / partial) recorded in ticket `§Outcome` and T-P4-124 `§Pending follow-ups` updated.

### A4. Install executed (adopted candidates only)
For each adopted skill:
- Source available as directory: copy to `~/.claude/skills/<source>/<skill>/` (preserve source attribution in frontmatter `source_repo:` field if not present).
- Source available as remote repo only: note URL + `git clone` command in plan.md (designer cannot execute shell; emit script artifact or note for user).
- SkillMatrixTab auto-picks up new entries (no code change needed — `collectMdFiles` glob).

### A5. Doctrine reference updated (adopted candidates only)
For each adopted skill, add reference line to the relevant persona's `## Skills` section:
- G3 (a11y) → `pdt-qa.md` (both repo + home mirror)
- G4 (user docs) → PO or designer depending on skill's `personas[]` frontmatter
- G7 (i18n strategy) → `pdt-designer.md` or `pdt-developer.md` per frontmatter

### A6. i18n key stub added (adopted candidates only)
Each newly installed skill name → `locales/ko.json` + `locales/en.json` under `skills.descriptions.<skillName>` per T-P4-123 pattern. Empty string or placeholder acceptable; full translation deferred to i18n cleanup ticket.
