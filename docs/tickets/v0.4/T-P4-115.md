## §1 Background

### Dogfood trigger (paepyeong)

paepyeong 프로젝트에서 PRD·Design phase 작업이 완료된 뒤 **PhaseStrip가 Build를 표시하지 않는** 현상이 발견됐다.

원인 추적 결과 3-layer gap 확인:

| Layer | 파일 | 현 상태 |
|:--|:--|:--|
| **렌더 — props 미전달** | `MainPanel.tsx:19` | `<PhaseTransitionGate gate={gate} />` — `onApprove`/`onModify` 미전달. 버튼 클릭 → no-op |
| **IPC bridge 없음** | `electron/preload.ts` | `approvePhase()` 미노출 |
| **Main handler 없음** | `electron/main.ts` | `phase:approve` ipcMain.handle 미존재 → PoState 쓰기 경로 없음 |

이 세 gap이 겹쳐 **[승인 →] 클릭이 실제로 `po-state.json`을 변경하지 않는다.**

결과: paepyeong PoState `current_phase = undefined`, `phase_history = []` 상태 지속. PhaseStrip는 `getActivePhaseIndex` default 0(PRD) 표시. 임시로 productune monorepo 는 `jq` manual write로 `current_phase=3` 세팅해 우회 중.

### 부수 문제 — PhaseStrip safe fallback 미구현

`phase-mapping.ts:41`: `current_phase` 가 `undefined` 일 때 `phase_history` 를 전혀 참조하지 않고 index 0 반환. paepyeong처럼 `phase_history` 가 있어도 PRD 표시. 동일 fallback 패턴이 `workspace.ts:derivePhase` 에도 존재.

## §2 Scope

### A — `MainPanel.tsx`: `onApprove` / `onModify` 핸들러 wire

**현재 코드** (`packages/gui/src/components/workspace/main/MainPanel.tsx:19`):
```tsx
<PhaseTransitionGate gate={gate} />
```

**수정 방향**:
- `useWorkspace` 에서 `project` (projectDir 소스) 를 추가 select.
- `onApprove` 핸들러 구현: `window.api.approvePhase({ ... })` IPC 호출 → 성공 시 `readPoState` 재호출로 store 갱신.
- `onModify` 핸들러 구현: 기존 chat-emit 방식 유지 (문자열 "modify" 를 chat에 inject) — 별도 IPC 불필요.
- 두 핸들러를 `<PhaseTransitionGate gate={gate} onApprove={...} onModify={...} />` 로 전달.

### B — `electron/main.ts`: `phase:approve` IPC handler 신규

**채널명**: `phase:approve`

**args 타입**:
```ts
interface ApprovePhaseArgs {
  projectDir: string
  fromPhase: number        // gate.from_phase (1..5)
  toPhase: number          // gate.to_phase (2..5)
  summary?: string         // gate.summary
  userApprovedAt: string   // ISO timestamp (client-generated)
}
```

**동작**:
1. `po-state.json` 경로: `path.join(projectDir, '.productune', 'po-state.json')`
2. 파일 read → JSON parse.
3. `state.current_phase = toPhase`.
4. `state.phase_history` (배열 없으면 `[]` 초기화) 에 `PhaseTransition` entry append:
   ```json
   {
     "phase": toPhase,
     "started_at": "<userApprovedAt>",
     "summary": "<summary>",
     "user_approved_at": "<userApprovedAt>"
   }
   ```
5. `state.pending_gate = null` (gate 클리어).
6. JSON.stringify(state, null, 2) → `fs.writeFileSync` atomic-style (tmp → rename 또는 직접 write — 기존 `state:readPoState` 패턴 참고).
7. 반환: `{ ok: true }` / 실패 시 `{ ok: false, error: string }`.

**에러 처리**: parse 실패, write 실패 모두 `{ ok: false, error }` 반환. main에서 throw 하지 말 것 (renderer가 직접 에러 표시).

### C — `electron/preload.ts`: `approvePhase` bridge 노출

기존 IPC bridge 패턴 (`ipcRenderer.invoke`) 준수:

```ts
approvePhase: (args: {
  projectDir: string
  fromPhase: number
  toPhase: number
  summary?: string
  userApprovedAt: string
}): Promise<{ ok: boolean; error?: string }> =>
  ipcRenderer.invoke('phase:approve', args),
```

`contextBridge.exposeInMainWorld('api', { ... })` 블록 내 **Workspace state IPC** 섹션 아래 배치.

### D — doctrine 명시 업데이트 (`~/.productune/sections/lifecycle-mechanics.md` 또는 해당 섹션)

> **Note**: `~/.productune/sections/` glob 결과 없음 — 실제 경로가 다를 수 있음. 개발자는 phase transition doctrine 파일(lifecycle / stages / phase-gate 관련 .md)을 grep으로 찾아 아래 내용 추가.

추가할 내용 (한 문단, 관련 섹션 말미):

```markdown
### Phase transition mechanical write

GUI [승인 →] 클릭은 `phase:approve` IPC를 통해 직접 `po-state.json` 을
mechanical write한다 (`current_phase` ++ , `phase_history` append,
`pending_gate = null`). PO 스크립트가 직접 `jq` 로 write하는 경로도
동등하게 유효하며, 둘 중 하나만 실행되면 된다. 수동 `jq` 우회가
필요한 경우: `jq '.current_phase = <N> | .phase_history += [{"phase":<N>,"started_at":"<ISO>","user_approved_at":"<ISO>"}] | .pending_gate = null' .productune/po-state.json > /tmp/ps.json && mv /tmp/ps.json .productune/po-state.json`
```

### E — `phase-mapping.ts`: `getActivePhaseIndex` phase_history fallback

`current_phase` 가 range 밖(`undefined` / 0 / null) 일 때 `phase_history` 마지막 entry의 `phase` 값으로 fallback:

```ts
export function getActivePhaseIndex(poState: PoState | null): number {
  const phase = poState?.current_phase
  if (typeof phase === 'number' && phase >= 1 && phase <= 5) return phase - 1

  // Fallback: use latest phase_history entry when current_phase missing
  const history = poState?.phase_history
  if (Array.isArray(history) && history.length > 0) {
    const latest = history[history.length - 1].phase
    if (typeof latest === 'number' && latest >= 1 && latest <= 5) return latest - 1
  }
  return 0  // default PRD
}
```

`workspace.ts:derivePhase` 도 동일 fallback 로직 적용 (또는 내부적으로 `getActivePhaseIndex` 를 재사용하도록 리팩터).
