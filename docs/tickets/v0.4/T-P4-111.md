# T-P4-111: macOS File → Open Recent 메뉴 활성화

> macOS App menu bar 의 File → Open Recent 가 비어 있음.
> Electron `app.addRecentDocument` API 를 활용해 프로젝트 열기/생성 시 자동 등록하고,
> "Open Recent" submenu 에서 직접 진입 가능하도록 구현.

## §1 Background

**사용자 dogfood (2026-05-14)**:

> "macOS Status bar - file - recent가 비어있음 recent 기능 활성화 필요 (내가 최근에 오픈한 디렉토리 프로젝트도 포함)"

macOS native UX 표준에서 File → Open Recent 는 앱이 직전에 다룬 문서/프로젝트를 빠르게 재진입하는 핵심 메뉴. Electron 은 `app.addRecentDocument(path)` / `app.clearRecentDocuments()` 로 macOS 의 Recent Documents 시스템을 직접 연동할 수 있으며, `open-url` / `open-file` 이벤트와 조합하면 표준 동작을 그대로 제공할 수 있음.

현재 productune GUI 는 이 API 를 전혀 호출하지 않아 macOS 측 Recent Documents 목록이 빈 상태 → File → Open Recent 가 비어 보임.

## §2 Scope

### A. `app.addRecentDocument` 호출 — 프로젝트 진입 시 자동 등록

`openFolder` / `installAt` / 새 프로젝트 init 이 완료되어 `projectDir` 이 확정되는 시점마다 main process 에서 호출:

```ts
// packages/gui/electron/main.ts  (기존 openFolder 처리 분기 직후)
import { app } from 'electron'

app.addRecentDocument(projectDir)   // macOS 에 OS-level recent 등록
```

**등록 트리거 3곳**:

| 트리거 | 파일 / 위치 |
|:--|:--|
| 기존 프로젝트 열기 (`openFolder` IPC) | `main.ts` — openFolder handler 완료 후 |
| 새 프로젝트 init / installAt (`installAt` IPC) | `main.ts` — installAt handler 완료 후 |
| 드래그&드롭 or Finder에서 `open-file` 이벤트 | `main.ts` — `app.on('open-file', ...)` 핸들러 (신규 추가 또는 기존 확인) |

> `app.addRecentDocument` 는 macOS 전용 API — Windows/Linux 는 no-op 이므로 플랫폼 분기 필요 없음 (`process.platform === 'darwin'` guard 추가 권장).

### B. File 메뉴에 "Open Recent" submenu 추가

`main.ts` 의 Menu builder (또는 별도 `menu.ts`) 에서 File 메뉴 항목에 Electron native role 을 사용:

```ts
{
  label: 'File',
  submenu: [
    // ... 기존 항목 ...
    { type: 'separator' },
    {
      label: 'Open Recent',
      role: 'recentDocuments',          // ← macOS native: OS가 자동으로 최근 항목 populate
      submenu: [
        {
          label: 'Clear Menu',
          role: 'clearRecentDocuments', // ← macOS native: app.clearRecentDocuments() 트리거
        },
      ],
    },
  ],
}
```

`role: 'recentDocuments'` 는 Electron 이 macOS 의 Recent Documents NSMenu 를 자동으로 채워주는 native 통합 — 별도 동적 생성 불필요.

### C. Recent item click → `openFolder` IPC 트리거

macOS 가 Recent Documents 항목을 클릭하면 `app.on('open-file', (event, path) => {...})` 이벤트 발생. main process 에서 이를 수신해 해당 `path` 로 `openFolder` 로직을 호출:

```ts
app.on('open-file', (event, filePath) => {
  event.preventDefault()
  // 이미 window 가 열려 있으면 IPC로 전달, 없으면 window 생성 후 전달
  mainWindow?.webContents.send('open-recent-project', filePath)
  app.addRecentDocument(filePath)  // 재진입 시에도 갱신
})
```

renderer 에서 `open-recent-project` IPC 수신 → 기존 `openFolder` 플로우 호출.

> `open-file` 는 앱 시작 전에도 발생 가능 — `app.whenReady()` 이전 이벤트를 queue 했다가 ready 후 처리하는 패턴 적용 (Electron 공식 권장).

### D. Clear Menu 동작

B 에서 `role: 'clearRecentDocuments'` submenu item 을 넣으면 macOS 가 직접 `app.clearRecentDocuments()` 를 호출 → Recent 목록 초기화. 별도 IPC 불필요.

### E. `open-file` 이벤트 — app 시작 전 처리 (queue 패턴)

```ts
// main.ts 상단 (app.whenReady 바깥)
let deferredOpenPath: string | null = null

app.on('open-file', (event, filePath) => {
  event.preventDefault()
  if (mainWindow) {
    mainWindow.webContents.send('open-recent-project', filePath)
  } else {
    deferredOpenPath = filePath
  }
  app.addRecentDocument(filePath)
})

// app.whenReady / window 생성 완료 직후:
if (deferredOpenPath) {
  mainWindow.webContents.send('open-recent-project', deferredOpenPath)
  deferredOpenPath = null
}
```

- **최근 파일 개수 제한 설정 UI** — macOS 가 OS-level 로 관리, 별도 설정 불필요

## §8 Open questions

1. **preload contextBridge** — `open-recent-project` IPC 를 renderer 가 수신하려면 contextBridge 에 `onOpenRecentProject(cb)` 류 helper 노출 필요. 기존 패턴 (`onOpenFolder` 등) 존재 시 그대로 따름; 없으면 신규 추가 (L1 추가 분량).
2. **app 시작 전 cold-open** — Finder/Dock 에서 Recent Documents 를 클릭해 앱을 최초 실행하는 경우, window 생성 타이밍과 `open-file` 이벤트 경쟁 조건 — E 의 defer 패턴으로 커버되나 구현자 검증 필요.
