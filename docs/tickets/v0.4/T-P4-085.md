# T-P4-085 — User-facing 어휘 mode-aware full audit

## §1 Background

T-P4-084 (User mode developer / planner tone 분기) 는 핵심 surface area 11 keys
(§7.1 모달 5 + §7.2 Settings 섹션 제목 6) 에만 `.dev` / `.planner` suffix 를 적용하고,
full audit 은 OQ-5 로 후속 분리했다:

> "전체 어휘 매핑 표 정밀 audit (T-P4-085 후속 ticket 권장 — §7 의 1차 표 외
> 모든 user-facing 문구)" — T-P4-084 §11 Out of scope

**drift risk**: T-P4-084 land 이후 신규 i18n key 추가 시 `.dev` / `.planner` suffix
누락이 자동 감지되지 않는다. T-P4-057 linter 는 보호어 보존만 검사하고 mode-aware
suffix coverage 는 검사하지 않는다. 이 gap 이 누적될수록 mode 분기 효과가 부분적으로만
적용되는 **silent drift** 로 이어진다.

본 ticket 목표:
- GUI 전체 user-facing 문구를 대상으로 `(file × mode × suffix 필요 여부)` audit
  matrix 완성
- critical 미적용 항목에 대한 follow-up ticket 트리거
- T-P4-057 linter 의 mode-aware 확장 spec 산출

## §2 Scope

### A. 전체 user-facing i18n key audit matrix

`packages/gui/src/locales/en.json` + `ko.json` 의 **모든 key** 를 스캔하여 아래
형식의 matrix 로 분류한다:

```
| key_group | file | component_context | mode_sensitivity | suffix_status | severity | action |
```

#### 컬럼 정의

| 컬럼 | 값 |
|---|---|
| `mode_sensitivity` | `sensitive` / `invariant` / `review` |
| `suffix_status` | `covered` (`.dev` or `.planner` 이미 존재) / `missing` (sensitive 인데 없음) / `n/a` (invariant) |
| `severity` | `critical` / `medium` / `low` / `n/a` |
| `action` | `emit-follow-up` / `spec-extend` / `none` |

#### 분류 기준 (T-P4-084 §2 / §3 doctrine)

| key prefix 패턴 | 권장 sensitivity | 근거 |
|---|---|---|
| `modal.*` | sensitive | 사용자 직접 읽고 판단 — dev 어휘 수위 차이 명확 |
| `error.*`, `toast.error.*` | sensitive | stack/code 노출 수위가 mode 별로 다름 |
| `tooltip.*`, `hint.*` | sensitive | dev 어휘 inline 보조 여부 |
| `settings.section.*` | sensitive | T-P4-084 §7.2 기준점 |
| `artifact.*`, `log.*` | sensitive (review) | 산출물 label — dev 어휘 포함 가능성 |
| `statusBar.*`, `banner.*` | sensitive (review) | 간접 노출 |
| `onboarding.step0_5.*` | invariant | mode 선택 화면 자체 — 단일 key 설계 |
| `persona.*` | invariant | T-P4-057 보호어 (PO/Designer/Dev/QA) |
| `phase.*`, `status.*`, `stage.*` | invariant | T-P4-057 보호어 (doctrine enum) |
| `nav.*`, `tab.*`, `cta.*`, `button.*` | review | 판단 필요 |
| `placeholder.*`, `aria.*` | review | 판단 필요 |

산출물: **`docs/qa/i18n-audit-T-P4-085.md`** — 위 분류 전체 key list 포함.

### B. Critical violation list

A 매트릭스에서 `severity=critical AND suffix_status=missing` 항목을 추출하여
별도 섹션으로 정리한다:

```
| # | key | planner_text (base) | dev_text (proposed .dev) | area_tag | follow_up_trigger |
```

**Critical 판정 기준**:
- 모달 confirm / warn / error body — 사용자가 직접 읽고 의사결정하는 텍스트
- 에러 메시지 (Bash / network / Vercel API 실패) — stack / error code 노출 수위
- Settings 섹션 제목 (T-P4-084 §7.2 범위 외 추가 발견분)
- Tooltip (영문 dev 어휘 포함 hint)

area_tag 예시: `modal/autosave`, `error/network`, `tooltip/deploy`,
`settings/advanced`, `artifact/log`, `statusbar/reminder`.

### C. T-P4-057 linter mode-aware 확장 spec

`packages/gui/scripts/check-locale-protected.sh` 에 **mode-coverage check** 추가
설계 spec:

- `sensitive` 분류 key 가 base 만 있고 `.dev` suffix 가 하나도 없으면 **warn** 출력
  (not fail — 신규 key 가 항상 mode-sensitive 는 아님).
- warn 목록을 stdout 으로 출력 → PR reviewer 가 mode-coverage 결정.
- 기존 보호어 fail 로직은 그대로 유지.
- covered rate (`mode-sensitive key 중 .dev suffix 존재 비율`) 을 summary 로 출력.

본 ticket 산출물은 **spec 문서** — 실제 linter 코드 수정은 §2-D 트리거 시 follow-up
impl ticket 이 커버.

### D. Follow-up ticket trigger 기준

아래 조건 충족 시 해당 area_tag 별 follow-up ticket 1개 트리거:

| # | 조건 | 판단 주체 |
|---|---|---|
| D-1 | Critical violation ≥ 1 개 / area_tag | 자동 트리거 (audit 결과 확인 즉시) |
| D-2 | Medium violation ≥ 3 개 / area_tag | PO 판단 후 트리거 |
| D-3 | linter warn 항목 ≥ 5 개 (전체) | linter 확장 impl ticket 트리거 |
