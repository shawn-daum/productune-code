# T-P4-146 — MCP 서버 추가 + name rename 활성화

## Request

Phase 5 deferral에서 v0.4로 앞당긴 항목 1/3.  
`McpServersTab`의 `[+ 서버 추가]` 버튼 활성화 + `McpServerModal` name 필드 editable 전환.  
신규 `mcp:add` / `mcp:delete` IPC 추가, i18n 정리 포함.

## Design doc

`docs/artifacts/v0.4/T-P4-146/plan.md` — 전체 spec (IPC 명세, 컴포넌트 spec, 유효성 규칙, i18n key, 스타일).

## §Scope

**In scope**

1. `McpServersTab` — `[+ 서버 추가]` 버튼 활성화, `phaseLockLabel` 제거, "new" 모드로 modal 열기.
2. `McpServerModal` — `mode: 'new' | 'edit'` prop 추가, name 필드 editable, 유효성 검증 (빈 이름 / 중복 / 특수문자 / max 64자), rename 시 delete+add flow.
3. `main.ts` — `mcp:add` IPC (중복 가드), `mcp:delete` IPC (idempotent) 추가.
4. `preload.ts` — `mcpAdd`, `mcpDelete` 노출.
5. `ko.json` / `en.json` — `addBtnTooltip` 제거, `emptyDesc` 변경, 신규 key (`modal.newTitle`, `modal.namePlaceholder`, `modal.nameError.*`) 추가.

**Out of scope**

- Source tier 선택 UI (local 고정 hidden).
- Connection test 실제 구현 (기존 stub 유지).
- `productune` tier 서버 GUI 편집.
- 서버 삭제 버튼 (rename-only 삭제 경로 제외).
- a11y / aria-label 개선.

## T-P4-146 — MCP 서버 추가 + Name Rename 활성화

**Status**: Design ready  
**Version**: v0.4  
**Date**: 2026-05-20  
**Companion ticket**: T-P4-146  
**Phase 5 deferral unlock**: 1/3 (MCP add + rename)

---

### 1. Context

`McpServersTab`의 `[+ 서버 추가]` 버튼이 Phase 5 lock으로 `disabled` 처리되어 있다.  
`McpServerModal`의 이름 필드도 `readOnly`. 두 항목 모두 v0.4에서 활성화.

T-P4-140에서 `mcp:save`가 local tier(`~/.claude.json`)를 기본으로 통일 완료. 이 티켓의 add/rename도 local tier 사용.

---

### 2. Goals

1. `[+ 서버 추가]` 버튼 활성화 — "new" 모드로 `McpServerModal` 열기.
2. `McpServerModal` 이름 필드 editable — 신규 서버 생성 + 기존 서버 rename 모두 지원.
3. i18n 정리 — "Phase 5 에서 지원 예정" 문구 제거, 신규 copy 한·영 parity.
4. 입력 유효성 검증 — 빈 이름 / 중복 / 특수문자 차단.
5. IPC 확장 — `mcp:add` (중복 가드 포함) + `mcp:delete` (rename 원자성) 추가.

### 2.1 Non-goals

- Source tier 선택 UI — local tier 고정 (hidden). `mcp:save` 동작과 동일.
- Connection test 구현 — 기존 stub 유지 (별도 Phase 5 항목).
- 서버 목록 정렬 / 드래그 리오더.
- productune tier (`~/.claude/settings.json`) 서버 수동 편집.
- 일괄 삭제.

### 3. UX Flow

#### 3.1 서버 추가 (새 서버)

```
McpServersTab
  └─ [+ 서버 추가] 클릭
        └─ McpServerModal (mode="new")
              ├─ Name 필드: empty, editable, placeholder "my-server"
              ├─ Transport: stdio (default)
              ├─ Command / URL: empty
              ├─ Env rows: 없음
              └─ [저장]
                    ├─ 유효성 검사 통과 → api.mcpAdd(name, config, projectDir)
                    │     ├─ ok → toast "저장됐어요" + onSaved() 콜백 → 목록 reload
                    │     └─ error:"duplicate" → inline error "이미 사용 중인 이름이에요"
                    └─ 유효성 실패 → inline error (저장 호출 없음)
```

#### 3.2 서버 수정 / rename (기존 서버)

```
McpServersTab
  └─ 서버 행 클릭
        └─ McpServerModal (mode="edit", server=<entry>)
              ├─ Name 필드: 기존 이름, editable
              ├─ [저장]
                    ├─ name 변경 없음 → api.mcpSave(name, config, projectDir)  (기존 flow)
                    └─ name 변경
                          ├─ 유효성 검사 (중복·형식)
                          ├─ api.mcpDelete(originalName, projectDir)
                          └─ api.mcpAdd(newName, config, projectDir)
```

#### 3.3 Empty state CTA 변경

현재 `emptyDesc`: "install.sh 로 서버를 추가할 수 있어요."  
→ "install.sh 또는 [+ 서버 추가] 버튼으로 추가할 수 있어요." (ko)  
→ "Add via install.sh or the [+ Add server] button." (en)

### 4. Component Spec

#### 4.1 McpServersTab 변경

| 항목 | Before | After |
|:--|:--|:--|
| 버튼 `disabled` | `true` | `false` |
| 버튼 스타일 | `addBtnDisabled` (grey, cursor:not-allowed) | `addBtn` (active, cursor:pointer) |
| `phaseLockLabel` span | 존재 | 제거 |
| `title` attribute | `t('settings.mcp.addBtnTooltip')` | 없음 (또는 "새 MCP 서버 추가") |
| onClick | noop | `() => setSelectedServer(NEW_SERVER_SENTINEL)` |
| modal open condition | `selectedServer !== null` | `selectedServer !== null` (동일, sentinel 활용) |

**Sentinel pattern**: `NEW_SERVER_SENTINEL = Symbol('new')` 또는 `selectedServer = 'new'` (string literal).  
McpServerModal이 `server | null`을 prop으로 받을 경우 `null`을 "new 모드"로 사용하는 것도 가능.

→ **권장**: `McpServerModal`에 `mode: 'new' | 'edit'` + optional `server` prop 분리.


#### 4.5 Validation 함수

```ts
const NAME_RE = /^[a-zA-Z0-9_-]+$/

function validateName(
  value: string,
  mode: 'new' | 'edit',
  originalName: string | undefined,
  existingNames: string[],
): string | null {
  if (!value.trim()) return t('settings.mcp.modal.nameError.required')
  if (value.length > 64) return t('settings.mcp.modal.nameError.tooLong')
  if (!NAME_RE.test(value)) return t('settings.mcp.modal.nameError.invalid')
  const isDuplicate =
    mode === 'new'
      ? existingNames.includes(value)
      : existingNames.includes(value) && value !== originalName
  if (isDuplicate) return t('settings.mcp.modal.nameError.duplicate')
  return null
}
```

#### 4.6 Save 로직 변경

```ts
const handleSave = async () => {
  // 1) 이름 유효성
  const nameErr = validateName(name, mode, server?.name, existingNames)
  if (nameErr) { setNameError(nameErr); return }

  if (saving) return
  setSaving(true)
  try {
    const api = (window as any).api
    let result: { ok: boolean; error?: string }

    const isRename = mode === 'edit' && name !== server!.name

    if (mode === 'new' || isRename) {
      if (isRename) {
        // 1) 기존 이름 삭제
        await api.mcpDelete?.(server!.name, projectDir)
      }
      // 2) 새 이름으로 추가
      result = await api.mcpAdd?.(name, buildConfig(), projectDir)
    } else {
      // edit, no rename
      result = await api.mcpSave?.(name, buildConfig(), projectDir)
    }

    if (result?.ok) {
      showToast(t('settings.mcp.toastSaved'), 'success')
      setTimeout(() => showToast(t('settings.mcp.toastRestartNeeded'), 'info'), 600)
      dirtyRef.current = false
      onSaved()
    } else {
      if (result?.error === 'duplicate') {
        setNameError(t('settings.mcp.modal.nameError.duplicate'))
      } else {
        showToast(result?.error ?? '저장 실패', 'error')
      }
    }
  } catch (e: any) {
    showToast(e?.message ?? '저장 실패', 'error')
  } finally {
    setSaving(false)
  }
}
```

### 5. IPC 변경 명세

#### 5.1 새 IPC: `mcp:add`

**main.ts 추가**

```ts
ipcMain.handle(
  'mcp:add',
  (
    _event,
    serverName: string,
    config: McpServerConfig,
    projectDir?: string,
  ): { ok: boolean; error?: string } => {
    try {
      // 중복 확인
      const existing = getExistingServerNames(projectDir)
      if (existing.has(serverName)) {
        return { ok: false, error: 'duplicate' }
      }
      // local tier에 추가 (projectDir 있으면 ~/.claude.json, 없으면 settings.json)
      if (projectDir) {
        const claudeJson = readClaudeJson()
        if (!claudeJson.projects) claudeJson.projects = {}
        if (!claudeJson.projects[projectDir]) claudeJson.projects[projectDir] = {}
        if (!claudeJson.projects[projectDir].mcpServers)
          claudeJson.projects[projectDir].mcpServers = {}
        claudeJson.projects[projectDir].mcpServers[serverName] = config
        writeClaudeJson(claudeJson)
      } else {
        const settings = readClaudeSettings()
        if (!settings.mcpServers) settings.mcpServers = {}
        settings.mcpServers[serverName] = config
        writeClaudeSettings(settings)
      }
      return { ok: true }
    } catch (e: any) {
      return { ok: false, error: e?.message ?? 'unknown error' }
    }
  },
)
```

`getExistingServerNames(projectDir)`: `mcp:getServers` 로직의 일부를 추출하거나, `mcp:add` 내부에서 두 tier를 merge해 set 반환.

#### 5.2 새 IPC: `mcp:delete`

**main.ts 추가**

```ts
ipcMain.handle(
  'mcp:delete',
  (
    _event,
    serverName: string,
    projectDir?: string,
  ): { ok: boolean; error?: string } => {
    try {
      let deleted = false
      // local tier 우선
      if (projectDir) {
        const claudeJson = readClaudeJson()
        if (claudeJson.projects?.[projectDir]?.mcpServers?.[serverName] !== undefined) {
          delete claudeJson.projects[projectDir].mcpServers[serverName]
          writeClaudeJson(claudeJson)
          deleted = true
        }
      }
      // productune tier fallback
      if (!deleted) {
        const settings = readClaudeSettings()
        if (settings.mcpServers?.[serverName] !== undefined) {
          delete settings.mcpServers[serverName]
          writeClaudeSettings(settings)
          deleted = true
        }
      }
      return { ok: true }  // not-found도 ok — idempotent
    } catch (e: any) {
      return { ok: false, error: e?.message ?? 'unknown error' }
    }
  },
)
```

### 8. §1.5 Design Principles Check

| Principle | Status | Note |
|:--|:--|:--|
| Few Things | ✓ | 기존 modal UI 그대로, name 필드만 editable 전환 |
| Familiar | ✓ | 같은 modal 패턴, 같은 버튼 배치 |
| Predictability | ✓ | 유효성 에러는 inline (toast 아님), 저장 결과는 toast |
| Feedback | ✓ | 저장 성공 toast + restart 안내 유지, validation → inline error |
| Escape | ✓ | Esc + dirty guard 기존 동작 유지. name 변경도 `dirtyRef` 트리거 |

**Anti-pattern 없음**: 저장 action에 항상 feedback (ok → toast, error → toast 또는 inline). 유효성 에러는 toast가 아닌 inline으로 §Feedback 만족.

### 9. Alternatives Considered

| Option | Rejected Reason |
|:--|:--|
| `mcp:rename` 단일 IPC | delete + add 두 step 이면 각각 rollback 처리가 필요. 분리가 더 단순. |
| `existingNames` prop 대신 IPC에서 중복 체크만 | 클라이언트 즉시 피드백 위해 prop도 필요. 양쪽 검증. |
| name field read-only 유지, 별도 "rename" 버튼 추가 | 불필요한 UX 분리. 편집 modal에서 name도 editable이 자연스럽다. |

### Implementation Notes (dev용)

1. **`mcp:add`의 `getExistingServerNames`**: `mcp:getServers` 에서 already computed merged map 있음. helper 함수로 추출하거나 `mcp:add` 내부에서 직접 read-merge 처리.
2. **Rename 원자성**: `mcp:delete` + `mcp:add`는 two-phase. 중간 실패 시 frontend에서 toast error. 스펙상 OK (단일 사용자 앱, 동시 write 없음).
3. **`autoFocus` on new modal name field**: Electron Chromium context에서 `autoFocus` prop 작동 확인 필요. `useRef` + `useEffect` fallback 고려.
4. **ko.json / en.json `addBtnTooltip` key 제거**: 버튼에 tooltip이 없어지는 것. 접근성 관점에서 aria-label 검토 가능 (scope: 별도 a11y 티켓).
