# T-P4-110: Close detection 정밀화 — `outcome?.observed_result` 기준으로 교정

> `isVersionClosed` / `isCurrentVersionClosed` 의 `!!outcome` 판단을 `!!outcome?.observed_result` 로 교정.
> Planning 시점 미리 작성된 outcome object (north_star / input_metrics / validation_method) 는 closed trigger 가 아님 — 실제 측정값 `observed_result` 가 set 됐을 때만 close.

## §1 Background

**사용자 dogfood (2026-05-14)**:

> productune GUI 가 v0.4 를 "close" 로 표시 (sidebar 지난 버전). 실제: ended_at=null, outcome.observed_result=null, ticket 다수 진행 중, PHASE GATE 가 "Build → Close 승인 대기" — 즉 v0.4 는 ongoing.

**v0.4 entry 상태 요약**:

| 필드 | 값 |
|:--|:--|
| `ended_at` | `null` |
| `outcome.observed_result` | `null` |
| `outcome.north_star` | 채워짐 (planning 시점 작성) |
| `outcome.input_metrics` | 채워짐 (planning 시점 작성) |
| `outcome.validation_method` | 채워짐 (planning 시점 작성) |
| ticket 진행 상황 | 다수 진행 중 |
| PHASE GATE | Build → Close 승인 대기 (ongoing) |

**Root cause — T-P4-097 plan §2(d) / 구현 코드**:

T-P4-097 구현(`SidePanelCurrentVersion.tsx` L31, `SidePanelPastVersions.tsx` L30)의 close 판단 조건:

```ts
// 현재 (버그)
return !!ver.outcome || !!ver.ended_at
```

`outcome` object 는 PRD Planning 시점에 `north_star` / `input_metrics` / `validation_method` 를 미리 채워두는 schema — Phase 2+ 진입 시점부터 non-null 이 됨. `!!outcome` truthy 평가 → version 이 ongoing 이어도 closed 분류.

**사용자 directive**: "최신 버젼에 old data 끼워맞추는 방식" = 현재 schema 가 SoT. old data 에도 본 logic 으로 평가. schema 구조 자체는 변경하지 않음.

## §2 Scope

### A. Close detection condition 정밀화

| | Old | New |
|:--|:--|:--|
| 조건 | `!!ver.outcome \|\| !!ver.ended_at` | `!!ver.outcome?.observed_result \|\| !!ver.ended_at` |
| 의미 | outcome object 존재 = closed | 실제 측정값 set = closed |

**적용 지점 2곳** (둘 다 동일 one-liner 교체):

```ts
// A-1. SidePanelCurrentVersion.tsx — isCurrentVersionClosed (L31)
// A-2. SidePanelPastVersions.tsx    — isVersionClosed (L30)
```

교체 후:

```ts
// A-1
return !!ver.outcome?.observed_result || !!ver.ended_at

// A-2
return !!ver.outcome?.observed_result || !!ver.ended_at
```

`observed_result` 는 `string | null | undefined` 예상 — `!!` 로 falsy(null/undefined/"") 모두 cover. 타입이 정확히 맞지 않을 경우 `!= null` 로도 가능하나 `!!` 로 충분.

### B. SidePanelCurrentVersion.tsx — `isCurrentVersionClosed` 함수 docstring 갱신

주석 L7-8 에 "current version has outcome|ended_at set → transient-close" 라고 되어 있어 buggy wording. 갱신:

```ts
// Before (L7-8):
//   2. current version has outcome|ended_at set → transient-close fallback

// After:
//   2. current version has outcome.observed_result|ended_at set → transient-close fallback
//      (planning-time outcome object with north_star/input_metrics is NOT a close trigger)
```

### C. SidePanelPastVersions.tsx — `isVersionClosed` 함수 docstring 갱신

```ts
// Before (L28): Returns true when a version is considered closed.
// After (L28):
/** Returns true when a version is considered closed.
 *  Close = ended_at set OR outcome.observed_result set (measured result populated).
 *  Planning-time outcome object (north_star / input_metrics / validation_method) is NOT a close trigger.
 */
```

### D. VersionRow.tsx — `isClosed` prop 영향 없음

`VersionRow` 는 `isClosed: boolean` prop 을 그대로 표시만 함. `isVersionClosed()` 계산 결과를 SidePanelPastVersions 가 pass-through → A 수정으로 자동 연쇄 수정. VersionRow 자체 코드 변경 없음.

### E. T-P4-097 plan.md §2(d) wording 갱신

`docs/artifacts/v0.4/T-P4-097/plan.md` §2(d) (또는 §5 Module Map `isVersionClosed` helper 항목):

```md
// Before:
isVersionClosed(version) — `!!version.outcome || !!version.ended_at`. 작은 helper...

// After:
isVersionClosed(version) — `!!version.outcome?.observed_result || !!version.ended_at`.
close = ended_at set 또는 observed_result 실측값 set.
planning-time outcome object(north_star/input_metrics/validation_method)는 trigger X.
```

> **Note**: plan.md 가 존재하지 않거나 경로가 다를 경우 skip (wording 정보는 본 ticket §1 에 기록됨).
