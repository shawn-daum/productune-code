# T-P4-080: PresenceBar chip hover popup + 위치 + dev derive 미작동 fix

## Background

사용자 dogfood (2026-05-11) — T-P4-076/077/078/079 land 후 manual 검증 중 3건 발견:

1. **PresenceBar chip click → popup open** 동작이 click 으로만 trigger (T-P4-068 §E spec). 사용자 의도 = **hover trigger**.
2. **chip 호버 popup 위치** = 현재 StatusBar segment 기준 위로 펼침 패턴을 그대로 차용 → chip click 으로 열 때 popup 이 chat 영역 하단에 떠서 어색. 사용자 의도 = **chip 바로 아래** (PresenceBar 아래쪽으로 펼침).
3. **PresenceBar dev dot working 미작동** — designer × 2 + dev × 1 dispatch 시 BackgroundTaskPopup 의 row 에는 dev task 가 표시되지만 (예: "Developer selectors") PersonaPresenceBar 의 dev chip 만 회색 idle. T-P4-076 derive 의 dev case 또는 T-P4-077 normalize 매핑 mismatch 의심.

### B) chip hover popup 위치 — chip 아래로 펼침

- [ ] `packages/gui/src/components/workspace/BackgroundTaskSegment.tsx` 의 `BackgroundTaskPopup` 의 positioning 분기 추가:
  - **anchor source 분기**: segment hover (기존) vs chip hover (신규)
  - segment hover anchor → 현재 패턴 유지 (StatusBar segment 우측 정렬, 위로 펼침)
  - chip hover anchor → **chip 바로 아래** 정렬 (chip getBoundingClientRect 기준 bottom + 4px gap, left 정렬, **아래로 펼침**)
  - max-h / max-w / surface tokens / Esc + 외부 click / dismiss 정책 등 다른 부분은 정합 유지
- [ ] 구현 path:
  - `useBackgroundTasks` store 에 `popupAnchor: { type: 'segment' | 'chip', rect: DOMRect | null }` 추가
  - segment hover 시 `setPopupAnchor({ type: 'segment', rect: segmentRef.current.getBoundingClientRect() })`
  - chip hover 시 `setPopupAnchor({ type: 'chip', rect: chipRef.current.getBoundingClientRect() })`
  - `BackgroundTaskPopup` 의 positioning 계산이 anchor.type 분기 따라 위/아래 결정
- [ ] 회귀: persona filter 가 set 된 popup 도 chip 위치 anchor 사용 (사용자 의도 정합)
