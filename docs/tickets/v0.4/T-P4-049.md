# T-P4-049: Persona presence bar — Right Panel PO Chat 세션 헤더 하단 4-페르소나 상태 표시

**Round**: phase4-r4  **Stage**: impl  **Status**: todo  **Assignee**: pdt-developer
**PRD anchor**: [docs/prd/productune.md#phase-4](../../prd/productune.md#phase-4--terminal-무의존-gui-풀-사이클-future)
**Design**: [docs/designer/service-flow-and-screens.md §4.3 Right panel — Persona presence bar](../../design/service-flow-and-screens.md)
**Bundle**: 본 티켓은 `T-P4-R4-workspace-shell` 번들의 일부로 함께 출고.
**Sibling**: T-P4-041 (Right Panel PO Chat 본체 — 본 티켓이 그 위 한 줄을 추가).

> **사용자 요청 (2026-05-07)**: PO Chat 세션 헤더 아래에서 페르소나가 지금 일하는 중인지를 한눈에 인지하고 싶다. **내용 (작업 본문) 은 노출하지 않는다** — "일하는 중" / "쉬는 중" / "끝남" 만.
>
> Right Panel PO Chat **세션 title/header 바로 아래**, `.rp-msgs` 위에 24px strip 추가. 4 페르소나 (PO / Designer / Developer / QA) 상태 칩. **작업 본문 / prompt / full response 노출 금지** — 상태 + 산출물 이름만.

## Acceptance

### 레이아웃 (24px strip)
- [ ] `.rp-persona-bar` 신규 영역 — Right Panel PO Chat 세션 title/header 직하 / `.rp-msgs` 직상에 삽입
- [ ] height 24px, `padding: 0 10px`, `display: flex`, `align-items: center`, `gap: 10px`
- [ ] background `#161616` (`.rp-ctx` 와 동일 surface), `border-bottom: 1px solid var(--border)`
- [ ] 항상 4 칩 표시 (PO / Designer / Dev / QA) — 위치 안정성. idle 도 dim 으로 visible. 숨김 X
- [ ] Right Panel collapse / FAB 회수 시 함께 collapse — bar 단독 토글 X

### 칩 anatomy
- [ ] 8px filled circle (`.persona-dot`) + 짧은 label (`PO` / `designer` / `dev` / `QA`, 10px caption, persona color)
- [ ] dot color = persona token (`--po` / `--designer` / `--dev` / `--qa`) 또는 state token
- [ ] tab order: PO → Designer → Dev → QA (고정)

### 상태 3종
- [ ] `idle` — dot fill `--txt3` (#4a4a4a, dim), label `--txt2`. 애니메이션 없음
- [ ] `working` — dot fill = persona color, **dot 자체 blink** (opacity 1↔0.2, 0.8s ease infinite). label 정지
- [ ] `done` — dot fill `--success` (#22C55E), label suffix `✓`. 애니메이션 없음. **사용자가 볼 때까지 유지** (자동 fade X)

### 동시 working
- [ ] 2 명 이상 페르소나 `working` 동시 가능 — 각 dot 독립 blink
- [ ] 모두 `idle` 도 가능 (전부 dim) — bar 자체는 항상 렌더

### Done 상태 + artifact tooltip
- [ ] `done` 칩 hover → tooltip 노출 (**artifact/output 이름만**, 작업 내용 / prompt / full response 노출 금지)
  - 위치: 칩 상단 (rp-bar 상단 여유 부족 시 하단 fallback)
  - 내용: artifact 짧은 이름 — 예 `mockup.html updated` / `system.md` / `T-049 closed` / `chat.json saved`
  - 복수 artifact 시 쉼표 1줄, overflow ellipsis
  - 스타일: `bg #1e1e1e`, `border #3a3a3a 1px`, `radius 4px`, `font 10px`, `color var(--txt)`, `padding 3px 7px`, `box-shadow 0 4px 12px rgba(0,0,0,.5)`
- [ ] Done 해제 (idle 로 복귀) 조건 — **다음 둘 중 하나**:
  - (a) 해당 페르소나의 가장 최근 chat 메시지가 `.rp-msgs` viewport 안으로 진입 (IntersectionObserver `threshold: 0.5`)
  - (b) 사용자가 칩 hover 후 칩 외부 click (명시적 dismiss)
- [ ] Done → idle 전환은 즉시 (transition 없음) — 명확한 상태 변화

### 데이터 / 이벤트 스키마
- [ ] `persona-status:update` 이벤트 main → renderer push (Electron IPC bridge)
- [ ] payload 스키마:
  ```ts
  type PersonaStatusEvent = {
    persona: 'po' | 'designer' | 'dev' | 'qa'
    state: 'idle' | 'working' | 'done'
    artifact?: string  // done 일 때만 채움 — tooltip 노출용 짧은 이름
    at: string         // ISO timestamp
  }
  ```
- [ ] 이벤트 발생 위치 (PO doctrine 측 변경 — T-P4-049 와 paired):
  - PO 가 `delegate <persona>` 호출 직후 → `state: 'working'` emit
  - 페르소나 turn 종료 (PO 가 응답 수신) 직후 → `state: 'done'` + `artifact` 채워서 emit
- [ ] artifact 명 도출: 페르소나 응답 JSON 의 산출물 경로 필드 (예: designer 의 `design_doc_path`, developer 의 `changed_files[0]`, qa 의 `verdict_path`) 에서 basename 추출. 복수 시 처음 1–3 개. 없으면 ticket-id (`T-049 done`).
- [ ] 페이지 새로고침 / 앱 재시작 후 — bar 상태는 **모두 idle 로 reset**. 진행중 working 은 in-flight tool-call 추적이 별도 메커니즘이며 본 티켓 out of scope.

### CSS 토큰 / 변수
- [ ] 신규 토큰 추가 X — 기존 `--po` / `--designer` / `--dev` / `--qa` / `--txt3` / `--success` 재사용
- [ ] `@keyframes persona-blink { 0%,100%{opacity:1} 50%{opacity:0.2} }` 신규 정의 — 0.8s ease infinite
