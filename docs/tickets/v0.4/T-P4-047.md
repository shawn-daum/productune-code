## §1 Decision — mount 위치

**Overlay modal**, `WorkspaceShell` 최상위 (grid 외부, `RestartSessionModal` 와 같은
계층). `App.tsx` 가 아니라 **`views/WorkspaceShell.tsx`** — 이유:

- HomeView / OnboardingWizard 에서는 ⌘P 무의미 (project context 없음).
- `openTab` dispatcher 가 `useWorkspace` store 에 묶여 있음 → project 가 mount 된
  WorkspaceShell scope 안이 자연스러움.
- 키 listener 가 이미 WorkspaceShell `useEffect` 안에 있고 `'productune:quick-open'`
  custom event 를 emit 함 → 같은 컴포넌트에서 listener 잡고 local state 토글.

새 컴포넌트 → `components/workspace/QuickOpenPalette.tsx` (단일 파일, ~300 라인 예상).

```
WorkspaceShell
├─ <div style={dynamicGrid}> … (기존 4-col grid)
├─ {restartModalOpen && <RestartSessionModal />}
└─ {quickOpenVisible && <QuickOpenPalette onClose={…} />}   ← 신규
```

local state: `const [quickOpenVisible, setQuickOpenVisible] = useState(false)`.
listener:

```ts
useEffect(() => {
  const onQuickOpen = () => setQuickOpenVisible(true)
  window.addEventListener('productune:quick-open', onQuickOpen)
  return () => window.removeEventListener('productune:quick-open', onQuickOpen)
}, [])
```

## §2 검색 source

palette 가 indexing 하는 4 종 source. 각 source 는 `QuickOpenItem` interface 로 normalize.

```ts
interface QuickOpenItem {
  id: string                    // unique per source — `file:docs/prd.md`, `ticket:T-P4-047`
  source: 'file' | 'ticket' | 'persona' | 'skill'
  label: string                 // 검색 매칭 대상
  sublabel?: string             // 우측 dim 텍스트 (path / type / phase)
  icon: LucideIconName          // FileText / TicketCheck / User / Sparkles
  priority: number              // 0~100, 높을수록 위. tie → fuzzy score
  open: () => void              // 클릭/Enter 시 실행 (§5 dispatcher 통합)
}
```

| source | 수집 방식 | priority 기본 | filter |
|---|---|---|---|
| **files** | IPC: `window.api.listProjectFiles(projectDir)` (신규 IPC, dev 호출에서 추가) — `projectDir` 루트 + `.productune/` 하위 재귀, `.git`/`node_modules`/`dist`/`dist-electron` 제외 | 50 (md = 60, prd.md = 80) | extension whitelist: `.md`, `.json`, `.html`, `.txt` |
| **tickets** | `useWorkspace` po-state + `docs/tickets/**/*.md` 메타 (제목, phase, status) | 70 (open ticket = 75, closed = 40) | status `closed`/`abandoned` 는 sublabel 회색 처리 (배제 X) |
| **personas** | static enum (`pdt-po`, `pdt-designer`, `pdt-developer`, `pdt-qa`, `pdt-tickets-keeper`) — open 시 persona-def tab open | 30 | 항상 표시 (전체 결과의 상수 노이즈는 fuzzy 가 거름) |
| **skills** | static manifest (현 R4 = 사용자 wiki + future skill registry placeholder). 첫 R5 = persona 와 동일 priority 30 | 30 | empty 가능 |

> **수집 trigger**: palette open 시점에 1회 fetch + memoize until close. project 변경 또는
> ticket 추가/삭제 watcher 는 §7 unresolved.

## §4 검색 mechanism

**library 결정: 자체 fuzzy scoring (no fuse.js)**.

이유:
- 현 source 합 ≤ 수백 건 (file + ticket + persona + skill). fuse.js 의 indexing
  overhead 불필요.
- bundle 크기 ↓ (fuse.js ≈ 12KB minified).
- VSCode-style scoring (substring match + camelCase boost + path segment match) 을
  단순 함수로 구현 가능.

### 4.1 scoring 알고리즘

```ts
function score(query: string, item: QuickOpenItem): number {
  if (!query) return item.priority
  const q = query.toLowerCase()
  const label = item.label.toLowerCase()
  const sub = (item.sublabel ?? '').toLowerCase()

  // 1. exact prefix on label → +200
  if (label.startsWith(q)) return item.priority + 200
  // 2. label contains query as substring → +120
  if (label.includes(q)) return item.priority + 120
  // 3. char-by-char subsequence match on label → +60 + (matched/q.length)*40
  const subseq = subsequenceScore(q, label)
  if (subseq != null) return item.priority + 60 + subseq * 40
  // 4. sublabel substring → +20
  if (sub.includes(q)) return item.priority + 20
  // 5. no match → -∞ (filter out)
  return -Infinity
}
```

`subsequenceScore`: query 의 각 문자가 label 에서 순차 등장하면 매치 — 연속 매치
구간이 길수록 보너스 (`matched_consecutive / q.length`).

### 4.2 정렬 + cap

```ts
items
  .map(it => ({ it, s: score(query, it) }))
  .filter(({ s }) => s > -Infinity)
  .sort((a, b) => b.s - a.s)
  .slice(0, 100)        // hard cap — DOM 폭주 방지
```

empty query → 모든 source priority 순 정렬 (file = 50 이라 ticket=70 이 위로 옴 — 의도).

## §5 dispatcher 통합

각 source 의 `open()` 은 `useWorkspace.openTab(...)` 호출.

| source | openTab 호출 |
|---|---|
| file (`.md`) | `openTab('markdown:'+path, 'markdown', { path }, basename(path))` |
| file (`.json`/`.html`/`.txt`) | `openTab('markdown:'+path, 'markdown', { path }, basename(path))` — markdown viewer 가 raw text fallback (dev 확인 필요 §8) |
| ticket | `openTab('ticket-review:'+id, 'ticket-review', { ticketId: id }, id)` |
| persona | `openTab('persona-def:'+slug, 'persona-def', { personaSlug: slug }, slug)` |
| skill | `openTab('skill-matrix:'+id, 'skill-matrix', { skillId: id }, id)` |

`openTab` 의 dedupe (`tabId` 일치 시 reuse) 가 자동 처리 → palette 에서 같은 항목
두 번 열어도 탭 1개 + activate.

palette 측은 store 를 직접 import 하지 않고 prop drill — `QuickOpenPalette` 는
`onPick(item)` 받고 부모가 dispatch:

```tsx
<QuickOpenPalette
  onClose={() => setQuickOpenVisible(false)}
  onPick={(item) => {
    item.open()                  // useWorkspace.getState().openTab(...) 안에서
    setQuickOpenVisible(false)
  }}
  items={…}                      // 부모가 fetch + memoize
/>
```

(parent 가 store hook, child 는 presentational — 테스트 용이성)
