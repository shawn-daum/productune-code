# T-P4-001: Monorepo setup — pnpm workspaces + turborepo + packages/core + packages/cli + packages/gui 골격

**Round**: phase4-r0  **Stage**: impl  **Status**: done  **Assignee**: pdt-developer
**PRD anchor**: [docs/prd/productune.md#phase-4--개발-비숙련-기획자-모드-planner-mode-future](../../prd/productune.md#phase-4--개발-비숙련-기획자-모드-planner-mode-future)
**Estimated complexity**: L4  **Risk flags**: architecture

> Round 0 의 첫 단계. pnpm workspaces + turborepo 를 채택하여 monorepo 인프라를 구성하고, `packages/core`, `packages/cli`, `packages/gui` 세 패키지의 디렉터리 + `package.json` 골격을 생성. 기존 root-level 파일은 이 티켓에서 이동하지 않음 — 실제 이관은 T-P4-002 에서 수행. 이 티켓의 목표는 "패키지 경계 선언" 뿐.

---

## Request

pnpm workspaces 와 turborepo 를 monorepo 도구로 채택한다 (ROADMAP.md OQ 결정: turborepo 추천 — 캐시 + 병렬 빌드). 작업 내용:

1. **루트 워크스페이스 설정**: `pnpm-workspace.yaml` 에 `packages/*` glob 선언. 루트 `package.json` 에 `workspaces` 필드 추가 + `turbo` devDependency 추가.
2. **turborepo 파이프라인 정의**: `turbo.json` 에 `build` / `test` / `lint` 파이프라인 기본 정의. 캐시 설정 포함.
3. **패키지 골격 생성**:
   - `packages/core/package.json` — name: `@productune/core`
   - `packages/cli/package.json` — name: `@productune/cli`, peer/dep on `@productune/core`
   - `packages/gui/package.json` — name: `@productune/gui`, peer/dep on `@productune/core`
   - 각 패키지에 최소 `src/index.ts` (빈 파일) 또는 `index.ts` placeholder 생성
4. `pnpm install` 로 workspace link 동작 확인.

기존 `scripts/`, `po/`, `agents/`, `docs/`, `config/`, `codex/` 등 **root-level 파일은 전혀 이동하지 않음**. 파일 이동은 T-P4-002 스코프.

## Notes

- turborepo 는 `devDependency` 로 루트에만 설치 (`turbo@latest`). 각 패키지에 별도 설치 불필요.
- `packages/core/package.json` 의 `main` 필드는 이 시점엔 placeholder (`"dist/index.js"`) 로 두어도 무방 — T-P4-002 이관 후 확정.
- ROADMAP Round 0 합격 기준: "기존 CLI 동작 100% 보존 + Electron 빈 창 띄우기 성공 + `pnpm -r build` 통과" — 본 티켓은 그 중 **인프라 기반 마련** 단계. CLI 동작 보존 검증은 T-P4-002 에서.
- `pnpm-workspace.yaml` 은 루트에 단독 파일로 존재해야 함 (`package.json` 내 `workspaces` 필드와 병행 사용 시 pnpm 이 yaml 파일 우선 적용).
