## §1 Request

**사용자 directive verbatim (2026-05-18):**
> "PO는 오케스트레이션 only지만.. promotion 반영도 orchestration이야.."

→ Wiki episode write *is* orchestration. PO must be the mechanical executor;
doctrine must reflect this.

### Trigger — T-P4-120 dogfood

직전 ticket T-P4-120 (Alternative-reporting protocol) 의 PROMOTION-APPROVED wiki
write 가 `pdt-designer` subagent dispatch 경로로 6회 sequential fail. 작동 경로는
PO 가 `claude --print` (no `--agent`) subprocess 으로 직접 호출하는 것.

### 4-layer root cause (`plan.md` §1 상세)

| Layer | Failure |
|:--|:--|
| 1 | `~/.productune/productune.env` 의 `GRAPHITI_LLM_PROVIDER` 미설정 → launcher 즉시 exit |
| 2 | `claude mcp add` 미실행 → claude code 가 graphiti 서버 미인식 |
| 3 | agent whitelist `tools:` 항목 `mcp__graphiti__add_memory` 와 actual MCP tool name 정합 (hyphen) — claude code 2.1.142 runtime 에서 "No such tool available" |
| 4 | `claude --agent <persona>` 가 project-local MCP server registration 을 inherit 안 함 — 구조적 |

Layer 3 + 4 는 productune doctrine 외부 (claude code 구현 사정). PO subprocess
경로만이 **현재 유일한 작동 경로** — doctrine 변경 필요.

### What this ticket changes

- PO 가 wiki episode write 의 mechanical executor 가 됨. `claude --print` (no
  `--agent`) subprocess 으로 `[PROMOTION-APPROVED]` 마킹된 task 호출.
- Persona-side `mcp__graphiti__add_memory` call 가능성 **doctrine 에서 제거**.
  `tools:` 화이트리스트도 제거 (Q2 (b) — config-doctrine lock).
- `[PROMOTION-APPROVED]` gate 의미는 유지 — 변경된 건 target executor 만 (persona
  → PO subprocess).
