# T-011: A4 — CLI statusline 강화

> v0.5 Track A, item A4. `productune` CLI statusline 에 현재 phase label + 인-phase 티켓
> 진행률을 compact token 으로 추가한다. bash-only 변경 (React 없음).

## Request

CLI statusline 에 `[<version> P<phase>·<done>/<total>]` 형태의 compact progress token 을
브랜치 segment 옆에 추가한다.

- **데이터 소스**: `~/.productune/po-state.json` (또는 `<cwd>/.productune/po-state.json`) 에서
  `current_version`, `current_phase` 읽기. `jq` 대신 이미 설치된 `python3` 사용 (install.sh 의존성 준수).
- **티켓 카운트**: `docs/tickets/<version>/` 내 `.md` 파일의 frontmatter `phase:` 필드가
  `current_phase` 와 일치하는 티켓만 집계. `status: done` = done, 나머지 = open.
  기존 type-기반 분류를 phase-field-기반으로 교체.
- **Phase label (소문자)**: P1=prd, P2=design, P3=build, P4=deploy, P5=close.
- **출력 포맷 예시**: `v0.5 | phase 3: Build (5/7) | branch: main [v0.5 P3·5/7]`
- **Graceful fallback**: `po-state.json` 부재 또는 python3 실패 → token 없이 기존 출력 그대로.
  에러 메시지 출력 없음, 크래시 없음.
- **Latency**: 스크립트 전체 1초 이내 완료 (네트워크 없음, 로컬 IO 만).

### KR

| # | 요건 |
|---|---|
| KR-1 | 브랜치 segment 에 `[<version> P<phase>·<done>/<total>]` compact token 이 브랜치명 바로 뒤에 붙는다 |
| KR-2 | 티켓 카운트는 frontmatter `phase:` 필드 기반이다 (type 기반 PHASE_TYPES 매핑 제거) |
| KR-3 | `po-state.json` 없을 때 기존 statusline 그대로 출력 (에러/크래시 없음) |
| KR-4 | `bash -n` 문법 검증 통과 |
| KR-5 | P1 phase 에서는 count 없이 `[<version> P1·prd]` 형태로 표시 |

## Acceptance

### Functional

- [x] **[AC-1]** `po-state.json` 이 있는 프로젝트에서 statusline 출력이
  `... | branch: <name> [<version> P<phase>·<done>/<total>]` 형태를 포함한다.
- [x] **[AC-2]** done/total 은 현재 phase 의 `phase:` frontmatter 값과 일치하는 티켓만
  집계한다 (다른 phase 티켓 제외).
- [x] **[AC-3]** `po-state.json` 부재 시 기존 `branch: <name>` 만 출력한다 (에러 없음).
- [x] **[AC-4]** `bash -n packages/core/scripts/statusline-productune.sh` 통과.
- [x] **[AC-5]** 스크립트 실행 시간이 실제 프로젝트 디렉토리에서 1초 미만이다.

## Plan

`packages/core/scripts/statusline-productune.sh` 단일 파일 수정.

1. **Python3 블록 출력 2-line 구조로 변경**: 기존 1줄 출력에서 2줄 출력으로 확장.
   - Line 1: 기존 verbose `PRODUCTUNE_PART` (`v0.5 | phase 3: Build (5/7)`)
   - Line 2: compact `PHASE_TOKEN` (`[v0.5 P3·5/7]`)
2. **티켓 카운트 로직 교체**: `PHASE_TYPES` dict + `type:` 필드 매칭 → `phase:` 필드가
   `current_phase` 와 일치하는지 비교. P1 은 티켓 수 없이 label-only compact token.
3. **phase label 테이블 추가**: `phase_names_short` dict (`{1:'prd', 2:'design', ...}`).
4. **`_STATE_OUT` 변수로 python3 출력 캡처** 후 `sed -n '1p'` / `sed -n '2p'` 로 분리.
5. **RIGHT segment 구성 변경**: `PHASE_TOKEN` 이 있으면 `branch: $BRANCH $PHASE_TOKEN`,
   없으면 기존 `branch: $BRANCH`.

## Outcome

`bash -n` 통과. 실행 테스트 결과:

```
$ echo '{"workspace":{"current_dir":"/path/to/productune"}}' | bash statusline-productune.sh
v0.5 | phase 3: Build (4/4) | branch: main [v0.5 P3·4/4]
```

fallback 테스트 (po-state.json 없는 경로):

```
$ echo '{"workspace":{"current_dir":"/tmp/no-productune-dir"}}' | bash statusline-productune.sh
productune
```

두 케이스 모두 AC 만족. 스크립트 latency = 로컬 IO 전용, 1초 미만.
