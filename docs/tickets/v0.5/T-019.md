# T-019: B3 — OS 알림

> v0.5 Track B, item B3. Full spec = **PRD §B3** (`docs/prd/productune.md` lines 404–413).
> Platform scope = macOS (Notification Center) 우선. Windows parity 는 follow-up (v0.5 gate 아님).

## Request

백그라운드 dispatch 가 제품 핵심이므로, 완료/에스컬레이션/게이트 진입 순간을 창 밖으로 알린다.

- Electron `Notification` 을 PO event stream 의 3개 이벤트 타입에 바인딩: dispatch-done / escalation-raised / phase-gate-entry.
- 알림 클릭 시 관련 surface 로 포커스 이동.

## Acceptance (PRD §B3 AC)

- [ ] **[AC-1]** 3개 이벤트 각각이 창이 백그라운드일 때 native macOS 알림을 발생시킨다.
- [ ] **[AC-2]** 알림 클릭 시 관련 surface 로 포커스가 이동한다.
- [ ] **[AC-3]** tsc 통과.

## Plan

> 변경은 `packages/gui/electron/**` + 클릭 라우팅용 최소 renderer hook 으로 한정.
> `package.json` / `electron-builder.yml` / `.github/` / `scripts/` 는 건드리지 않음 (다른 ticket 소유).

### 1. 이벤트 바인딩 — PO event stream 의 실제 신호에 연결

3개 알림 타입을 invented event 가 아닌 **이미 존재하는** PO stream 신호에 바인딩한다 (`packages/gui/electron/po-runner.ts`).

| 알림 타입 | 실제 신호 (source) |
|---|---|
| `dispatch-done` | `onQaLoopUpdate` `status === 'pass'` — dispatch 된 ticket 의 QA 루프 통과 = 작업 완료 순간 |
| `escalation-raised` | `onQaLoopUpdate` `status === 'capped'`(3-cap 도달) 또는 `'auth-required'`(인증 필요) |
| `phase-gate-entry` | PO `result` envelope 의 `pending_gate` 객체 — 신규 parser `parsePendingGate()` 로 추출 |

`pending_gate` 는 별도 stream event 가 없고 PO 가 po-state.json 에 직접 write + chat envelope 에 실어 보낸다. 기존 `parseQaEnvelope` / `parseTicketFocusItems` 와 동일 패턴(`extractJsonCandidates`)으로 result text 에서 파싱한다.

### 2. `packages/gui/electron/notifications.ts` (신규)

- `fireNotification(spec)` — `Notification.isSupported()` 가드 → `isBackgrounded()` (모든 BrowserWindow 가 `isFocused() === false`) 일 때만 발생 (**AC-1**).
- 클릭 핸들러: focus 된 창(없으면 첫 생존 창)을 `restore()`/`show()`/`focus()` 후 `notification:navigate` IPC 로 route 전송 (**AC-2**).

### 3. `packages/gui/electron/po-runner.ts`

- `PendingGateInfo` 타입 + `onPhaseGate` 콜백을 `RunCallbacks` 에 추가.
- result 핸들러에 `parsePendingGate()` 호출 추가 → gate 감지 시 `cb.onPhaseGate`.
- `emitToWebContents` 의 `onQaLoopUpdate` 를 래핑: 기존 `wc.send` 유지 + `pass` → dispatch-done, `capped`/`auth-required` → escalation-raised `fireNotification`. `onPhaseGate` → phase-gate-entry `fireNotification`.

### 4. `packages/gui/electron/preload.ts`

- `onNotificationNavigate(cb)` 구독 브리지 추가 (`notification:navigate` 채널, unsubscribe 반환).

### 5. `packages/gui/src/store/poEvents.ts` (renderer 클릭 라우팅 hook)

- `api.onNotificationNavigate` 구독 추가. `surface === 'ticket-review'` → 기존 `openTab(...)` 재사용으로 ticket-review 탭 포커스. `surface === 'phase-gate'` → ChatPanel 의 sticky `PendingGateChip` 이 항상 보이므로 창 포커스만으로 충분 (no-op).

### 검증 방법

1. `pnpm --filter @productune/gui tsc --noEmit` → 오류 없음.
2. 수동 검증 (실행 중인 앱 필요):
   - `pnpm dev` 로 앱 실행 → 다른 앱으로 창을 백그라운드 처리.
   - PO 에게 작업을 dispatch → QA pass / 3-cap / phase gate 도달 시 macOS Notification Center 알림 발생 확인 (**AC-1**).
   - 창이 포커스 상태일 때는 알림이 뜨지 않음 확인 (suppress).
   - 알림 클릭 → 창이 앞으로 오고, ticket 알림은 해당 ticket-review 탭으로 이동, gate 알림은 ChatPanel 의 gate chip 이 보임 (**AC-2**).

## Outcome

### 변경 파일

1. **`packages/gui/electron/notifications.ts`** (신규)
   - `fireNotification(spec)` — 백그라운드(`isBackgrounded()`)일 때만 native `Notification` 발생, 클릭 시 창 focus + `notification:navigate` route 전송.
   - `NotifyKind` / `NotifyRoute` / `NotifySpec` 타입 export.

2. **`packages/gui/electron/po-runner.ts`**
   - `import { fireNotification }` 추가.
   - `PendingGateInfo` 타입 + `RunCallbacks.onPhaseGate` 추가.
   - `parsePendingGate()` 신규 parser (result envelope 의 `pending_gate` 추출).
   - result 핸들러에서 `parsePendingGate` 호출 → `cb.onPhaseGate`.
   - `emitToWebContents`: `onQaLoopUpdate` 래핑(pass → dispatch-done, capped/auth-required → escalation-raised) + `onPhaseGate`(phase-gate-entry) 알림 발생.

3. **`packages/gui/electron/preload.ts`**
   - `onNotificationNavigate(cb)` 구독 브리지 추가 (`notification:navigate`).

4. **`packages/gui/src/store/poEvents.ts`**
   - `api.onNotificationNavigate` 구독 추가 — ticket-review route 는 기존 `openTab` 재사용, phase-gate route 는 창 포커스로 충분 (no-op).

### 이벤트 바인딩 (실제 신호)

- `dispatch-done` ← `onQaLoopUpdate` `status === 'pass'`
- `escalation-raised` ← `onQaLoopUpdate` `status === 'capped' | 'auth-required'`
- `phase-gate-entry` ← `parsePendingGate()` (PO result envelope `pending_gate`)

### tsc 결과

`./node_modules/.bin/tsc --noEmit` (packages/gui) — 오류 없음 (pass).

### 이탈 사항

- `phase-gate-entry` 는 별도 stream event 가 없어 PO result envelope 의 `pending_gate` 객체를 파싱하는 방식으로 바인딩 (가장 가까운 실제 신호). PO 가 envelope 에 `pending_gate` 를 싣지 않고 po-state.json 에만 write 하는 경로에서는 알림이 발생하지 않을 수 있음 — QA 시 확인 필요.
- live 알림 발생은 실행 중인 앱 + 실제 PO dispatch 가 필요하므로 tsc 외 자동 검증 불가. 수동 검증 절차는 Plan §검증 방법 참조.
