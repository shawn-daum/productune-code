## R2 — persona×model 2D 피벗 뷰 (신규 집계)

### 데이터 전제 (T-027 (b) 스키마 — 확인됨)

`<project>/.productune/turns.jsonl` 의 각 라인은 이미 `scope`(subagent|main), `persona`,
`model`, `usage{input,output,cache_*}`, `cost_usd`, `session_id` 를 보유 → persona×model
교차표 산출에 추가 캡처 불필요.

### 핵심 비대칭 (반드시 보존)

| scope | token 분해 | cost 집계 규칙 |
|---|---|---|
| **subagent** | `usage{in,out,cache}` 권위 → **표시 + 단순 sum** | per-turn `cost_usd` **단순 sum** |
| **main** (pdt-po) | **신뢰 불가** (context 스냅샷, 누적 아님) → token 셀 **공백/—** | session_id 별 **MAX → 합산** (단순 sum 금지) |

- **`context_window` token 은 절대 합산 금지** (T-027 risk: statusline-cumulative-vs-context).
  main 행은 token 컬럼을 비우고 cost_usd 만 채운다.
- subagent 와 main 의 cost 집계 함수가 **CLI/GUI 동일**해야 함 (T-027 의 기존 parity 계약 연장).

### 뷰 설계 — "어느 페르소나가 어느 모델을 얼마나 썼는지"

**1차 그룹 = persona, 2차 = model.** nested(중첩) 테이블을 채택한다 (matrix 대신).

근거 — fork 결정:
- **nested 채택**: persona/model 카디널리티가 작고(페르소나 5±, 모델 2~3종), 각 셀이
  `turns / tokens(in·out·cache) / cost` 다값(多値)이라 진짜 matrix(셀 1값)에는 안 맞는다.
  또한 main 행의 token 비대칭(공백)을 자연스럽게 표현 가능. CLI 텍스트 출력과도 구조가 일치
  (한 행 = persona+model 조합)하여 CLI/GUI 동형 → parity 검증 용이.
- matrix(행=persona, 열=model, 셀=cost) 는 한눈 비교엔 좋으나 token 분해를 못 담고 main 의
  공백 셀이 "0 비용"과 구분 안 됨 → 기각.

**표시 형태 (nested):**
```
persona            model               turns   in      out     cache    cost_usd
pdt-designer       claude-opus-4-8        12   84.2k   9.1k    51.0k    0.4631
                   claude-sonnet-4-6       4   12.0k   1.8k     6.4k    0.0420
pdt-developer      claude-sonnet-4-6      31   210k    24k    140k     0.2890
pdt-po (main)      claude-opus-4-8         1     —       —       —      0.9120   ← session max
─────────────────────────────────────────────────────────────────────────────
TOTAL                                     48                            1.7061
```
- persona 헤더 행(또는 첫 model 행에 persona 표기, 이후 공백 들여쓰기) + persona 소계 표시.
- main 행: persona 라벨에 `(main)` 표기, token 컬럼은 `—`.
- token 컬럼 합계는 subagent 만 의미 있으므로 **TOTAL 의 token 칸은 비우거나 subagent-only
  소계임을 명시**(over-count 방지). cost TOTAL = subagent sum + main(session-max sum).

  위험 — 동일 fixture 로 교차 검증 필수. QA 게이트.
