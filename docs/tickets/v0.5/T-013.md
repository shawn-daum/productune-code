# T-013: A9 — PO 대화창 개선

> v0.5 Track A, item A9. PO chat 을 first-class 렌더 표면으로 격상한다.
> 세 가지 sub-item: (a) 마크다운 렌더 token 정합, (b) AskUserQuestion 인라인 카드,
> (c) 프로모션 승인/거절 인라인 카드. 어느 것도 채팅 backend/streaming 엔진을
> 건드리지 않는다 — 렌더 + 클릭 표면만.
>
> Design artifacts: `docs/designer/archive/v0.5/T-004-a9-flow.md` · `docs/artifacts/v0.5/T-004-a9-mockup.html`

## Request

### (a) Markdown render polish

`MessageBubble.tsx` 의 `<Markdown>` 컴포넌트가 현재 처리하지 않는 요소들을
design-system token 기반 `md-*` recipe 로 정확히 렌더한다.

- **미처리**: `table/thead/tbody/tr/th/td`, `blockquote`, `h1/h2/h3`, `strong`,
  `pre` (code block), `hr`. 브라우저 기본 스타일로 렌더 → unstyled / wrong token.
- `PERSONA_COLOR.po` = `#FF6B2B` (old orange) — T-006 Option B 적용 필요 (`#8B5CF6`).

**구현 요건**

- `md-*` recipe 명은 `docs/designer/archive/v0.5/T-004-a9-flow.md` §1.1 이 단일 SoT.
  T-013 에서 recipe 명 재유도 금지 — 이름으로만 참조.
- Syntax-highlight: monochrome-leaning subset (`md-syntax-*`) 만 ship.
  OQ-A9-1 (multi-hue palette) 는 PO 미결정 → **구현 금지**.

### (b) AskUserQuestion 인라인 카드 (Surface A)

PO 가 질문 이벤트를 발행하면 모달 대신 chat transcript 안에 옵션 카드를 렌더한다.
사용자 클릭 → 선택 echo → resolved chip 으로 전환하는 전체 상태 흐름 구현.

### (c) Promotion 승인/거절 인라인 카드 (Surface B)

PO 가 promotion-candidate 이벤트를 발행하면 transcript 안에 승인/거절 카드를
렌더한다. 승인/거절 클릭 → resolved 전환 + transcript echo 전체 흐름 구현.

#### 2-2. `MdRenderer.tsx` — ReactMarkdown component 맵

`react-markdown` 의 `components` prop 에 아래 override 를 추가한다.
기존 `Markdown` 함수에서 이 목록이 누락돼 있었으므로 **추가**만 한다:

```tsx
// 추가 필요 컴포넌트 override (기존 p / code / ul / ol / a 는 유지 + 정합)
h1: ({ children }) => <h1 className="md-h1">{children}</h1>,
h2: ({ children }) => <h2 className="md-h2">{children}</h2>,
h3: ({ children }) => <h3 className="md-h3">{children}</h3>,
strong: ({ children }) => <strong className="md-strong">{children}</strong>,
blockquote: ({ children }) => <blockquote className="md-blockquote">{children}</blockquote>,
hr: () => <hr className="md-hr" />,
// pre: fenced code block wrapper
pre: ({ children }) => <pre className="md-code-block">{children}</pre>,
// code: inline vs block 분기 — react-markdown 은 pre > code 가 block
code: ({ className, children }) => {
  const isBlock = !!className  // block code has language class
  if (isBlock) {
    // syntax-highlight 적용 (monochrome subset)
    return <code className={className}>{applySyntaxHighlight(children)}</code>
  }
  return <code className="md-code-inline">{children}</code>
},
table: ({ children }) => <table className="md-table">{children}</table>,
thead: ({ children }) => <thead>{children}</thead>,
th: ({ children }) => <th className="md-table-th">{children}</th>,
tbody: ({ children }) => <tbody>{children}</tbody>,
td: ({ children }) => <td className="md-table-td">{children}</td>,
tr: ({ children, ...props }) => {
  // zebra 는 CSS :nth-child 로 처리 (md-table-row-even) — tr override 불필요
  return <tr>{children}</tr>
},
ul: ({ children }) => <ul className="md-ul">{children}</ul>,
ol: ({ children }) => <ol className="md-ol">{children}</ol>,
p: ({ children }) => <p className="md-body" style={{ margin: 0 }}>{children}</p>,
```

`applySyntaxHighlight(children: React.ReactNode): React.ReactNode` — 텍스트를
정규식으로 분석해 `<span className="sx-*">` 으로 래핑하는 헬퍼. string 토큰만
처리하고 React node 는 pass-through. monochrome subset 패턴:
- keyword: `/\b(def|return|if|else|for|while|import|from|class|const|let|var|function|=>)\b/g`
- string: `/("(?:[^"\\]|\\.)*"|'(?:[^'\\]|\\.)*'|`(?:[^`\\]|\\.)*`)/g`
- comment: `/(#.*$|\/\/.*$|\/\*[\s\S]*?\*\/)/gm`
- number: `/\b(\d+\.?\d*)\b/g`
- punctuation: `/([{}()\[\].,;:])/g`

### 3. (b) AskUserQuestion 카드 — `AskUserQuestionCard.tsx`

#### 3-1. IPC event shape

PO chat IPC 가 action-card 메시지를 구별하는 기존 방법이 없다.
`Message` 타입에 두 필드를 추가한다:

```ts
// packages/gui/src/lib/types.ts
export type MessageKind =
  'po' | 'designer' | 'dev' | 'qa' | 'trace' | 'user'
  | 'ask-user-question'   // ← 신규
  | 'promotion-candidate' // ← 신규

export interface Message {
  // ... 기존 필드 ...
  payload?: AskUserQuestionPayload | PromotionPayload  // ← 신규
}

export interface AskUserQuestionPayload {
  question: string
  options: Array<{ key: string; title: string; description?: string }>
  resolved?: { chosenKey: string }  // 존재 시 resolved chip 표시
}

export interface PromotionPayload {
  candidateSummary: string
  targetTier: string
  rationale: string
  sourceTicketId: string
  resolved?: { outcome: 'approved' | 'rejected' }
}
```

Main process (`packages/core/src/po/chat-ipc.ts` 또는 동등 IPC handler) 에서
PO 가 JSON blob 으로 `ask-user-question` / `promotion-candidate` 이벤트를 발행할
때 위 `payload` 를 `chat:appendMessage` IPC 로 내려 보낸다. 구체적인 PO 발행
트리거가 아직 없으면 **IPC 수신 + 렌더 경로만 구현** 하고, 실제 PO 발행 훅은
별도 follow-up ticket 으로 처리 (risk_flags: `promotion-event-trigger-undefined`).

#### 3-2. 컴포넌트 상태 흐름

```
props.message.payload.resolved 존재
  → ResolvedChip 표시 (idempotent)

아니면
  → live option cards + composer non-trapping
  → 클릭 → local selectedKey state (즉시 ≤100ms)
  → dispatch IPC (async) → spinner on selected card
  → ack → appendMessage({ kind:'user', text: chosenLabel })
           + appendMessage({ ...original, payload.resolved:{chosenKey} })
```

로컬 `selectedKey` 와 `pending` state 는 컴포넌트 내 `useState` 로 관리.
`message.payload.resolved` 가 store 에 반영되는 순간 resolved chip 으로 전환.

### 4. (c) Promotion 카드 — `PromotionCard.tsx`

#### 4-1. 상태 흐름

```
payload.resolved 존재
  → ResolvedApprove 또는 ResolvedReject 표시 (idempotent)

아니면
  → live card (본문 + CTA)
  → [승인] 클릭 → pressed + spinner → IPC → resolved:approved
  → [거절] 클릭 → InlineConfirm 표시 (Esc 무효, [Cancel] 명시)
                 → confirm 클릭 → IPC → resolved:rejected
```

`InlineConfirm` = 카드 하단에 인라인으로 나타나는 compact confirm row.
별도 modal 미사용 (§1.5.5 non-modal pattern).

#### 4-2. 카드 스타일

- `.action-card` shell: AskUserQuestionCard 와 동일 DS token.
- `[승인]` button: `background:#8B5CF6`, `color:#0F0F0F`, `border-radius:4px`, `padding:8px 16px`, `font-weight:500`.
- `[거절]` button: `background:transparent`, `color:#C8C8CC`, ghost style.
- resolved-approve: `border-left-color:#34D399`.
- resolved-reject: `border-left-color:#3A3A3A`, overall `opacity:0.85`.
- `.pill` neutral: `border:1px solid #1F1F1F`, `background:#1A1A1A`, `color:#C8C8CC`, `font-size:10px`, `border-radius:20px`.
- `.pill.tier`: `background:color-mix(in oklab,#8B5CF6 12%,transparent)`, `color:#8B5CF6`.

#### 4-3. Transcript echo (system line)

승인/거절 완료 후 `metadata` recipe system line 을 transcript 에 append:
```ts
appendMessage({
  id: `sys-${Date.now()}`,
  role: 'assistant',
  kind: 'trace',
  text: outcome === 'approved'
    ? `candidate 가 ${targetTier} 에 promote 되었습니다`
    : `candidate 가 거절되었습니다`,
  status: 'done',
  created_at: new Date().toISOString(),
})
```

### 5. IPC 추가 사항

두 카드의 사용자 action 을 PO 에 전달하는 IPC 채널:
- `chat:answerQuestion` — `{ projectDir, messageId, chosenKey }`
- `chat:resolvePromotion` — `{ projectDir, messageId, outcome: 'approved' | 'rejected' }`

Main process handler: store the answer in `chat.json` 의 해당 message `payload.resolved`,
PO 에 answer text 를 이어 보낸다 (기존 `poSendMessage` 경로 재사용 가능).
