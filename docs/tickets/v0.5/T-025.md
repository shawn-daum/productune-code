# T-025: Session / weekly usage bar below chat input (#10)

> Phase 3-B build. Spike confirmed feasibility (see original T-025 spike findings).
> Data source: `rate_limits` object in the statusLine hook response (claude.ai subscribers).

## Request

Show a **UsageBar** below the chat input in `ChatPanel` displaying:
- **5-hour session usage**: `rate_limits.five_hour.used_percentage` + `rate_limits.five_hour.resets_at`
- **7-day weekly usage**: `rate_limits.seven_day.used_percentage` + `rate_limits.seven_day.resets_at`

This is **near-live** — data updates on statusline refresh during active work, not per-turn.

### Data pipeline

1. **statusLine script** (`packages/core/scripts/statusline-productune.sh`): on each refresh,
   if `~/.claude/statsig_* ` / the API response exposes `rate_limits`, write the payload to
   `~/.productune/usage-state.json`:
   ```json
   {
     "five_hour":  { "used_percentage": 42, "resets_at": "2026-06-04T18:00:00Z" },
     "seven_day":  { "used_percentage": 17, "resets_at": "2026-06-09T00:00:00Z" }
   }
   ```
   If a key is absent (non-subscriber or field not yet returned), omit that axis from the file
   rather than writing nulls.

2. **Main process** (`electron/`): `fs.watch` (or `fs.watchFile`) on
   `~/.productune/usage-state.json`. On change, read + parse the file and emit an IPC event
   `productune:usage-update` to the renderer with the parsed payload.

3. **Renderer — `UsageBar` component** (`src/components/workspace/chat/UsageBar.tsx`):
   - Receives `{ five_hour?: UsageAxis; seven_day?: UsageAxis }` via IPC.
   - Renders a compact bar (or two bars) below the chat input, showing percentage fill + reset
     time formatted as "resets in Xh" or "resets in Xd Xh".
   - If a given axis key is absent, hide that axis — do not show an empty/zero bar.
   - If both axes are absent (no file / non-subscriber), render nothing — the component is
     a no-op so the chat layout is unchanged.
   - Style: design-system tokens, lucide-react icons only, no amber.

4. **`ChatPanel.tsx`**: mount `<UsageBar />` below the rate-limit banner and above / adjacent
   to the input textarea (exact slot: just above the draft input row or just below the
   rp-rate-limit-banner region — designer to confirm placement at design time, or default to
   just above the input).

### Caveats (document in code comments)

- Data only available for claude.ai subscribers; hide cleanly for non-subscribers.
- No live updates when there is no active session / the statusline is not refreshing.
- `resets_at` is an ISO timestamp from the API; parse to a relative label in the renderer.

      refresh cycle when `rate_limits` data is available.
- [ ] **[AC-2]** Main process `fs.watch` on `usage-state.json` emits `productune:usage-update`
      IPC to the renderer within one watch callback after the file changes.
- [ ] **[AC-3]** `UsageBar` renders the 5-hour bar (with % fill + reset label) when

- [ ] **[AC-4]** `UsageBar` renders the 7-day bar (with % fill + reset label) when
      `seven_day` is present in the payload.
- [ ] **[AC-5]** If an axis key is absent, that bar is not rendered; if both absent, the component
      renders nothing and the chat layout is unaffected.
- [ ] **[AC-6]** `UsageBar` uses design-system tokens + lucide-react only; no amber color.
- [ ] **[AC-7]** `pnpm tsc --noEmit` passes.

## Plan

1. Extend `statusline-productune.sh`: after the main statusline output, parse `rate_limits` from
   the Claude API response JSON (already available in the hook context) and write
   `~/.productune/usage-state.json`.
2. Add `electron/ipc/usageWatch.ts`: set up `fs.watch` on the usage-state file, read + forward
   payload via `productune:usage-update` IPC. Wire into `electron/main.ts`.
3. Add to `electron/preload.ts`: expose `onUsageUpdate((payload) => void) => unsubscribe`.
4. Build `src/components/workspace/chat/UsageBar.tsx`.
5. Mount in `ChatPanel.tsx`; hook IPC subscription.
6. `pnpm tsc --noEmit` green.

## Out of scope

- Per-turn usage polling (near-live via statusline is sufficient for v0.5).
- Showing usage for non-subscriber / API-key-only users (no data available).
- Editing or resetting usage limits from the GUI.
