# T-014: Build — A2 산출물 뷰어 신설

## Request

### EN (master)

Implement the **A2 Artifacts viewer** per PRD v0.5 item A2 and the design artifacts
`T-002-a2-flow.md` / `T-002-a2-mockup.html`.

**Scope (IN)**

- Left panel `artifacts` tab (ActivityBar slot activated by T-008) → replace the current
  `panelPlaceholder` in `LeftSidebar.tsx` with a real scoped file list.
- Scoped roots (fixed order): `docs/prd/`, `docs/artifacts/<version>/`, `docs/designer/`.
  `<version>` = the current version id from `poState.current_version`; fall back to
  scanning all `docs/artifacts/*/` subdirectories when `current_version` is null.
- Each list row: type-glyph (lucide-react, `--icon-sm`, stroke 2, `currentColor`) +
  filename (`body-dense` recipe). Scope-group labels (monospace, `--text-faint`).
- Clicking a row opens (or focuses) a main-panel tab whose viewer type is chosen by
  file extension (see routing table below).
- **Viewer types**:
  - `.md` → new `artifact-md` tab type — wraps `MdRenderer` (from T-013) read-only;
    breadcrumb showing `docs/…/<filename>` + "읽기 전용" lock badge.
  - `.mmd` / `.mermaid` → new `artifact-mermaid` tab type — wraps `MermaidBlock`
    (existing `packages/gui/src/components/MermaidBlock.tsx`); reads the file as raw
    text and passes it as the `code` prop.
  - `.md` files whose content contains a ` ```mermaid ` fence are handled by the
    `artifact-md` viewer; `MdRenderer` already delegates mermaid fences to
    `MermaidBlock`, so no special routing is needed here.
  - `.html` → reuse the existing `browser` tab type with `props.url = 'file://<absPath>'`.
    No new component; just call `openTab` with `type: 'browser'`.
- **Read-only invariant**: none of the three viewers expose an edit button, editable
  surface, or save action.
- **Tab dedup**: `openTab` in `workspace.ts` already deduplicates globally by `tabId`.
  Use a stable tab id derived from the relative file path:
  `artifact:<relPath>` (e.g. `artifact:docs/prd/productune.md`). Re-clicking the same
  row focuses the already-open tab rather than duplicating it.
- **Empty state**: if the three scoped roots resolve to zero files, render the DS §8.9
  Empty pane (`lucide FolderOpen`, `--icon-2xl`, `--text-faint`; headline
  `heading-section`/`--text-secondary`; one helper line `body-dense`/`--text-muted`).
  No create/edit CTA (read-only version).
- **Load-error state**: if a file fails to read or parse, the viewer shows a DS §2.8
  health-error inline banner (`lucide AlertOctagon`, `--health-error`) with a "다시 시도"
  retry action.
- **No TOC / rich nav**: body-only render; no auto-generated table of contents and no
  cross-doc navigation tree (→ v0.6).
- **GUI-only reachability**: no terminal or OS file-explorer step required to reach any
  listed artifact from the GUI.

**Scope (OUT)**

- Editing artifacts (read-only this version).
- Rich nav / TOC template (→ v0.6).
- Artifacts from paths outside the three scoped roots.

## Plan

### Overview

Five discrete changes across the stack:

1. **IPC: `artifacts:listScoped`** — new handler in `electron/ipc/` that scans the three
   scoped roots and returns a typed file list.
2. **IPC: `artifacts:readFile`** — new handler that reads a file by absolute path (with
   path-traversal guard) and returns the content as a string.
3. **`ArtifactsPane` component** — replaces the `artifacts` placeholder in
   `LeftSidebar.tsx`.
4. **New tab types** — `artifact-md` and `artifact-mermaid` registered in `workspace.ts`
   and `TabContent.tsx`.
5. **Preload bridge** — expose the two new IPC channels on `window.api`.

### 1. IPC — `electron/ipc/artifacts.ts` (new file)

Create `packages/gui/electron/ipc/artifacts.ts`:

```ts
// Channel: artifacts:listScoped
// Args:    projectDir: string, currentVersion: string | null
// Returns: ArtifactEntry[]
interface ArtifactEntry {
  relPath: string       // relative to projectDir, e.g. "docs/prd/productune.md"
  absPath: string
  ext: string           // ".md" | ".mmd" | ".mermaid" | ".html" (lower-cased)
  scopeGroup: 'prd' | 'artifacts' | 'designer'
}

// Channel: artifacts:readFile
// Args:    absPath: string
// Returns: string (UTF-8 content)
// Guard:   resolved path must start with projectDir — reject traversal
```

**`artifacts:listScoped` logic:**

- Determine the three root directories:
  - `prd` root: `<projectDir>/docs/prd/`
  - `artifacts` root: `<projectDir>/docs/artifacts/<currentVersion>/` if
    `currentVersion` is non-null and the directory exists; otherwise walk all direct
    subdirectories of `<projectDir>/docs/artifacts/` and union results.
  - `designer` root: `<projectDir>/docs/designer/`
- For each root: `fs.readdirSync` (non-recursive, top-level only — no deep walk for
  this version). Filter by extension whitelist: `.md`, `.mmd`, `.mermaid`, `.html`.
- Return results in fixed group order: `prd` → `artifacts` → `designer`.
  Within each group, sort alphabetically by filename.
- If a root directory does not exist, skip it silently (no error).

**`artifacts:readFile` logic:**

- Resolve `absPath` with `path.resolve`.
- Path-traversal guard: resolved path must start with `<projectDir>` + `path.sep`.
  Throw `'path traversal rejected'` otherwise.
- Extension guard: only `.md`, `.mmd`, `.mermaid`, `.html` are readable.
- Return `fs.readFileSync(resolved, 'utf-8')`.

Register both handlers in `register()` and export from `electron/ipc/artifacts.ts`.
Wire in `electron/main.ts` alongside the other `ipc/*.register()` calls.

### 7. Tab dedup contract

`workspace.ts` `openTab` already performs global dedup: if any leaf pane already
contains a tab with the given `tabId`, it focuses that tab and returns immediately.
Using `artifact:<relPath>` as the stable `tabId` satisfies this contract — no
additional dedup logic is needed in `ArtifactsPane`.

The same pattern is used by `SidePanelArtifacts.tsx` (T-P4-112) which calls
`openTab(file.path, file.tabType, …)` with `file.path` as `tabId`. This ticket
uses a namespaced `artifact:` prefix to avoid collisions with explorer-opened tabs
that use raw absolute paths as ids.

---

### 8. `browser` tab reuse for `.html`

`BrowserTab.tsx` accepts `props.url` as the initial URL:

```ts
const initialUrl =
  typeof tabProps?.url === 'string' && tabProps.url
    ? tabProps.url
    : 'about:blank'
```

Pass `url: 'file://' + entry.absPath`. The nav bar will show the `file://` URL.
The existing `loadFailed` error overlay in `BrowserTab` covers the load-error case.

**Webview sandbox note**: `file://` URLs load from the local filesystem. Ensure
`BrowserWindow.webPreferences.webviewTag: true` is already set (it is — confirmed in
`BrowserTab.tsx` comment: "Requires webviewTag: true in BrowserWindow webPreferences").
No additional CSP change is needed for read-only local HTML files in this version.
