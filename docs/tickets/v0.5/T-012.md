# T-012: A5 — 채팅 rate-limit 표시

> v0.5 Track A, item A5. Anthropic API 가 rate-limit(429)을 반환할 때, 응답 헤더에서
> 회복 시각을 파싱해 chat UI 에 카운트다운 배너를 표시한다. 표시 값은 추정이 아닌
> 실제 헤더 기반이어야 한다.

## Request

Anthropic API 가 rate-limit 응답을 반환할 때, **정확한 회복 시각** 을 헤더에서 읽어
채팅 패널에 카운트다운 타이머로 표시한다. 타이머가 0에 도달하면 배너가 사라지고
전송 버튼이 다시 활성화된다.

### 구현 범위 (in/out)

- **In**: Anthropic API 직접 응답 경로 (claude CLI 의 stderr/stdout JSONL envelope) 에서
  rate-limit 신호를 포착 → 회복 시각 추출 → renderer 에 IPC 전달 → 카운트다운 UI.
- **Out**: MCP / AI-gateway / 다른 provider 의 rate-limit 처리 (future).

### (a) 429 인터셉트 위치

`packages/gui/electron/po-runner.ts` 의 `handleStderrHealth()` 함수가 이미
`rate.?limit` 패턴을 감지하고 `emitHealth('rate-limited', { resetAt }, ...)` 를 호출한다.
현재 `resetAt` 은 `resets? at <ISO>` 정규식으로 추출하지만 **실제 Anthropic API 헤더**
(`retry-after` 또는 `x-ratelimit-reset-requests`) 는 claude CLI stderr 에 노출되지
않을 수 있다.

따라서 두 계층에서 병행 처리한다.

1. **stderr 텍스트 파싱 (현행 유지 + 보강)**: `handleStderrHealth()` 에서 `retry-after:
   <seconds>` 헤더 값이 클로드 CLI stderr 에 노출될 경우 이를 `resetAt` (ISO string) 로
   변환. 기존 `resets? at` 패턴과 병행 — 먼저 매칭된 값 사용.
2. **stream-json envelope 파싱**: `handleStreamJsonLine()` 의 `type === 'result'` 분기에서
   `obj.subtype === 'error'` 또는 `obj.is_error === true` 시 `obj.error` 문자열을
   추가 파싱 — `429`, `rate_limit_error`, `retry_after` 키워드가 있으면 `emitHealth
   ('rate-limited', { resetAt })` 을 호출. `resetAt` 은 `obj.retry_after` 수치(초)가
   있으면 `Date.now() + seconds * 1000` 으로 계산, 없으면 undefined.

두 경우 모두 `resetAt` 이 없을 때는 **기본값 60초** 를 사용해 카운트다운을 시작한다
(추정 표시 — 이 경우 배너에 "약 N초 후 재시도" 문구 사용).

### (b) retry-after 값 추출

`emitHealth()` 의 `detail.resetAt` 필드는 현재 ISO string (optional). 이를 확장해
`detail.retryAfterSec` (number, optional) 도 받도록 `PoHealthDetail` 인터페이스에 추가한다
(renderer 의 `sessionHealth.ts` `PoHealthDetail` 인터페이스도 동일하게 확장).

우선순위:
1. `retryAfterSec` 이 있으면 `Date.now() + retryAfterSec * 1000` 으로 deadline 계산.
2. `resetAt` (ISO string) 이 있으면 `Date.parse(resetAt)` 으로 deadline 계산.
3. 둘 다 없으면 `Date.now() + 60_000` (기본 60초 fallback — 추정).

### (c) UI 요소

ChatPanel 의 `rp-msgs` 와 `rp-input` 사이에 **`RateLimitBanner`** 컴포넌트를 삽입한다.

- `sessionHealth.state === 'rate-limited'` 일 때만 렌더. 정상 상태에서 DOM 없음.
- **레이아웃**: 36px 고정 높이, 전체 너비. `SessionHealthBanner` 의 `warn` 변형 패턴
  (`--health-warn` `#FBBF24`, 좌측 4px solid bar, `--surface-subpanel` bg) 과 동일
  token 사용.
- **아이콘**: lucide `Clock` (`--icon-sm` 14px, stroke 2, color `--health-warn`).
- **텍스트 구조**:
  - `resetAt` 또는 `retryAfterSec` 있을 때 (실측): `"API 한도 도달 — N초 후 재시도 가능"`
  - fallback (추정): `"API 한도 도달 — 약 N초 후 재시도 가능 (추정)"`
  - N = 남은 초 (정수, `Math.ceil`).
  - 0초 도달 시 배너 즉시 제거.
- **전송 버튼**: 카운트다운 진행 중 `disabled` 처리. 기존 `streaming || !project` 조건에
  `rateLimited` 플래그 추가.
- **dismiss 없음**: rate-limit 배너는 사용자가 직접 닫을 수 없다. 카운트다운 완료 또는
  다음 성공 응답에 의해 자동 해제.

### (d) 카운트다운 tick 메커니즘

renderer 프로세스 (React) 에서 `setInterval` 로 1초마다 tick.

```
RateLimitBanner 마운트 시:
  deadline = sessionHealth.detail.retryAfterSec
             ? Date.now() + detail.retryAfterSec * 1000
             : detail.resetAt
             ? Date.parse(detail.resetAt)
             : Date.now() + 60_000
  setInterval(1000) → remaining = Math.max(0, Math.ceil((deadline - Date.now()) / 1000))
  remaining === 0 → clearInterval + clearHealth()
```

- `useEffect` cleanup 에서 `clearInterval` 필수 (컴포넌트 언마운트 시 leak 방지).
- `deadline` 은 컴포넌트 마운트 시점 1회 계산 (re-render 마다 재계산 X).

### (e) 카운트다운 종료 시 동작

카운트다운이 0에 도달하면:

1. `clearInterval` 호출 (RateLimitBanner 내부).
2. `useSessionHealth.getState().clearHealth()` 호출 → `state` 를 `'healthy'` 로 초기화.
3. `setStreaming(false)` — 이미 streaming=false 여야 하지만 방어적으로 호출.
4. `RateLimitBanner` 언마운트 (state가 'healthy'로 바뀌었으므로 자동).
5. `ChatPanel` 의 전송 버튼 re-enable (`rateLimited` 플래그 해제).

다음 전송 시도는 사용자가 명시적으로 버튼을 누를 때만 발생 (자동 재전송 없음).

## Acceptance

### Functional

- **[AC-1]** Anthropic API rate-limit 응답 (429 또는 `rate_limit_error` subtype) 발생 시,
  ChatPanel 의 `rp-msgs`/`rp-input` 사이에 `RateLimitBanner` 가 노출된다.
  *(기능 발생 시 rate-limit 배너가 chat 패널에 나타난다.)*

- **[AC-2]** 배너의 카운트다운 숫자는 실제 `retry-after` / `retryAfterSec` 헤더 값 또는
  `resetAt` ISO timestamp 에서 파생된다. 헤더가 없을 때는 60초 fallback 이 사용되며
  배너에 "(추정)" 이 표시된다.
  *(카운트다운 값은 실제 헤더 기반이거나, 없을 경우 60초 fallback + 추정 표기.)*

- **[AC-3]** 카운트다운이 0에 도달하면 배너가 사라지고 전송 버튼이 재활성화된다.
  사용자가 별도 액션 없이 자동으로 해제된다.
  *(0초 도달 시 배너 자동 해제 + 전송 버튼 활성화.)*

- **[AC-4]** rate-limit 상태에서 전송 버튼은 `disabled` 이다. 카운트다운 중 전송 불가.
  *(rate-limit 진행 중 전송 버튼 disabled.)*

- **[AC-5]** rate-limit 이 발생하지 않은 정상 응답에서는 배너 DOM 이 존재하지 않는다.
  *(정상 상태에서 배너 없음.)*

- **[AC-6]** `RateLimitBanner` 언마운트 시 `setInterval` 이 정리된다 (memory leak 없음).
  DevTools Performance 에서 interval 누적 없음 확인.
  *(언마운트 시 interval clearup.)*

### Design-system

- **[AC-7]** 배너 좌측 bar = `--health-warn` `#FBBF24`, bg = `--surface-subpanel` `#1A1A1A`,
  아이콘 = lucide `Clock`, height = 36px. `SessionHealthBanner` warn 변형과 동일 token 체계.

### Layer 1 — main process (`po-runner.ts`)

**`PoHealthDetail` 인터페이스 확장**:
```ts
export interface PoHealthDetail {
  persona?: string
  resetAt?: string
  retryAfterSec?: number   // NEW
  errorMessage?: string
  deniedPattern?: string
}
```

**`handleStderrHealth()` 보강**:
기존 `resets? at <ISO>` 패턴에 더해 아래 패턴도 시도:
- `retry-after:\s*(\d+)` → `retryAfterSec = parseInt(match[1])`
- `x-ratelimit-reset-requests:\s*([0-9T:+\-Z.]+)` → `resetAt = match[1]`

**`handleStreamJsonLine()` error result 분기 보강**:
```ts
if (obj?.subtype === 'error' || obj?.is_error === true) {
  const errStr = JSON.stringify(obj?.error ?? '')
  let retryAfterSec: number | undefined
  let resetAt: string | undefined
  if (/rate_limit_error|429|rate.?limit/i.test(errStr)) {
    if (typeof obj?.retry_after === 'number') retryAfterSec = obj.retry_after
    // fallback: undefined → renderer 에서 60초 default 적용
  }
  emitHealth('rate-limited', { retryAfterSec, resetAt }, hCtx, cb)
  return
}
```

### Layer 4 — `ChatPanel.tsx` 수정

1. `sessionHealth` store 구독 추가:
   ```ts
   const healthState = useSessionHealth((s) => s.state)
   ```

2. `rp-msgs` / `rp-input` 사이에 삽입:
