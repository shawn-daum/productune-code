# T-027: 제품별 TOKEN-COST 아카이브 (version·persona·model 집계)

> Plan-first 설계 티켓. 구현 금지. 본 티켓은 "토큰 비용을 캡처 → 영속화 → 집계/조회"하는
> 파이프라인의 설계 + 수용 기준을 정의한다. 실제 구현은 별도 라운드에서 진행한다.

## Request

### Problem

현재 productune 는 토큰 비용을 **어디에도 누적 저장하지 않는다**. 확인된 현실:

- subagent (`claude --agent pdt-*`) 호출의 usage/cost 데이터는 응답 JSON 으로 **흘러 들어오지만**
  `post-bash-strip-cost.sh` 가 사용자에게 보여줄 출력에서 `total_cost_usd`/`modelUsage`/`usage`
  를 잘라낸다 → 데이터는 존재하나 **영속화 없이 버려진다**.
- main-loop (PO) 자기 자신의 토큰 사용량은 어떤 hook payload 에도 직접 노출되지 않는다 (아래 (c) 참조).
- `turns/*.jsonl` 스펙은 README 에 정의돼 있으나 **미구현** (write 코드 없음).
- model id 는 어디에도 권위 있게 기록되지 않는다 (`post-delegate-state-write.sh` 가 명령줄
  `--model` 플래그를 best-effort 로 긁지만 대개 `default` 로 떨어진다).

목표: **product version · persona · model** 3개 차원으로 토큰 비용을 집계 가능한 per-product
아카이브를 만든다.

### (c) CRUX 해결 — main-session 토큰 사용량은 hook 으로 관측 가능한가?

claude-code-guide (공식 docs 재검증) 결과:

- **`Stop` / `SessionEnd` hook payload 에는 토큰/비용 데이터가 전혀 없다.** (`total_cost_usd`,
  `usage`, 토큰 카운트 모두 부재.) → main-session 비용을 Stop/SessionEnd 로 직접 캡처하는 것은 **불가능**.
- `Stop`/`SessionEnd` 는 `transcript_path` (JSONL) 를 받지만, 그 파일의 per-message 토큰 구조는
  **문서화되지 않음** → transcript 파싱은 fragile fallback (스키마 변경에 깨짐).
- **유일하게 문서화된 main-session 캡처 경로 = `statusLine` hook stdin.** 매 statusline refresh 마다
  같은 stdin JSON 에 다음이 들어온다:
  ```json
  {
    "model": { "id": "claude-opus-4-8", "display_name": "Opus" },
    "cost": { "total_cost_usd": 0.01234, "total_duration_ms": 45000, "total_api_duration_ms": 2300,
              "total_lines_added": 156, "total_lines_removed": 23 },
    "context_window": {
      "total_input_tokens": 15500, "total_output_tokens": 1200, "context_window_size": 200000,
      "used_percentage": 8,
      "current_usage": { "input_tokens": 8500, "output_tokens": 1200,
                         "cache_creation_input_tokens": 5000, "cache_read_input_tokens": 2000 }
    },
    "rate_limits": { ... }
  }
  ```

**핵심 행운**: `statusline-productune.sh` 는 이미 이 stdin 을 파싱해 `rate_limits` 만
`~/.productune/usage-state.json` 으로 atomic write 하고 있다. 같은 payload 의 `cost` /
`context_window` / `model.id` 필드는 **현재 무시되고 있을 뿐** — 새 hook 없이 기존 스크립트
확장만으로 main-session 비용 캡처가 가능하다. 이것이 (c) 의 채택 해법이다.

> **주의 — statusLine cost 의 의미론적 함정** (docs v2.1.132): `context_window.total_input_tokens`
> / `total_output_tokens` 는 **현재 컨텍스트 사용량**이지 세션 누적이 아니다. `cost.total_cost_usd`
> 는 세션 시작부터의 client-side 추정 누적값(monotonic). 따라서 main-session 비용은
> **token 합산이 아니라 `cost.total_cost_usd` 의 세션별 최종값(또는 high-watermark delta)** 으로
> 집계해야 한다. token-단위 분해는 main-session 에 대해선 신뢰 불가 → cost USD 를 권위값으로 둔다.

## Design — 5 pieces

전체 파이프라인 = **capture → persist (turns.jsonl) → aggregate (CLI/GUI read)**.

### (a) subagent usage 캡처 (strip 이전, tee/branch)

확인된 사실: PostToolUse(Bash) 에 두 hook 이 각각 등록돼 있고 (`post-delegate-state-write.sh`,
`post-bash-strip-cost.sh`) **둘 다 동일한 전체 `tool_response` 를 독립적으로 stdin 으로 받는다**.
strip hook 은 PO 가 사용자에게 surface 하는 출력만 변형할 뿐, 다른 hook 이 보는 이벤트 사본은
건드리지 않는다. → **별도 tee 불필요**: capture 로직을 `post-delegate-state-write.sh` 안(또는
바로 옆 신규 hook)에 두면 strip 과 무관하게 raw usage 를 본다. 순서 의존성 없음.

캡처 대상 (subagent 응답 JSON envelope):
- `total_cost_usd`
- `modelUsage` (per-model 분해 — model id 의 **권위 출처**, `--model` 플래그보다 신뢰)
- `usage` (input/output/cache_creation/cache_read 토큰)
- 기존에 이미 뽑는 `session_id`, `--agent pdt-<persona>`

> subagent JSON 의 `modelUsage` 정확한 하위 필드명은 공식 docs 에 fully-documented 되지 않음
> (claude-code-guide 확인). → 구현 시 **실제 `claude -p --output-format json` 출력을 한 번 떠서
> 스키마를 고정**하고, 누락 필드는 graceful null 로 처리. (risk_flag 참조.)

### (b) turns JSONL write 구현 (model + usage 필드 포함)

README 의 미구현 스펙을 실제 write 코드로 구현. 위치 제안: per-product
`<project>/.productune/turns.jsonl` (append-only, 1 line = 1 turn).

라인 스키마 (README 스펙 + cost 필드 확장):
```json
{
  "ts": "2026-06-15T09:12:00Z",
  "scope": "subagent",                      // "subagent" | "main"
  "persona": "pdt-designer",                // main 일 땐 "pdt-po"
  "task_slug": "token-cost-archive",
  "ticket_id": "T-027",
  "version": "v0.5",
  "turn_index": 3,
  "model": "claude-opus-4-8",               // subagent: modelUsage 키 / main: cost payload model.id
  "usage": {                                 // subagent: 권위 / main: 부분(컨텍스트 스냅샷, 누적아님)
    "input_tokens": 8500, "output_tokens": 1200,
    "cache_creation_input_tokens": 5000, "cache_read_input_tokens": 2000
  },
  "cost_usd": 0.0385,                        // subagent: total_cost_usd / main: cost.total_cost_usd(세션 누적값)
  "cost_basis": "subagent_total" ,          // "subagent_total" | "main_session_cumulative"
  "session_id": "…",
  "promotion_outcome": null,
  "input_meta": {}, "output_full": null     // README 필드 — 본 티켓 범위 밖, null 허용
}
```

- **subagent turns**: (a) 의 캡처 지점에서 append. `version`/`ticket_id`/`task_slug` 는 po-state.json
  의 `current_version`/`current_task` 에서 읽는다 (statusline 이 이미 같은 파싱을 함 — 재사용).
- **main turns**: (c) 해법 — `statusline-productune.sh` 의 기존 usage-state write 블록 옆에서,
  `cost.total_cost_usd` 가 직전 기록값과 달라졌을 때만 append (refresh 마다 중복 append 방지를 위해
  high-watermark/delta 또는 session_id+cost 변경 감지). `cost_basis="main_session_cumulative"`,
  같은 session_id 의 최신 라인이 그 세션의 권위 누적 비용.

### (c) PO main-session 캡처 — 채택안

위 CRUX 결론대로 **statusLine stdin 의 `cost`/`model.id` 를 `statusline-productune.sh` 에서 추가
캡처**. Stop/SessionEnd 비채택(데이터 없음), transcript 파싱 비채택(undocumented, fragile) — 단
fallback 으로만 문서에 남김.

main-session 집계 주의: 같은 session 의 cost 는 누적 monotonic 이므로 **합산하면 중복 카운트**된다.
집계 시 `scope="main"` 라인은 **(session_id 별) 최댓값**만 취해 합산한다. subagent 라인은
turn 별 독립값이므로 단순 합산.

### (d) model id per-turn 기록

- subagent: `modelUsage` 키 = 권위 model id (명령줄 `--model` 플래그 대신).
- main: `cost` payload 의 `model.id`.
- 둘 다 (b) 스키마의 `model` 필드로 정규화. `post-delegate-state-write.sh` 의 기존
  `recent_turns[].model = "default"` 한계를 이로써 해소 (추후 그 필드도 modelUsage 기반으로 교정 권장).

### (e) 집계/조회 surface (version·persona·model)

파일 포맷 = per-product `<project>/.productune/turns.jsonl` (위 (b)).

**read path 1 — CLI** (`packages/core/scripts/`): `productune cost [--version vX] [--by version|persona|model]`
서브커맨드. turns.jsonl 을 스트림 파싱해 group-by 집계 테이블 출력:
```
version  persona        model            turns   cost_usd
v0.5     pdt-designer   claude-opus-4-8     12     0.4631
v0.5     pdt-developer  claude-sonnet-4-6   31     0.2890
v0.5     pdt-po(main)   claude-opus-4-8      1     0.9120   # session 별 max, 합산 아님
```
- subagent 라인: 단순 sum.
- main 라인 (`scope="main"`): session_id 별 max → 그 후 합산 (누적 중복 방지).

**read path 2 — GUI (선택, v0.5 범위는 read-only 뷰까지)**: `usageWatch.ts` 패턴 재사용해
turns.jsonl 또는 사전집계 캐시를 `fs.watch` → IPC → 신규 `CostArchivePanel` 컴포넌트에서
version·persona·model 매트릭스 표시. **단 본 티켓에서 GUI 는 stretch** — 최소 산출물은 CLI read path.
GUI 상세 레이아웃/토큰/카피는 디자인 라운드에서 별도 확정.

## 비목표 (Out of scope)

- 실시간(per-API-call) 비용 스트리밍. statusline refresh 주기 + subagent 호출 종료 시점 캡처로 충분.
- transcript_path JSONL 파싱 기반 main-session 토큰 분해 (undocumented → fallback 으로만 문서화).
- 실제 청구액 reconciliation (statusline/print cost 는 client-side 추정값임을 UI 에 명시).
- non-subscriber / API-key-only 사용자의 rate_limit 표시 (T-025 기존 동작 유지).
- 기존 `post-bash-strip-cost.sh` 의 사용자-surface strip 동작 변경 (그대로 둔다 — 캡처는 별경로).
- turns.jsonl 의 회전/압축/보존정책 (append-only 무한증가 → 후속 티켓, risk_flag 참조).

## Acceptance

- [ ] **[AC-1]** subagent (`claude --agent pdt-*`) 1회 호출 후, `<project>/.productune/turns.jsonl`
      에 `scope="subagent"` 라인 1개가 append 되며 `model`, `usage`(in/out/cache), `cost_usd`,
      `persona`, `version`, `ticket_id` 필드를 포함한다.
- [ ] **[AC-2]** subagent 라인의 `model` 은 명령줄 `--model` 플래그가 아니라 응답 JSON 의
      `modelUsage` 키(권위 출처)에서 도출된다. modelUsage 부재 시 graceful (`model: null`, 비충돌).
- [ ] **[AC-3]** main-session: statusline refresh 시 `cost.total_cost_usd` 가 직전 기록과 달라지면
      `scope="main"` 라인이 append 되고, 동일 session 의 동일 cost 로는 중복 append 되지 않는다.
- [ ] **[AC-4]** main 라인의 `cost_basis="main_session_cumulative"` 이며 `model` 은 statusLine
      `model.id` 에서 온다.
- [ ] **[AC-5]** strip 동작 회귀 없음: `post-bash-strip-cost.sh` 가 사용자-surface 출력에서 여전히
      cost 필드를 제거하면서도, turns.jsonl 에는 cost 가 캡처된다 (두 hook 독립 stdin 사본).
- [ ] **[AC-6]** `productune cost --by version|persona|model` 가 turns.jsonl 을 파싱해 해당 차원
      group-by 집계를 출력한다. `scope="main"` 라인은 session_id 별 max 로 합산(중복 카운트 없음),
      subagent 라인은 단순 sum.
- [ ] **[AC-7]** turns.jsonl 부재/빈파일/깨진 라인에서 CLI 와 캡처 hook 모두 crash 없이 graceful
      (깨진 라인 skip, 빈 집계).
- [ ] **[AC-8]** non-subscriber / cost 필드 부재 환경에서 캡처는 no-op 이고 T-025 의 rate_limit
      표시 동작은 회귀 없음.
- [ ] **[AC-9]** `pnpm tsc --noEmit` 통과 (GUI read path 를 포함할 경우).

   `total_cost_usd`/`modelUsage`/`usage` 실제 하위 필드명 확정 후 (b) 스키마에 반영.

   version/ticket/slug 읽어 turns.jsonl append. atomic append (lockfile 또는 O_APPEND).
3. **(c)+(d) main capture**: `statusline-productune.sh` 의 usage-state write 블록 옆에
   cost/model.id 파싱 + delta-gated turns.jsonl append 추가.
4. **(e) CLI**: `packages/core/scripts/productune` 에 `cost` 서브커맨드 + group-by 집계 (main=session max).
5. (선택) GUI read-only `CostArchivePanel` — 디자인 라운드 산출물 선행 필요.
6. `pnpm tsc --noEmit` green.

## risk_flags

- **main-session-cost-undocumented-schema** — subagent `modelUsage` 하위 필드명이 공식 docs 에
  fully-documented 아님. 구현 전 실출력 스냅샷으로 고정 필요. 스키마 drift 시 캡처가 조용히 빈값.
- **statusline-cumulative-vs-context** — statusLine `context_window.total_*_tokens` 는 누적이 아닌
  현재 컨텍스트값(docs v2.1.132). main-session 은 token 합산 금지, `cost.total_cost_usd`(세션 누적)만
  권위. 집계 시 session 별 max 필수 — 안 하면 refresh 횟수만큼 과대계상.
- **strip-hook-coupling** — capture 가 strip 과 같은 PostToolUse(Bash) 슬롯을 공유. 두 hook 이
  같은 stdin 사본을 받는다는 전제가 깨지면(향후 CC 버전이 hook chaining 으로 출력 파이프 변경 시)
  capture 가 strip 이후 데이터를 볼 위험. 별도 hook 으로 분리해 결합도 최소화 권장.
- **model-id-source-of-truth** — 명령줄 `--model` 플래그(기존 코드)는 종종 `default` → 부정확.
  modelUsage / statusLine model.id 로 일원화하되 둘 다 부재할 때 fallback 정책 명시 필요.
- **append-only-growth** — turns.jsonl 무한 증가. 보존/회전 정책은 후속 티켓 (본 티켓 비목표).
- **non-subscriber-degradation** — cost/rate_limit 필드는 claude.ai 구독자만 노출. API-key 사용자는
  main-session cost 캡처 불가 → 그 환경에선 subagent-only 집계로 graceful degrade.

   아카이브" 라는 표현은 product-local 을 시사하나, version·persona·model 횡단 비교가 목표라면
   글로벌 롤업이 자연스러움. 둘 중 우선순위 확인 요청.)

   필요 여부 결정.)
