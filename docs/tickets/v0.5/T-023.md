# T-023: Tab overflow shrink + drag-to-edge auto-split (#4)

> Phase 3-B, design-bearing. Two sub-parts kept in ONE ticket per user decision.
> Assignee starts as pdt-designer (UX), then pdt-developer for impl.

## Request

### #4a — Chrome-style tab shrink (no control encroachment)
When many tabs are open they currently overflow and get pushed off the bar. Instead, tabs must
shrink Chrome-style so ALL tabs stay visible within the bar. The right-side controls (split-pane,
close-group buttons — `splitButtons` in `TabBar.tsx:105-117`) must NEVER be encroached or pushed
off: reserve their width; only the tab area flexes/shrinks.
- Define min/max tab width + shrink behavior; show truncated titles with ellipsis at small widths;
  keep the active tab legible.

### #4b — Drag-tab-to-edge → auto-split (cmux / VS-Code style)
Dragging a tab to a pane edge auto-splits the pane and moves the tab into the new split, with
quarter / half drop-zone affordances.
- Existing primitives to REUSE: tab DnD already exists (`TabBar.tsx` `DRAG_MIME`, `dragHint`,
  `onTabDragStart/Over/Drop`, `moveTab`); pane splits exist in the store (`splitRight`, `splitDown`,
  `moveTab`, drag-hint kinds). Add edge drop-zones on the pane body (left/right/top/bottom halves +
  optional quarter zones) that, on drop, split and move the tab.
- Design the drop-zone UX: zone geometry, hover highlight, which edge → which split direction,
  feedback during drag.

### #4c — Bug fix: iframe pointer-capture breaks drag-to-split
The drag-to-split flow already partially exists in the app and has a regression when an HTML
artifact viewer (iframe) is open: the iframe intercepts pointer/drag events, making drop-zones
unreachable. Fix by suppressing pointer events on all iframes while a tab drag is in progress
(e.g. `pointer-events: none` on active iframes, or a transparent full-pane overlay that
captures drag events and delegates them to the drop-zone logic). Ensure drop-zones remain
hit-testable regardless of iframe presence.

### #4d — Bug fix: HTML artifact drop applies with a perceptible lag
After dropping a tab that contains an HTML artifact viewer, the new pane content renders slowly.
Investigate the source of the delay (likely a synchronous layout recalculation, an iframe
re-mount, or a state update chain that forces an expensive re-render) and eliminate the lag so
the drop applies at the same frame cadence as non-artifact tabs.

## Acceptance

- [ ] **[AC-1]** With N tabs exceeding bar width, all tabs remain visible (shrunk); none pushed off.
- [ ] **[AC-2]** The split/close-group controls never shrink, move, or get covered by tabs at any
      tab count or window width.
- [ ] **[AC-3]** Dragging a tab to a pane edge shows a drop-zone affordance and, on drop, splits the
      pane in the indicated direction and moves the tab into the new split.
- [ ] **[AC-4]** Quarter/half drop-zones are distinguishable and map to predictable split directions.
- [ ] **[AC-5]** Existing tab-reorder DnD still works (not regressed); `pnpm tsc --noEmit` passes.
- [ ] **[AC-6]** With an HTML artifact viewer (iframe) open in the source pane, dragging a tab to
      an edge drop-zone works correctly — the iframe does not intercept the drag.
- [ ] **[AC-7]** Dropping a tab that contains an HTML artifact applies without a perceptible render
      lag (comparable frame timing to dropping a non-artifact tab).

## Plan

**Designer to detail at design time** (drop-zone geometry, hover/feedback states, min/max tab width
tokens, truncation rule — all against `docs/designer/design-system.md`). Implementation reuses the
existing `TabBar` DnD + store split/move primitives; this ticket's UX design gates impl. Splitting
into a design ticket + an impl ticket at design close is acceptable if scope warrants.

**Bug-fix sub-tasks (#4c, #4d)** do not require designer sign-off and can be picked up by a
developer against the existing drag system. For #4c: apply `pointer-events: none` to iframes (or
an equivalent overlay) when `dragHint` is active. For #4d: profile the drop path and remove any
synchronous reflow / unnecessary remount.

## Out of scope

- Detaching a tab into a separate OS window; cross-pane drag persistence across restarts.
