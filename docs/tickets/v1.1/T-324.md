## Request

**Ship 눈검 회귀**: 새 프로젝트를 만들고 버전(v0.1)을 선택해 생성한 뒤, 예전에 있던 **"PO에게 첫 요청을 입력하는 초기 화면"(다른 것 없이 입력창만 있던 화면)이 안 뜬다.** 사용자가 첫 문장("OOO 만들고 싶어")을 넣을 자리가 사라짐.

의심 영역(참고): T-321이 PO 세션/챗 경로를 건드렸고(`packages/gui/electron/chat-store.ts`·`po-session-cycle.ts`·`ipc/po.ts`·`packages/gui/src/App.tsx`), 새 프로젝트가 이제 레거시 `.productune` 대신 `.prdt`(`prdt init --json`)로 생성된다. 신규 `.prdt` 프로젝트를 열었을 때의 워크스페이스 초기(빈 챗/첫-요청 입력) 상태가 렌더 안 되는 것으로 추정. 근본 원인은 재현으로 확정할 것.

## Acceptance

- 새 프로젝트 생성(slug→버전 v0.1→생성) 후, PO에게 첫 요청을 입력하는 초기 화면(입력창)이 정상적으로 뜬다 — create→open→첫 요청 입력 가능 상태를 실제로 구동해 확인.
- 회귀 원인을 증상이 아니라 root cause로 잡고, 재발 방지 테스트(가능한 지점)를 추가.
- 기존 프로젝트 열기 경로의 동일 화면도 깨지지 않았는지 확인.
- build green · lint clean · typecheck clean · relevant tests green.

## Outcome

**Root cause** — not T-321's chat/session-cycle edits (those were comment-only `pdt-po`→`prdt-po` renames). T-321 *did* change new-project creation to delegate to `prdt init --json` (packages/gui/electron/ipc/project.ts `createPrdtProject`), which writes `.prdt/po-state.json` as `{schema_version, stage:"define", version:<chosen>, current_task:null}` — `version` is stamped **unconditionally at creation**, before any PO turn.

`EntryGate.hasPrdtWorkTrace` (packages/gui/src/components/EntryGate.tsx, added earlier in T-308/adapter A8 for a different case — resuming a prdt project whose chat.json is empty) treated a non-empty `po-state.json.version` as proof "work already happened." Once T-321 wired brand-new project creation to `.prdt`, every freshly created project satisfied that check on the very first read (status `pending` → work-trace override → `workspace`), so `EntryGate` always skipped `<FreshComposer>` (the "PO에게 첫 요청" 1-input screen) and jumped straight to `WorkspaceShell`. Confirmed against the *real* CLI output (`prdt init --json --slug my-saas --version v0.1` in a scratch dir): old logic → `hasPrdtWorkTrace = true` (bug reproduced); fixed logic → `false`.

**Fix** — moved `hasPrdtWorkTrace` out of `EntryGate.tsx` into the testable SoT `packages/gui/src/lib/phase-mapping.ts` (exported, doc-commented with the failure mode) and dropped the `version` check; kept `current_task != null` and `stage !== 'define'` as the only work-trace signals (both are populated by actual PO turns, never by `init`). `EntryGate.tsx` now imports the shared function instead of a local copy.

**Regression test** — `packages/gui/src/lib/phase-mapping.test.ts` gained `WORK_TRACE_CASES` (framework-free case-list pattern, same as the file's existing suites): brand-new `stage:"define"` + stamped `version` (both `v0.1` and `v1`) → `false`; `stage` advanced or `current_task` assigned → `true`; legacy (`current_phase`, no `stage`) → `false`; null/empty → `false`.

**Existing-open-path check (AC3)** — unaffected. A resumed/migrated project with real work always has `current_task` set or `stage !== 'define'` (this repo's own `.prdt/po-state.json`: `stage:"ship"`, `current_task` assigned) — still routes to `WorkspaceShell`. A project with actual chat history is still caught earlier by the separate `hasMessages` check in `EntryGate`, unchanged. A migrated project with zero PO turns and default `stage:"define"` now correctly gets `FreshComposer` too — that is the intended behavior, not a regression (it genuinely has no PO turns yet).

**Proof of behavior**: `pnpm run build` (typecheck + vite build) green, `pnpm run lint` clean, `pnpm run test` — core 26 + gui 27 green (phase-mapping.test.ts covers the new cases within its single vitest `test()`). Also verified live against the actual `prdt` CLI binary output (see root-cause note above), not just hand-written fixtures.

**Files touched**: `packages/gui/src/lib/phase-mapping.ts` (new export `hasPrdtWorkTrace`, fixed), `packages/gui/src/components/EntryGate.tsx` (now imports the shared fn, local copy removed), `packages/gui/src/lib/phase-mapping.test.ts` (regression cases).
