## Request

**버그 리포트 (shawn, 2026-07-14, 스크린샷)**: PO 턴 실행 중 메시지를 큐에 쌓고 싶은데 **전송 버튼이 없음**.

- 관찰: 실행 중 composer의 placeholder는 "이어서 입력 — PO 턴이 끝나면 전송돼요..."로 큐잉을 안내하는데, 전송 버튼 자리가 정지(stop) 버튼으로 대체되어 있어 큐에 넣을 수단이 안 보임.
- 기대: 실행 중에도 입력한 메시지를 큐에 추가할 수 있어야 함 — 전송(큐 추가) 버튼과 정지 버튼이 공존하거나, 최소한 Cmd+Enter로 큐잉되고 그 사실이 시각적으로 안내되어야 함.
- 확인 필요 (설계 판단): 큐잉 백엔드가 이미 있는지(placeholder 문구가 있는 걸 보면 의도된 기능) — 있으면 UI 노출만 복구, 없으면 함께 구현.

## Acceptance

- While a PO turn is running, typing a message and triggering send (button and/or Cmd+Enter) queues it, and the queued state is visible to the user (e.g. pending indicator).
- The queued message is sent automatically when the current turn ends, in order if multiple are queued.
- Stop button remains available while running; idle-state composer behavior unchanged.

## Outcome

**확인 결과**: 큐잉 백엔드는 이미 T-309에서 전부 구현되어 있었음 — `useWorkspace.enqueueMessage/removeQueuedMessage/clearQueue`, turn-end 자동 flush (FIFO, newline-join, abort 시 큐 보존), 큐 chip 인디케이터(순서 번호 + 개별 제거 X 버튼 + "PO 턴이 끝나면 하나의 메시지로 전송돼요" 힌트)까지 모두 존재하고 단위 테스트(`composerQueue.test.ts`)로 커버됨. 유일한 결손은 **버튼**: T-PATCH-081이 스트리밍 중 전송 버튼을 정지 버튼으로 완전히 대체해버려서, 큐에 넣는 유일한 수단이 (안내 문구엔 없는) Cmd+Enter뿐이었음.
