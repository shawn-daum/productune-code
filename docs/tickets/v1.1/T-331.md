## Request

**CLI 이슈**: `prdt init`의 불필요한 `stage` 질문 제거.

- `init_project()`가 slug → version → stage 순으로 프롬프트를 띄우는데, **stage는 항상 `define`으로 고정**됨. init 시점에 stage를 물어볼 이유가 없음.
- 수정 방향: stage 프롬프트 제거 (stage는 `define` 기본값 유지).

## Acceptance

- `prdt init` 실행 시 stage를 묻지 않는다 (slug, version만 프롬프트).
- 생성된 프로젝트의 `po-state.json` stage가 `define`으로 정상 설정됨.
- 기존 동작(stage 기본값 `define`)에 회귀 없음.

## Outcome

- 2026-07-09: 사용자 캡처(CLI 기능). 다음 버전으로 이월(백로그) — 이번 버전 스코프 아님, 버전 미배정.
- 2026-07-14: 구현 완료. `packages/core/scripts/prdt` `init_project()`에서 stage 프롬프트(`stage_in = input(...)`) 2줄 제거 — interactive 블록이 이제 slug → version만 묻는다. `stage` 파라미터 기본값(`"define"`)은 그대로 함수 시그니처에 남아 `po-state.json` 작성에 그대로 흘러간다. `cmd_init`의 argparse help 텍스트도 "3-item (slug·version·stage)" → "2-item (slug·version); stage defaults to define"로 갱신.
  - 검증: `expect`로 실제 pty 인터랙티브 세션을 구동 — slug/version 두 개만 입력한 뒤 프로세스가 즉시 종료(추가 프롬프트 없음), 생성된 `po-state.json.stage == "define"` 확인. `--yes`, `--json` 비대화형 경로도 동일하게 `stage: "define"` 유지 확인(회귀 없음). `npm test`(vitest 59 + schema-v-guard 2) 전체 green.
  - 테스트 미추가: stage 프롬프트는 `sys.stdin.isatty()` 분기 안에 있어 파이프 stdin(execFileSync 등 기존 vitest 블랙박스 패턴)으로는 애초에 도달 불가한 코드 경로 — 자동화 테스트로 "질문이 없어졌다"를 증명할 수 없고(pty 필요, 기존 테스트 스위트에 pty 인프라 없음), `--yes`/`--json` 경로는 원래도 이 블록을 타지 않아 회귀 신호가 없다. UI-glue 판단(habit)으로 수동 pty 검증(위)으로 doctrine #4 충족.
  - 미해결(designer 라우팅 후보, 코드 아님 — 직접 수정 안 함): `docs/prdt-v1-design.md` §10이 "3항목 인터랙티브 init … slug → 첫 버전 v1 → stage=define"이라고 서술 — 이번 변경으로 stage 프롬프트가 사라졌으니 §10 문구 갱신 필요.
