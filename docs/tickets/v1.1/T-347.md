## Request

**버그 리포트 (shawn, 2026-07-14, 스크린샷 — dogfooding, enneagram-mentor)**: 프로젝트 탭에 **프로젝트 카드가 안 뜸** — ".ENV" 섹션만 보이고 카드 영역이 비어 있음.

- 진단 포인트: 이 프로젝트는 `~/productune/projects/enneagram-mentor` 경로 (legacy 레이아웃 가능성). 카드 렌더 조건(po-state/config 파싱 실패? prdt-only 게이팅? 데이터 부재 시 silent 미렌더?)을 확인하고, 데이터가 없더라도 빈 화면이 아니라 카드 골격+안내가 뜨는 게 기대 동작.

## Acceptance

- The project tab shows the project card for the reported project (and a prdt-standard project) — with slug/version/stage populated when available.
- If required data is missing/unparsable, the card renders a graceful state (skeleton or notice), never silently disappears.
- Root cause of the reported blank card identified with evidence.

## Outcome

**Root cause**: `packages/gui/src/components/workspace/LeftSidebar.tsx` wrapped the entire project card (`SidePanelCurrentVersion`) in `{!isPrdt && (...)}`. `isPrdt` = `isPrdtPoState(poState)` (`phase-mapping.ts`), true whenever po-state carries the flat prdt `stage` field. That gate was intentional per T-291 (adapter A8) — the legacy card reads `versions[]` + `current_version`, which prdt po-state never has — but it suppressed the card with **no replacement**, so every prdt project rendered nothing above `.ENV`. Not a parse failure and not silent-on-missing-data specifically — a straight `!isPrdt` boolean gate with no prdt branch at all.

Confirmed the trigger is the **po-state shape**, not directory layout: `enneagram-mentor` (`~/productune/projects/enneagram-mentor`, legacy path) and `hanta`/`paepyeong` (`<project>/.prdt`, prdt-standard path) all carry the identical flat `{schema_version, stage, version, current_task}` po-state — `isPrdtPoState` is true for all three, so all three were blank before this fix regardless of layout.

**Fix**:
- Added `packages/gui/src/components/workspace/SidePanelPrdtProjectCard.tsx` — the prdt-shaped card (slug / version / stage badge, optional ticket done/total), rendered in the `isPrdt` branch of `LeftSidebar.tsx` (previously empty).
- Graceful fallbacks, in precedence order: (1) `poStateError === 'parse'` → explicit error row (mirrors the existing `SidePanelCurrentVersion` pattern); (2) po-state missing/unparsable such that neither slug nor version resolve → a muted notice row (new i18n key `workspace.versionHistory.sidePanel.currentPrdtMissing`, en+ko); (3) otherwise the card renders with whatever fields ARE available (e.g. slug-only when version is absent) — never blank.
- Slug resolution prefers `poState.project_slug`, falling back to `Project.slug` (always resolved by the app at open time regardless of legacy/prdt-standard layout) — so slug is effectively never blank even though prdt po-state rarely carries `project_slug` itself.
- Extracted the render-vs-fallback decision into a pure `resolvePrdtProjectCard(poState, projectSlug)` in `phase-mapping.ts` (runs `bridgePrdtVersion` internally so it works on raw or already-bridged po-state) — unit-tested in `phase-mapping.test.ts` (6 new cases, incl. the exact enneagram-mentor/hanta/paepyeong shapes, project_slug precedence, version-missing fallback, and null/empty po-state).
- Legacy (`!isPrdt`) path is untouched — `SidePanelCurrentVersion` renders exactly as before.

**Verification**: `tsc --noEmit` clean; `node scripts/check-locale-keys.js` clean (en/ko parity, 955 keys); full `vitest run` — 24 files / 74 tests passing (incl. the 6 new `resolvePrdtProjectCard` cases). No UI test harness (RTL/jsdom) exists in this package for a live-render screenshot, so the case-list drives the actual on-disk po-state shapes from the three real local projects (`enneagram-mentor`, `hanta`, `paepyeong`) rather than a rendered-DOM check.
