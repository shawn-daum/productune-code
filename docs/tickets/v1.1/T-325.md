## Request

**Ship 눈검 회귀/결함**: PO 챗 메시지에서 **순서 목록(ordered list)이 표(table)에 끊기면 번호가 1로 리셋**된다. 예: "결정 필요 — 3가지"가 `1.` → (표) → `1.` `2.`로 렌더 (1·2·3이어야 함). PO가 자주 쓰는 "번호 목록 + 표" 패턴에서 항상 발생.

원인(참고, 접근은 워커 판단): `MdRenderer.tsx`의 `ol` 커스텀 렌더가 마크다운 AST의 `start` 속성을 `<ol>`에 안 넘기고, `md-recipes.css`의 `.md-ol`이 CSS 카운터(`counter-reset: md-ol`)를 매 `<ol>`마다 0으로 리셋 + `li::before content: counter(md-ol)`로 마커를 그려서 native `start`를 무시. 표가 목록을 두 `<ol>`(start=2인 두번째 포함)로 쪼개면 둘째가 1부터 다시 셈.

## Acceptance

- 순서 목록이 표(또는 다른 블록)로 중단돼 여러 `<ol>`로 나뉘어도 번호가 연속됨 — `1.`(표) `2.` `3.`처럼 이어짐. 실제 챗 렌더로 재현 케이스(번호목록+중간 표) 확인.
- native `start` 속성을 존중(둘째 `<ol start=2>` → 2부터). CSS 카운터를 쓰면 start로 시드.
- 기존 순서/비순서 목록 스타일(마커 색·간격, 챗/doc 스코프) 회귀 없음.
- build green · lint clean · typecheck clean · relevant tests green.

## Outcome
- `MdRenderer.tsx` `ol` 렌더가 mdast `start`(remark-rehype는 start≠1일 때만 emit)를 native `<ol start>`로 전달 + `--md-ol-start` CSS var(`start-1`)로 시드.
- `md-recipes.css` `.md-ol`의 `counter-reset: md-ol`을 `counter-reset: md-ol var(--md-ol-start, 0)`로 변경 — var 미설정(대부분 리스트, start=1)이면 기존과 동일하게 0부터, 표로 끊긴 2번째 `<ol start=3>`은 2로 시드돼 `li::before`가 3부터 이어짐.
- 라이브 확인: vite dev + playwright(chromium)로 실제 MdRenderer를 "번호목록 + 중간 표" 재현 케이스로 렌더 — 1·2·(표)·3·4 연속 확인 + 별도 케이스로 native `start=5`(표 뒤 5·6, 3/4 스킵) 존중 확인. 스크린샷으로 시각 검증(임시 harness 파일은 검증 후 삭제, 작업트리 잔류 없음).
- 회귀: `.md-ul`/마커 색·간격·`.md-doc` gap 규칙 미변경, build/lint/typecheck/vitest(27/27) green.
- QA grill 회귀 수정: `--md-ol-start`가 CSS custom property라 상속 → 연속번호(start>1) 목록 안의 **중첩 `<ol>`**(자체 start 없음)이 부모 var를 물려받아 엉뚱한 번호부터 매겨지는 결함. `counter-reset`의 `var(…,0)` fallback은 값이 상속으로 세팅돼 있으면 안 걸림. 수정: ol 렌더가 var를 **항상 명시 세팅**(start 있으면 start-1, 없으면 0) → 자체 start 없는 모든 (중첩 포함) ol이 상속값을 shadow하고 1부터 리셋. 라이브 재검(A 연속·B start존중·C 연속목록속 중첩·D 일반 중첩 4케이스 모두 스크린샷 확인).
