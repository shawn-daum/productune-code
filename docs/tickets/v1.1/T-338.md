## Request

**GUI follow-up (shawn, 2026-07-13, 스크린샷 리포트)**: T-335 이후에도 모델 표기가 기대에 못 미침.

1. **표기 형식**: `claude-sonnet-5` 같은 raw id 형태 말고 **"Claude Sonnet 5"** — 공간이 넓은 곳(모달 옵션, FreshComposer 선택 등)은 "Claude Sonnet 5" 풀네임, **좁은 곳**(스프라이트 칩, 전송버튼 배지)은 **"Sonnet 5"**.
2. **버전 미표시 잔존**: 실사용 세션 스크린샷에서 PO 스프라이트 칩과 전송버튼 배지가 여전히 "Opus"로만 표시 — PO가 이미 응답한 활성 세션인데도 버전 승격("Opus 4.8")이 안 일어남. T-335의 실모델 id 캡처(`po:model-id`)가 실제 GUI 세션에서 발화하는지 진단 필요 (resume 세션 경로, 빌드 미반영 가능성 포함).
3. **모달/선택 UI도 버전 표시**: alias 전용 표면(스위처 모달, FreshComposer 옵션)도 "opus"가 아니라 버전 포함 표기를 원함 — alias→실모델 해석 수단이 필요 (관측된 id 활용, 매핑, 기타 — 설계 판단. 단 하드코딩 드리프트와 버전 발명 금지 원칙은 유지, 해석 불가 시 "Claude Opus" 같은 graceful 표기).

## Acceptance

- No surface ever renders a raw model id (`claude-sonnet-5`) or bare lowercase alias (`opus`): wide surfaces (switcher modal options, FreshComposer selector) render "Claude Sonnet 5"-style full names, narrow surfaces (sprite chips, send-button badge) render "Sonnet 5"-style short names.
- In a real GUI session, the PO chip and send-button badge show the version (e.g. "Opus 4.8") once the session has streamed at least one assistant line — the screenshot scenario (active session, still "Opus") is diagnosed and fixed.
- Alias-only surfaces show a versioned name when the alias can be resolved to a real id without inventing a version; unresolvable aliases degrade gracefully ("Claude Opus" / "Opus").
- No regression in T-334/T-335 behavior (selection, switch-restart, worker forwarding, stale-version clearing).

실제 CLI 프로브(`claude --print --output-format stream-json --verbose --include-partial-messages`, 2026-07-13)로 스트림 셰이프를 실측:

- top-level `type:'assistant'` 라인은 `message.model`을 **실제로 실어옴** → T-335 캡처 로직 자체는 셰이프 정합. 배선(extractPoModel → `po:model-id` → preload `poOnPoModel` → poEvents → `setRealModelId`)도 전 구간 온전.
- 스크린샷 증상(대문자 "Opus", 버전 없음)의 직접 원인 = **stale main/preload 프로세스**: T-335는 워킹트리 상태로 렌더러만 Vite HMR로 반영되고, electron main + preload는 앱 재시작 전까지 구버전 — pre-T-335 main은 `po:model-id`를 아예 안 보내고, pre-T-335 preload엔 `poOnPoModel`이 없어 poEvents의 optional-chain 구독(`api.poOnPoModel?.()`)이 무음 no-op. 대문자 "Opus"(T-335 렌더러 humanizer 동작) + 버전 없음(main 미캡처) 조합이 이 시나리오와 정확히 일치. **→ main 프로세스 변경은 앱 재실행으로만 반영됨: QA/사용자 확인 시 앱 완전 재시작 필수.**
- 코드상 실버그 2건도 발견·수정 (아래) — 재시작만으로는 재발 가능했던 경로들.

### What changed

1. **`system init` 캡처 추가 (`electron/po-runner.ts`)** — 프로브 실측: init 봉투가 top-level `model`(`claude-haiku-4-5-20251001`)을 **턴 시작 시점에** 실어옴 (fresh/resume 공통). assistant 라인 대기보다 이르고 확실 → 첫 토큰 전에 라벨 승격. `!isNested` 게이트로 워커 init이 PO 라벨을 오염하지 않음. 기존 assistant-라인 캡처는 유지(이중 안전).
2. **리마운트 소거 버그 수정 (`src/store/poModel.ts` `load()`)** — 기존엔 `load()` 진입 시 `realModelId`를 무조건 소거 → ChatPanel/PersonaPresenceBar 리마운트(탭 전환 등) 때 세션 중 캡처된 버전이 증발, 다음 턴까지 alias로 회귀. `loadedProjectDir` 추적으로 **projectDir가 실제로 바뀔 때만** 소거 (프로젝트 전환 격리는 유지).
3. **포맷 v2 (`formatModelLabel` 재작성 + `formatModelLabelWide` 신설)** — 실 id의 날짜 스탬프(`-20251001`, 6+자리 숫자 꼬리 세그먼트)를 버전에서 제거 ("Haiku 4.5.20251001" 방지 — 프로브로 발견된 T-335 잔존 결함). legacy version-first 셰이프(`claude-3-5-sonnet-20241022` → "Sonnet 3.5")도 파싱해 raw id 노출 경로 봉쇄. wide는 파싱 성공 시에만 "Claude " 접두 (garbage에 "Claude " 안 붙임). 좁은 표면(스프라이트 칩, 전송 배지)은 기존 short form("Sonnet 5") 유지.
4. **alias 표면 버전 표시 (part 3)** — `observedByAlias` 맵 신설: 라이브 스트림에서 관측된 실 id(PO 자신 = `setRealModelId`, 워커 = poEvents `po:worker-meta` → `recordObservedId`)를 family가 alias 옵션과 일치할 때만 기록. 스위처 모달·FreshComposer·GeneralSettings 옵션은 `poModelOptionLabel`로 관측 id가 있으면 "Claude Opus 4.8", 없으면 "Claude Opus" (버전 발명 없음). 세션 재시작/프로젝트 전환에도 유지(머신 수준 사실).
5. **GeneralSettings raw alias 수정** — 모델 옵션이 bare `opus`를 그대로 렌더하던 AC-1 위반 표면 → wide 라벨로 교체.

### Key decisions
- **관측 기반 해석만, 매핑 테이블 금지** — alias→버전은 이 머신에서 실제로 스트리밍된 id로만 해석 (하드코딩 드리프트·버전 발명 금지 원칙 유지). 미관측 alias는 "Claude Opus" graceful form.
- 날짜 스탬프 판정 = 꼬리의 6+자리 숫자 세그먼트 (실측 8자리 YYYYMMDD, 여유 포함). 유일한 숫자 세그먼트가 날짜면 family만 렌더 (정직한 무버전).
- `observedByAlias`는 family ∈ PO_MODEL_OPTIONS일 때만 기록 (haiku 등 워커 전용 family는 옵션 라벨에 무관하므로 제외).
