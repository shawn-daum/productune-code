## Request

**Ship 눈검 결함 2건 (커플)**: design 산출물(HTML)이 PRD처럼 안 띄워지고, 브라우저 탭에 `file://` URL 직접 입력도 깨짐. 도그푸딩(enneagram-mentor): Designer가 `docs/artifacts/enneagram-mentor-ds.html`를 만들었는데 자동 표시 안 됨.

1. **`file://` URL 오변환 (사용자 직접 리포트)**: `BrowserTab.tsx:319-322` navigate가 `http://`/`https://`만 스킴으로 보고 나머지는 `https://` 프리픽스 → `file:///…` 입력이 `https://file:///…`로 깨짐. **이미 `://` 스킴이 있으면 프리픽스 붙이지 말 것.**
2. **HTML artifact 미표시**: `helpers.ts:109 artifactOpenType`가 `markdown`/`qa-result`만 인식, `.html`은 `null` 반환 → design HTML이 auto-open(`po:artifact-open`) 경로에서 무시됨. PRD(.md)는 열리고 ds.html은 안 뜬 이유.

## Acceptance

- BrowserTab 주소 입력이 이미 스킴(`file://`·`http://`·`https://`·기타 `scheme://`)을 가진 경우 그대로 로드 — `https://` 프리픽스 미부가. 스킴 없는 bare 도메인/입력만 `https://` 보강. `file:///…/ds.html` 직접 입력 시 정상 로드.
- `artifactOpenType`(또는 등가 라우팅)이 `.html` 산출물을 인식해 BrowserTab에 `file://`로 열도록 라우팅 → PO 엔벨로프가 design HTML을 `files_written`/`changed_files`로 방출하면 PRD처럼 자동 표시됨.
- 기존 markdown/qa-result artifact 표시 회귀 없음.
- build green · lint clean · typecheck clean · relevant tests green. 실제로 file:// HTML artifact가 브라우저 탭에 뜨는지 구동 확인.

## Outcome
- **Bug #1** (`BrowserTab.tsx` navigate): scheme detection widened from `http(s)://`-only to any `^[a-z][a-z0-9+.-]*:\/\//i` scheme via a new pure `normalizeBrowserUrl` (`packages/gui/src/components/workspace/main/panes/browserUrl.ts`) — `file:///…`/other schemes now load as-is, bare input still gets `https://` prepended. Unit-tested (`browserUrl.test.ts`, 6 cases).
- **Bug #2**: `artifactOpenType` (`helpers.ts`) return union gained `'html'`, matched by `^docs\/artifacts\/.*\.html$`. `useIpcSubscriptions`'s `po:artifact-open` handler routes `'html'` to a `browser` tab with `file://<projectDir>/<file>` (same routing QuickOpen's `extToTabType` already used for `.html` artifacts) — `projectDir` threaded in as a new param from `WorkspaceShell`. Unit-tested (`helpers.artifactOpenType.test.ts`, 10 cases covering markdown/qa-result no-regression + new html + narrow-scope negatives).
- Gates: `pnpm run build` (tsc + vite, both renderer/main/preload) green · `pnpm run lint` (locale checks) clean · `pnpm exec tsc --noEmit` clean · `vitest run` 18/18 files, 29/29 tests green (no regressions).
- Live drive-verify (playwright-electron, isolated `--user-data-dir` + scratch `.prdt` project, temp spec deleted after run): `po:artifact-open` with a `docs/artifacts/*.html` file opened a BrowserTab whose underlying webContents `.getURL()` matched the exact `file://` path and `.getTitle()` matched the fixture's `<title>`; typing a second `file://` URL into the address bar and pressing Enter loaded it unmodified (input mirrored the exact typed URL post-`did-navigate`, webContents URL/title confirmed) — no `https://file://` mangling. No residue left in the working tree (temp spec, `renderer` symlink, `test-results/` all removed post-run).
