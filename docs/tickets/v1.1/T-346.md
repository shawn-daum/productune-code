## Request

**버그 리포트 (shawn, 2026-07-14, 스크린샷 — T-345 후속)**: GUI 재시작 후에도 enneagram-mentor의 기존 메시지 file:// 경로가 여전히 클릭 불가.

- 스크린샷 증거: 해당 경로들이 **고정폭(inline code) 렌더** — PO가 경로를 백틱으로 감싸 안내한 메시지. T-345의 linkify는 코드 스팬을 건드리지 않으므로(마크다운 의미상 정상 동작) 이 형태는 여전히 죽은 텍스트.
- 실사용에서 PO/워커가 경로를 백틱으로 감싸는 빈도가 높음 → 코드 스팬 안의 artifact/file 경로도 클릭 가능해야 실효성 있음.
- 방향 (설계 판단): MdRenderer의 inline `code` 컴포넌트에서 내용이 file:// URI 또는 `docs/artifacts/*.html`(+ doctrine 경로 등 기존 linkify 대상과 동일 스코프) 단일 경로일 때 클릭 가능하게 렌더 — 코드 모양은 유지하되 클릭 시 T-345 라우팅 재사용. 일반 코드 스니펫 오탐 금지.
- turn-end 자동 오픈(prose 스캔)도 백틱 감싼 언급을 감지하는지 확인 — parseArtifactMentions가 백틱 포함 형태를 커버 못 하면 함께 보완.

## Acceptance

- A file:// URI or docs/artifacts/*.html path wrapped in backticks in a chat message is clickable and routes identically to the T-345 plain-prose case (browser preview for .html).
- The reported real message (bullet list of backticked file:/// paths) becomes clickable on existing history after restart — render-time, no resend needed.
- parseArtifactFiles' prose fallback detects backtick-wrapped artifact mentions for turn-end auto-open.
- Ordinary inline code (non-path snippets) rendering unchanged; no false-positive linkification.

## Outcome

**구현**:
