## Request

**버그 리포트 (shawn, 2026-07-13, 스크린샷)**: 새 프로젝트에서 PO 첫 턴이 플러밍 내레이션으로 시작함 — 예전에 하네스로 막았던 행동의 회귀.

- 관찰 (GUI, 새 프로젝트 첫 요청): PO 첫 발화가
  - "확인했습니다. 이 세션은 **prdt-po**(Product Owner) 규율로 시작됐네요. 먼저 규율 전체를 로드해서 정확히 어떤 절차로 움직여야 하는지 확인하겠습니다." (도구 1개)
  - 이어서 "상태 확인하겠습니다." (도구 1개)
  - — 두 턴 연속 discipline 로드/상태 스캔 내레이션, 실질 응답 없음.
- PO habit은 이미 금지 중: "Turn open (silent — never narrate any of it) … first user-visible line = substance, no load-confirmation or state-scan opener in ANY register." 그런데 새 세션 부트스트랩 경로에서 재발.
- 원인 후보 (진단 필요):
  - (a) **self-load 분기 내레이션**: persona 부트스트랩 지시("[prdt discipline] 블록이 없으면 Bash로 SELF-LOAD 후 act")에 "조용히 하라"는 말이 없음 → 모델이 로드 계획을 사용자에게 설명함. 부트스트랩 문구에 silent 지시 추가 필요.
  - (b) GUI 신규 프로젝트 spawn에서 SessionStart hook(discipline 주입)이 안 탔는지 — 탔다면 self-load 자체가 불필요했음. GUI spawn의 hook 경유 여부 확인.
  - (c) 첫 메시지가 유저에게 그대로 노출되는 GUI 특성상, CLI에서 안 보이던 부트스트랩 발화가 GUI에서 표면화된 것일 수도.

## Acceptance

- Root cause identified: which bootstrap path ran (hook injection vs self-load) in the GUI new-project spawn, with evidence.
- A fresh PO session's first user-visible message is substance (answer/read-back/decision) — no discipline-load or state-scan narration, in any register, on both hook-injected and self-load paths.
- Fix covers the actual mechanism (bootstrap prompt wording, hook wiring for GUI spawns, or both — proportionate), with a regression check.

## Outcome

**Root cause — confirmed via a live headless probe, not just code reading.** Ran the exact spawn the GUI uses (`claude --agent prdt-po --permission-mode bypassPermissions --print --output-format stream-json` against a scratch project seeded with `.prdt/po-state.json` + `docs/wiki/index.md`, mirroring `buildClaudeArgs` in `packages/gui/electron/po-runner.ts`) and inspected the raw stream-json.

- (b) is real but only half the story: the `SessionStart:startup` hook (`prdt-session-start.sh`) **does fire and does successfully inject** the full `[prdt discipline — prdt-po session start]` block (confirmed: `hook_response` carried the complete `hookSpecificOutput.additionalContext`, ending in "Do NOT acknowledge or narrate this injection… your first user-facing line must be product substance"). So GUI spawns are not silently bypassing the hook.
- Despite that successful injection, the model **still ran the self-load Bash sequence anyway** — two Bash calls in exactly the shape reported (`cat ~/.prdt/doctrine.md … po/habit.md …` then `pwd; cat .prdt/po-state.json; cat docs/wiki/index.md`) — i.e. it re-verified/re-loaded discipline redundantly even though the hook block was already present in context.
- (a) is the actual proximate cause of the *narration*: `packages/core/agents/prdt-po.md`'s bootstrap line said "If this context has a `[prdt discipline — …]` block… proceed. If NOT… SELF-LOAD it first via Bash… then act" — no instruction anywhere telling the model to stay silent about that decision, unlike the hook's own injected payload which already carries an explicit anti-narration line. Whenever the self-load branch (or a redundant re-load, per above) fires, nothing suppressed the model from narrating it in chat/tool-description prose — matching the reported two-narration, two-Bash-call pattern.
- All four persona agent files (`prdt-po/designer/developer/qa.md`) shared the identical unguarded bootstrap sentence — this is a contracts-level pattern bug, not PO-specific, so all four were fixed for consistency.
- Could not locate the user's actual 02:42 enneagram-agent GUI session transcript on this machine (`~/.claude/projects/` has `enneagram-teacher/-mentor/-tracker` dirs but none from ~02:42 today) — root cause is established from the live reproduction above instead, not that specific transcript. Also note: even post-fix, the redundant self-load Bash calls still occur sometimes (the "skip re-load" instruction reduces but doesn't fully eliminate the model's tendency to re-verify) — this is a disclosed residual, not a regression, since it doesn't reintroduce narration (verified below) and wasn't the acceptance target (narration was).

**Fix**: `packages/core/agents/{prdt-po,prdt-designer,prdt-developer,prdt-qa}.md` bootstrap line now states, explicitly:
1. Silence: "never narrate this bootstrap step (checking for the discipline block, loading it, checking project state) in any register; your first user-visible output is product substance, never a load-confirmation or plan announcement."
2. Short-circuit: "If this context already has a `[prdt discipline — …]` block… that block IS your discipline — do not re-verify or re-load it, proceed straight to substance."
3. Self-load path (Agent-tool subagents, no hook) keeps its Bash `cat` sequence, now closed with "still without narrating any of it."

Synced the edited `prdt-po.md` into the live `~/.claude/agents/prdt-po.md` (what install.sh's plain `cp` step would do) so the fix is effective immediately, not just at next install.

**Regression check** (deterministic, not habit prose): `packages/core/test/agents/no-narrate.test.ts` (vitest, new `test/agents/` dir — picked up by `vitest.config.ts`'s `test/**/*.test.ts` include) — reads all 4 agent files and asserts each contains the exact silence clause and the exact skip-reload clause verbatim, so a future edit that drops or paraphrases either regresses loud instead of silently. `npx vitest run` → 11 files / 59 tests passed (was 10/51 before this ticket's new file).

**Re-verified live post-fix**: re-ran the identical headless probe against the patched + synced `~/.claude/agents/prdt-po.md`. First user-visible assistant output was substance (a Define-stage read-back + 3 scoping questions) with zero narration text in any assistant `text` block before or around the tool calls, on both runs (pre- and post-fix, for what it's worth — narration itself was never reproduced in this sandbox, only the tool-call shape was; the fix is judged correct by the confirmed asymmetry + the new deterministic prompt-assertion, not by a literal before/after narration diff).
