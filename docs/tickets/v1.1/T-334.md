## Request

**GUI 이슈**: PO 모델이 CLI 기본값을 그대로 상속 — GUI에서 보이지도, 바꿀 수도 없음.

- 사용자가 CLI에서 sonnet을 쓰다가 GUI를 실행하면 PO가 sonnet으로 돌아감. GUI 어디에도 현재 PO 모델이 표시되지 않고 변경 수단도 없음.
- 요구사항 (shawn 지정, 2026-07-13):
  1. **첫 시작 화면(FreshComposer, 질문 인풋만 있는 화면)**: PO 모델을 **기본 opus**로 제공하고, 사용자가 다른 모델로 선택 가능하게.
  2. **세션 사용 중 모델 표시**: PO 스프라이트 하단에 현재 모델 표시. 다른 persona(Designer/Developer/QA)도 실행 중일 때 어떤 모델로 도는지 동일하게 스프라이트 하단에 표시.
  3. **모델 변경은 PO만**: PO 스프라이트 하단 모델 표시를 클릭하면 모델 변경 가능. 변경 시 "세션이 새로 시작됩니다" 안내 문구 필수.
  4. **전송 버튼 좌측**에도 현재 PO 모델 표시.

## Acceptance

- FreshComposer offers a PO model selector defaulting to opus; the chosen model is what the PO session actually launches with (not the CLI default).
- During an active session, the PO sprite shows its current model below it; worker sprites (designer/developer/qa) show their running model the same way while active.
- Clicking the PO model label opens a model switcher (PO only — worker labels are display-only); switching shows a notice that the session will restart, and confirming restarts the PO session on the new model.
- The current PO model is also visible to the left of the send button.
- No regression in existing session start/resume flows.

## Outcome

**Status: implemented, build/typecheck/unit green. Switcher-restart + worker-model live display need a live-session QA pass (can't drive a real PO+subagent session in the dev sandbox).**

### What changed
Built on the existing T-310 infra (`gui_model` in `.prdt/config.json`, applied at spawn by `po-runner`, Settings UI in `GeneralSettings`) — no new config plumbing needed, only new UI surfaces + one additive worker-model forward.

1. **FreshComposer** (`src/components/FreshComposer.tsx`): PO model `<select>` in the composer footer, default **opus** (seeded from any existing `gui_model` so a Settings choice is respected). On send, `setPoSessionOverride({model})` is **awaited before** `poSendMessage` so the spawn launches with the chosen model, not the CLI default. prdt-only (gated on `getPoSessionConfig().supported`); persist failure is non-fatal (falls back to inherit, send still fires).
2. **Sprite model labels** (`src/components/workspace/PersonaPresenceBar.tsx`): each sprite shows its model beneath the label. PO = resolved session model, **clickable** → switcher. Workers (designer/dev/qa) = captured running model, **display-only**, silent when unknown. Bar height 92→106 for the extra line.
3. **PO model switcher** (`src/components/workspace/PoModelSwitchModal.tsx`, new): radio list + **mandatory restart notice**; confirm persists `gui_model` then `poRestartSession` + renderer session reset (mirrors `RestartSessionModal` mechanics) + restart-completed toast.
4. **Send-button-left badge** (`src/components/workspace/ChatPanel.tsx`): current PO model shown left of send, display-only.
5. **Worker model capture** (`electron/po-runner.ts` → `preload.ts` → `store/poEvents.ts` → `store/personaPresence.ts`): forwarded via the existing `po:worker-meta` channel from `extractSubagentCapture().model`, persona resolved by the same `delegatedByToolUseId.get(parentId)` key the proven worker-stream path uses. Sticky-merged in `WorkerMeta.model`, silent-on-missing (same posture as usage/duration).

New shared renderer store `src/store/poModel.ts` (`usePoModel` + `resolvePoModel` + `DEFAULT_PO_MODEL='opus'`) backs surfaces 2/3/4.

### Key decisions
- **Display resolves `gui_model ?? 'opus'`** (opus = declared GUI default). I did **not** change `po-runner`'s null→inherit spawn semantics — that protects the "no resume regression" acceptance. FreshComposer + the switcher always persist an explicit model, so the forward path is honest; the null (inherit) case only survives for pre-T-334 projects that never went through either.
- **prdt-only gating** everywhere the model is shown/switched (legacy `.productune` projects don't support the override — showing/switching would be meaningless/error).
- Worker-model forward is **additive + graceful** — if the sidechain stream never carries `model`, the label simply doesn't render.
