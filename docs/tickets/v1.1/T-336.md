## Request

**버그 리포트 (shawn, 2026-07-13, hanta 프로젝트)**: PO가 build → deploy로 넘어가면서 **stage 수정도 안 하고 회고(Retro)도 진행하지 않음**.

- 관찰: hanta 프로젝트에서 build 단계 작업 후 deploy까지 갔는데, `po-state.json` stage 전환(build→ship)이 없었고, ship 이후 라이프사이클 리추얼(ship-entry readiness, 이후 Retro 진입)도 일어나지 않음.
- 기대: PO habit상 deploy는 ship 단계 소속 — ship 진입 시 readiness pass, 버전 마무리 시 Retro(wiki consolidation + doctor)가 돌아야 함. stage는 lifecycle move 때 PO가 갱신해야 함.
- 원인 후보 (진단 필요 — hanta 쪽 po-state.json / wiki log / 세션 transcript 확인):
  - (a) habit/contracts 문구가 "deploy 전 ship 진입"을 강제 신호로 만들지 못함 (soft stage라 PO가 그냥 지나침)
  - (b) PO 모델 비준수 (규율은 있으나 무시) → habit 문구 강화 또는 deterministic hook backstop 필요
  - (c) stage 이동 신호 부재 — "turn open + doctor가 유일한 신호 지점"인데 해당 턴에서 둘 다 안 걸림

## Acceptance

- (진단 후 상세화) Root cause identified with evidence from the hanta project (po-state, wiki log, or transcript).
- A PO moving build→deploy without a ship-entry transition is prevented or reliably self-corrected (habit/contracts wording, hook backstop, or both — proportionate to the diagnosed cause).
- Retro is not silently skipped when a version wraps: the PO proposes Retro entry when ship-stage deliverables run dry.

**수정 (원인에 비례: deterministic 신호 복원 + habit 트립와이어):**

1. **신규 hook `prdt-user-prompt.sh`** (v1 hook #4, UserPromptSubmit, advisory-only additionalContext):
   - 매 user prompt마다 `[prdt state] stage=… · version=… · current_task=…` 1줄 주입 — habit이 가정한 turn-open 상태 읽기를 장수 세션에서도 결정적으로 보장.
   - deploy 모양 prompt(deploy/release/merge/main pr/배포/머지/출시 등) + stage가 define/build → ship-entry 경고 1줄 추가 (hanta 실패 지점 문자열 "main pr"·"머지완료"·"배포 완료"가 테스트 케이스). ship 단계 redeploy(패치 루프)는 경고 없음. soft stage 유지 — 차단 아닌 advisory (doctrine #5).
   - prdt 프로젝트 밖·파싱 실패 시 무음 no-op. 테스트 12/12 green (`packages/core/test/scripts/user-prompt-stage-guard.test.ts`, test-first).
2. **install.sh §4** UserPromptSubmit 등록 (hook 3종→4종) + README. uninstall은 path-prefix strip이라 자동 커버. sandbox에서 real install.sh 구동 → 미러된 hook에 hanta 시나리오 주입 → 경고 발화 e2e 확인.
3. **GUI 미러** (`onboarding.ts` PRDT_HOOK_BASENAMES + H.UserPromptSubmit) — "GUI/CLI 등록은 절대 diverge하지 않는다" 기존 불변식 유지. GUI 테스트 2 스위트 green.
4. **PO habit** (Lifecycle judgment): ① 신호 지점에 `[prdt state]` line 추가 + "days-ago 읽은 상태는 stale, 현재 턴의 line이 authority" ② **"Deploy IS ship"** — deploy 모양 요청은 ship-entry 이벤트, readiness+stage write가 deploy 작업보다 먼저 (또는 명시적 N/A-skip log) ③ live 검증된 deploy + 패치 큐 비면 **같은 reply에서 Retro 제안** — 사용자가 물을 때까지 방치 금지.
