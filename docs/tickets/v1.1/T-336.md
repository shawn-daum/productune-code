## Request

**버그 리포트 (shawn, 2026-07-13, hanta 프로젝트)**: PO가 build → deploy로 넘어가면서 **stage 수정도 안 하고 회고(Retro)도 진행하지 않음**.

- 관찰: hanta 프로젝트에서 build 단계 작업 후 deploy까지 갔는데, `po-state.json` stage 전환(build→ship)이 없었고, ship 이후 라이프사이클 리추얼(ship-entry readiness, 이후 Retro 진입)도 일어나지 않음.
- 기대: PO habit상 deploy는 ship 단계 소속 — ship 진입 시 readiness pass, 버전 마무리 시 Retro(wiki consolidation + doctor)가 돌아야 함. stage는 lifecycle move 때 PO가 갱신해야 함.
- 원인 후보 (진단 필요 — hanta 쪽 po-state.json / wiki log / 세션 transcript 확인):
  - (a) habit/contracts 문구가 "deploy 전 ship 진입"을 강제 신호로 만들지 못함 (soft stage라 PO가 그냥 지나침)
  - (b) PO 모델 비준수 (규율은 있으나 무시) → habit 문구 강화 또는 deterministic hook backstop 필요
  - (c) stage 이동 신호 부재 — "turn open + doctor가 유일한 신호 지점"인데 해당 턴에서 둘 다 안 걸림

## Acceptance

- (진단 후 상세화) Root cause identified with evidence from the hanta project (po-state, wiki log, or transcript).
- A PO moving build→deploy without a ship-entry transition is prevented or reliably self-corrected (habit/contracts wording, hook backstop, or both — proportionate to the diagnosed cause).
- Retro is not silently skipped when a version wraps: the PO proposes Retro entry when ship-stage deliverables run dry.
