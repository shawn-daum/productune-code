## Request

**GUI 이슈 (T-334 follow-up)**: 모델 표시에 버전 넘버까지 — "Sonnet 5" 식으로.

- T-334가 넣은 모델 표시(스프라이트 하단 라벨, 전송버튼 좌측 배지, FreshComposer 선택, 스위처)가 현재 alias 수준("sonnet"/"opus")으로 보임.
- 요구사항 (shawn, 2026-07-13): 모델명을 **넘버 포함 사람이 읽는 형태**로 — "Sonnet 5", "Opus 4.8" 식.
- 참고: spawn은 alias로 하지만 세션/사이드체인 스트림에는 실제 모델 id(`claude-sonnet-5`, `claude-opus-4-8` 등)가 실려옴 — 표시는 실제 id 기반으로 하고, id 미수신 구간(선택 UI 등)의 처리와 미지 id의 graceful 표기는 설계 판단.

## Acceptance

- Everywhere T-334 shows a model (sprite labels, send-button badge, FreshComposer selector, switcher), the label is human-readable with the version number (e.g. "Sonnet 5", not "sonnet").
- Labels derive from the actual model id when the session/stream provides one; unknown or not-yet-received ids render gracefully (no error, reasonable fallback — never a blank/broken label).
- No regression in T-334 behavior (selection, switch-restart, worker label forwarding).

### What changed

**1. Humanizer (`src/store/poModel.ts`, new exports).**
`formatModelLabel(idOrAlias)`: parses a real model id (`claude-<family>-<v>[-<v2>]`, optionally with a bracketed deployment suffix like `[1m]`, stripped the same way `costArchive.ts`'s `normalizeModelId` does) into `"Family V[.v2]"` (`claude-opus-4-8` → `"Opus 4.8"`, `claude-sonnet-5` → `"Sonnet 5"`). Not a lookup table — any well-formed `claude-<letters>-<digits>[-<digits>]*` id parses the same way, so a brand-new model id needs no code change. A bare alias (`"opus"/"sonnet"/"fable"` — all `PO_MODEL_OPTIONS` ever is) has no knowable version, so it renders as just the capitalized family, never an invented number. Anything unparseable renders as-is (never blank/broken — T-335 AC-2).
`poModelLabel({model, realModelId})`: the PO's combined display label — prefers the live-captured `realModelId` (formatted), falls back to the capitalized alias when none has arrived yet.

**2. PO's own real model id, captured live (new plumbing — this is the piece that makes the PO sprite/badge/switcher actually show a version number, not just the worker labels T-334 already fed with real ids).**
The alias (`gui_model`) is the CLI `--model` arg, never a version — so satisfying "human-readable with the version number" for the PO's OWN label (the surface the user actually saw "sonnet"/"opus" on) requires the real id, and nothing upstream captured it before this ticket (only worker/subagent ids were captured, via `extractSubagentCapture`). Added the symmetric top-level path:
- `electron/subagent-cost.ts`: `extractPoModel(obj, isNested)` — reads `message.model` (falls back to top-level `model`) off a **non-nested** stream-json line; returns `null` when nested (never leaks a worker's model onto the PO label) or when the line carries no model field (most don't).
- `electron/po-runner.ts`: new `RunCallbacks.onPoModel(model)`; called from the top-level `assistant` handler (right after the existing `isNested → return` guard, so it only ever sees PO's own lines) whenever a line carries the field. Wired in `emitToWebContents` → IPC `po:model-id`.
- `electron/preload.ts`: `poOnPoModel(cb)` subscription, mirrors `poOnWorkerMeta`.
- `src/store/poEvents.ts`: subscribes and calls `usePoModel.getState().setRealModelId(model)`; also clears it (`setRealModelId(null)`) in the existing `po:sessionRestarted` handler, since a fresh session's real id is unknown until ITS first line (prevents a stale pre-restart version lingering after a model switch).
- `src/store/poModel.ts`: `realModelId: string | null` state, also cleared at the top of `load()` (the project-switch entry point both `PersonaPresenceBar` and `ChatPanel` already call) so a previous project's captured id never bleeds into a newly-opened one.

**3. Surfaces updated to render the humanized label.**
- `PersonaPresenceBar.tsx`: PO chip → `poModelLabel({model, realModelId})`; worker chips → `formatModelLabel(workerMeta[id].model)` when present (still silent/undefined when not yet captured — unchanged T-334 posture).
- `ChatPanel.tsx`: send-button-adjacent badge → same `poModelLabel` combo.
- `FreshComposer.tsx`: PO model `<select>` options → `formatModelLabel(m)` (alias-only surface — capitalized family, no invented version, per the ticket's explicit guidance).
- `PoModelSwitchModal.tsx`: option-list labels → `formatModelLabel(m)` (same alias-only reasoning).

### Key decisions
- **New capture plumbing was necessary, not scope creep.** The ticket's own WHY ("사용자가 sonnet만 보고 세대를 모른다") points at the PO's own label, which is alias-only architecturally — without capturing the real id there was no way to ever show a version number on the surface the user actually flagged. Kept it minimal and symmetric with the existing (already-shipped, already-graceful) worker-model capture: same extraction shape, same best-effort/silent-on-missing posture, same IPC pattern.
- **Graceful degradation is layered, not a single fallback.** No real id yet this session → capitalized alias. Unparseable id ever received → raw string. Never blank, never a thrown error, matches AC-2 literally.
- **No new locale keys / UI copy added.** Stayed inside "make existing labels readable" — did not add a "currently running: X" hint or similar, to keep the diff scoped to what T-335 actually asks.
