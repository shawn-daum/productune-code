## Request

**버그 재발 리포트 (shawn, 2026-07-14, 스크린샷)**: T-344(리마운트 방식) 이후에도 **실제 macOS 한글 입력기**에서 잔류 재현.

- 재현: "하던거 계속해줘" 입력, 마지막 글자 조합 중 Cmd+Enter → 메시지는 전문 전송, 인풋에 "줘" 잔류.
- T-344의 CDP `Input.imeSetComposition` 검증은 브라우저 레벨 조합만 재현 — OS 입력기(macOS 한글)의 조합 세션은 리마운트 후 **재포커스된 새 textarea에 pending 글자를 다시 삽입**하는 것으로 추정.
- 방향 후보 (설계 판단): 전송 시 클리어 전에 `blur()`로 IME 커밋을 강제 후 클리어→리포커스 / 리포커스를 IME 세션 정리 이후로 지연 / compositionend 대기 후 클리어 등 — 실기기 한글 입력기로 재현·확인이 필수 (CDP 시뮬레이션만으로 pass 처리 금지).

## Acceptance

- With the real macOS Korean IME (실기기), typing Korean and pressing Cmd+Enter mid-composition sends the full text and leaves the input empty — no residual glyph, across ChatPanel (idle + queue) and FreshComposer.
- Verified against the actual OS IME (manual repro script or equivalent evidence) — CDP composition simulation alone is not sufficient proof for this ticket.
- No regression to T-344 behavior under non-IME input, plain Enter, and focus restoration.

## Outcome

**실기기 재현 성공 (자동화)**: CDP 시뮬레이션이 아니라 **실제 macOS 2-Set Korean IME**로 버그를 자동 재현했음. 핵심 발견 — AppleScript `keystroke`는 문자 페이로드를 실어 IME를 우회하지만(리터럴 "wnj" 입력됨), **raw virtual-key 이벤트(`key code {13,45,38}`)는 OS 입력기를 통과**해 "줘"를 진짜로 조합함. 이걸로 빌드된 앱(echo mode, fake HOME)을 Playwright로 띄우고 System Events key code로 조합 중 Cmd+Enter를 넣는 하네스를 구성 (`scratchpad/t354-harness.cjs` + `ime-select.swift` TIS 헬퍼).

- **T-344 빌드 재현 결과**: idle 경로 — 조합 "줘" 확인 → Cmd+Enter → 메시지 전송됨 + **textarea에 "줘" 잔류** (`idle_valueAfterSettle: "줘"`). queue 경로 — 큐 chip 등록 + **"줘" 잔류**. 사용자 리포트와 정확히 일치. 스크린샷 증거 확보.
- **원인 확정**: T-344의 리마운트는 브라우저 측 조합 세션만 버림. OS 입력기의 조합 상태는 DOM 노드와 독립적으로 살아있고, 리포커스된 새 textarea에 pending 글자를 재삽입. (T-344의 리포커스 effect가 React 18 discrete-event 동기 flush로 같은 keydown 처리 중에 실행된 것도 재삽입 창구를 넓힘.)

**수정** (방향 후보 ① blur-커밋-강제 채택 + 리포커스 지연 결합):
- `ChatPanel.handleSubmit`: 클리어 전에 `taRef.current?.blur()` — first-responder 상실이 Chromium이 OS IME에 조합 commit-and-end를 요청하는 유일한 신호. 커밋된 글자는 곧 리마운트될 옛 노드에 떨어지므로 무해 (`trimmed`은 이미 전문 캡처). idle/queue 두 경로 모두 커버.
- 리포커스 effect를 `setTimeout(…, 0)` macrotask로 지연 — IME 세션 teardown 이후에 새 노드가 포커스를 받도록.
- `FreshComposer.handleSend`: 동일 blur-first 적용 (전송 중 disabled라 재삽입 창구 자체가 없어지는 것도 확인).
- T-344의 key bump 리마운트는 유지 (브라우저 측 세션 + blur-커밋 잔여물 폐기, belt-and-suspenders).

**수정 빌드 검증 (동일 하네스, 실 IME)**:
- idle: 조합 "줘" → Cmd+Enter → 전송 확인 + 잔류 `""` ✓
- queue(스트리밍 중): 큐 chip "줘" 등록 + 잔류 `""` ✓ (T-343 큐 버튼 표시도 회귀 없음)
- 비-IME 회귀: ABC 레이아웃 "hello" + plain Enter → newline 유지(전송 안 됨), Cmd+Enter → 전송+클리어, **전송 후 포커스 복원 유지** ✓
- 게이트: `tsc --noEmit` clean · vitest 103/103 green · 빌드 green.

**남은 검증 한계 (명시)**: 하네스의 key code 주입은 실 IME 엔진을 통과하지만, 사람 손의 타이핑 타이밍/조합 패턴(길고 빠른 문장, 다양한 종성 조합)까지 전수 재현한 것은 아님. FreshComposer는 동일 패턴 적용 + 코드 추적으로 확인했고 하네스 직접 구동은 ChatPanel 두 경로만 수행. 최종 확인은 사용자 실기기 타이핑으로 받는 것을 권장.
