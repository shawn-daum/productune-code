## Request

**버그 리포트 (shawn, 2026-07-14)**: 한글 IME 조합 중 전송 시 조합 글자가 인풋에 잔류.

- 재현: "확정" 입력 → 마지막 글자 "정"이 아직 조합 중(커서 깜박)일 때 **Cmd+Enter** → 메시지는 "확정"으로 정상 전송되는데, 인풋창에 "정"이 남음.
- 원인 유형: composition(조합) 이벤트 미처리 — 전송 시 조합 중인 텍스트를 flush/취소하지 않고 입력값만 비워서, IME가 조합 세션을 이어가며 글자를 재삽입하는 전형적 패턴.
- 범위: ChatPanel composer + FreshComposer 등 텍스트 전송 입력 전반 — 동일 핸들러면 같은 버그.

## Acceptance

- Typing Korean text and pressing Cmd+Enter mid-composition sends the full text and leaves the input completely empty (no residual composing character).
- Behavior verified for both the running-turn queue path and the idle send path, and on FreshComposer if it shares the pattern.
- No regression for non-IME (English) input or plain Enter/newline behavior.
