## Request

**버그 (shawn 승인, 2026-07-15)**: 기기 override(`~/.prdt/overrides/<persona>.md`)가 세션에서 미적용되는 사고 발생.

- 원인 (PO 진단): SessionStart hook이 discipline 전체(doctrine→contracts→habit→overrides)를 하나의 additionalContext로 주입하는데, 크기 초과(16.6KB) 시 하네스가 파일로 persist하고 **미리보기 2KB만** 컨텍스트에 노출 — 맨 뒤의 overrides가 통째로 유실됨. 실제로 이번 세션에서 PO가 개조식/호칭/커밋금지 override 3건을 전부 미적용.
- 수정 방향 (shawn 선택 = a안): **overrides를 본 블록과 별도의 작은 주입으로 분리** — 크기로 잘릴 일 자체를 제거. hook이 additionalContext를 2번 내보내거나(가능 여부 확인), 불가하면 overrides를 주입 블록 **최상단**에 배치하되 last-wins 의미를 명시 문구로 보존하는 등 — 구현 세부는 developer 판단. 다른 persona hook(SubagentStart)도 같은 구조면 함께.

## Acceptance

- With an oversized discipline payload, the overrides content still reaches the model's visible context (not lost to persist-truncation) — demonstrated with a realistic-size fixture.
- Last-wins semantics preserved and explicit.
- Machines without overrides files behave unchanged; both SessionStart and SubagentStart paths covered if they share the pattern.
- Covered by tests.

## Outcome

**Investigation (protocol question first)**: does a hook event with multiple registered
hook commands persist-truncate each command's `additionalContext` independently, or does
the harness concatenate them first? No authoritative doc answer (claude-code-guide agent
found only the ~10K-char / 2KB-preview persist threshold documented; multi-hook
concatenation behavior is not documented). Settled it **empirically, live, in-session**:
this very developer dispatch's own SubagentStart hook context showed the prdt hook's
~17KB output persisted-and-previewed (2KB preview) while a co-registered, unrelated small
hook (`vercel-plugin:subagent-bootstrap`) rendered in full, un-truncated, in the same
turn. That proves per-hook independent persist-checking — option (a) is viable, not just
a fallback.

**Fix (option a, as directed)**: new dedicated hook `prdt-overrides-inject.sh` — reads
the same event JSON (`agent_type`), resolves persona, and if
`~/.prdt/overrides/<persona>.md` exists, emits ONLY that content (wrapped in an explicit
"LAST-WINS — takes priority over everything in the main injection" framing) as its own
`hookSpecificOutput.additionalContext`. Registered as a **second, distinct hook command**
under the same matcher blocks `prdt-session-start.sh` already uses — `SessionStart`
(`startup|resume|clear`) and `SubagentStart` (`^prdt-`) — via `install.sh`. Removed the
overrides block from `prdt-session-start.sh`'s own payload (no more duplication); its
header/intro text now points at the separate hook and states last-wins semantics
explicitly. Overrides-absent machines: the new hook exits with zero stdout (no JSON at
all) — byte-identical to before, since the old inline block was already a no-op for
missing files.

**Real-world verification** (actual `~/.prdt`, prdt-po persona, not a fixture):
- Main hook payload: 17,938 bytes (matches the ~16.6KB incident scale) — contains
  `SETTINGS`-BEGIN-overrides` count of 0, override body text count of 0. No duplication,
  no dependency on the override text.
- Overrides hook payload: 955 bytes, contains the full override body verbatim
  (`션님`, 개조식 rule, commit-gate rule) — comfortably under the ~10KB/2KB-preview
  threshold regardless of how large the main payload grows.

**Tests** (`packages/core/test/scripts/`, both run against the real scripts, sandboxed
HOME/PRDT_HOME/CLAUDE_DIR per repo convention):
- `overrides-inject-hook.test.ts` — overrides-absent machines emit nothing (both hooks);
  override-present machines get the LAST-WINS block with the body verbatim from the
  dedicated hook, and the main hook no longer duplicates it; a realistic oversized fixture
  (~18KB doctrine+contracts+habit, incident-scale) proves the overrides hook output stays
  small (<2000 bytes) and independent while the main payload alone exceeds 12,000 bytes.
- `install-overrides-hook.test.ts` — `install.sh` mirrors the new script as executable;
  registers it as a distinct entry (not merged) alongside `prdt-session-start.sh` under
  both the `SessionStart` and `SubagentStart` matcher blocks; idempotent on re-run (no
  duplicate entries).
- Full suite: `packages/core/test` — 14 files / 73 tests pass; `schema-v-guard.mjs` passes.
