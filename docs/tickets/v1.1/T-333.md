## Request

**GUI 이슈**: 도구 실행 표시가 raw command 그대로 노출 — 기획자가 못 읽음.

- 현재 Bash 실행 중 표시가 `echo "--- po-state ---"; cat .prdt/po-st… 실행 중`처럼 raw command를 그대로 보여줌. echo/cat/grep 같은 건 비개발자(기획자)가 봐도 의미를 모름.
- 반면 Agent 위임("Designer에게 위임 중")은 사람이 읽는 필드를 렌더해서 잘 읽힘 — Bash만 raw로 새는 구조.
- 수정 방향 (Define/설계에서 상세화):
  - (a) **GUI**: Bash tool call에 이미 포함된 `description` 필드를 1차 표시로 사용 — "스크립트 작성 중: po-state 확인" 식. raw command는 펼치기/호버로 강등.
  - (b) **i18n**: description이 영어로 생성되는 경우가 많음 → discipline에 description을 `user_lang`으로 쓰도록 한 줄 추가, 그리고/또는 description 부재·영어 시 GUI-side 흔한 명령 fallback 매핑(cat/echo/grep/git → "파일 확인 중 / 검색 중 / 변경 이력 확인 중" 등).

## Acceptance

- (Define/설계 시 상세화) GUI에서 Bash 실행 표시가 raw command 대신 사람이 읽을 수 있는 설명으로 나온다 (user_lang 기준).
- description이 없거나 매핑 불가한 명령도 에러 없이 합리적 fallback으로 표시됨.
- raw command는 여전히 확인 가능(펼치기/호버 등) — 개발자 디버깅 경로 유지.

## Outcome

Bash 실행 중 라인이 raw command 대신 사람이 읽는 설명으로 나오도록 고침. 우선순위: (1) Bash tool call의 `description` 필드가 있고 GUI 언어와 맞으면 그대로 표시 (2) 아니면 명령어 첫 단어 기반 GUI-side fallback 매핑(cat/echo/grep/git/ls/npm 등 10개 버킷)으로 표시 (3) 매핑 안 되는 명령도 "명령 실행 중" 제네릭으로 표시 — 에러·raw 노출 없음. raw command는 활동 라인에 마우스 호버 시 title 툴팁으로 계속 확인 가능(개발자 디버깅 경로 유지); 히스토리 쪽 `ToolUseGroup` 펼치기 상세는 기존에 이미 raw command + description을 보여주고 있어 별도 변경 불필요.

- (a) GUI: `packages/gui/src/components/workspace/chat/bashActivity.ts` 신설 — `descriptionUsable`(언어 불일치 휴리스틱, 한글 포함 여부로 판정) · `bashFallbackBucket`(첫 단어 → 버킷) · `rawBashCommand`(호버용 원문 추출) 순수 함수로 분리, `bashActivity.test.ts`로 케이스 테이블 커버(언어 판정 5케이스 + 매핑 9케이스 + 원문 추출). `ChatPanel.tsx`의 `humanizePoTool` Bash 분기 + `PoActivityLine`이 이를 사용하도록 교체, 기존 raw-command 표시(`activity.bash` 키)는 제거.
- (b) i18n: `packages/core/discipline/contracts.md` `## Language`에 한 줄 추가 — GUI가 활동 라벨로 노출하는 tool-call `description`도 `user_lang`을 따르라는 규칙(T-333 참조). GUI-side fallback으로 `workspace.chat.activity.bashDesc` / `bashFallback.{cat,echo,grep,git,ls,prep,run,net,data,generic}` 키를 en/ko 양쪽에 추가.
- 검증: `pnpm exec vitest run`(20 files/36 tests 전부 통과, 신규 3개 포함) · `pnpm exec tsc --noEmit`(clean) · `node scripts/check-locale-keys.js`(en/ko 952 키 동일, 사용 키 전부 해석) · `bash scripts/check-locale-protected.sh`(위반 없음) 모두 통과.
