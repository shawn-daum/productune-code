## Request

**버그/갭 리포트 (shawn, 2026-07-14, 스크린샷 — dogfooding)**: Designer가 디자인 방향 3안(HTML mockup a/b/c)을 `docs/artifacts/`에 쓰고 PO가 채팅에 `file:///...` 경로 목록으로 안내했는데:

1. **file:// 링크에 interaction이 없음** — 클릭 불가, 그냥 텍스트.
2. **턴 끝났을 때 자동으로 띄워주지 않음** — PRD처럼 turn-end에 artifact 패널로 자동 표시되길 기대. T-328이 design HTML artifact 자동표시를 넣었는데 이 케이스(복수 artifact, 워커 산출)는 트리거되지 않음.

- 진단 포인트: T-328의 surfacing 감지가 왜 이 경우를 놓쳤는지 (복수 파일? 워커 files_written 경유? 감지 패턴?) — `useSurfacedArtifacts` 및 관련 감지 경로 확인.
- 기대 동작: PO 턴 종료 시 그 턴에서 생긴 `docs/artifacts/*.html`이 (복수면 복수 모두 — 탭/목록 등 설계 판단) 자동 표시. 채팅 내 file:// 경로도 클릭하면 열리게.

## Acceptance

- When a PO turn (including worker-produced files during that turn) results in new/updated `docs/artifacts/*.html`, they auto-surface at turn end like the PRD panel — multiple artifacts are all reachable (tabs/list, design judgment).
- file:// links to project artifacts rendered in chat are clickable and open the artifact (in-app viewer or OS default, design judgment — no dead text).
- Existing T-328 single-artifact auto-display and PRD surfacing behavior unregressed.

## Outcome

**진단 (T-328이 이 케이스를 놓친 이유)**: `useSurfacedArtifacts`(T-PATCH-079, ticket-gated)는 무관 — 그 경로는 `requires_user_gate:true && status==='user-verify'`인 티켓 소속 아티팩트에만 반응하고, 게다가 `artifacts:reload` 이벤트는 사이드바 새로고침 버튼 수동 클릭으로만 발화해 turn-end 자동 트리거 자체가 없다. 실제로 동작하는 경로는 T-328의 `po:artifact-open`(main `po-runner.ts` → renderer `useIpcSubscriptions`)인데, 이건 **PO 자신의 턴 종료 텍스트에서 JSON envelope(`files_written[]`/`changed_files[]`)를 파싱**해야만 열린다(`parseArtifactFiles`). 이번 세션은 Designer(워커)가 파일을 쓰고, PO는 그 결과를 구조화 envelope 없이 `file:///...` 평문 목록으로만 안내했다 — 그래서 감지 자체가 트리거되지 않았다(복수/워커 여부는 무관, "envelope 미포함 prose" 가 근본 원인). 부가로 `linkifyText.ts`의 `file://` 처리는 T-PATCH-106 이후에도 `.productune/<persona>/*.md` doctrine 경로 전용이라 `docs/artifacts/*.html` 같은 일반 file:// 링크는 애초에 linkify되지 않아 클릭도 불가했다(리포트 증상 1과 일치). 그리고 설령 명시적 markdown 링크로 클릭 가능했더라도 `MdRenderer.routeLink`의 `ptn:file/` 분기가 확장자 무관하게 항상 `markdown` 뷰어로 열어, `.html`이 raw 텍스트로 보였을 것(잠재 결함, 이번에 같이 수정).

**수정**:
1. `packages/gui/electron/po-runner.ts` — `parseArtifactFiles`를 envelope 파싱(기존 동작 100% 보존)과 새 prose fallback(`parseArtifactMentions`)으로 분리·병합. Fallback은 `docs/artifacts/*.html`을 상대경로/`file://` 절대경로 어느 형태로 언급하든(콤마·개행 나열 포함) 정확히 추출해 dedupe 후 병합 — PO가 envelope 없이 평문으로만 안내해도 기존 `po:artifact-open`→`useIpcSubscriptions` 파이프라인(브라우저 탭, `ARTIFACT_OPEN_CAP=3`)이 그대로 동작한다. `docs/artifacts/` 바깥 파일 언급은 스윕하지 않도록 스코프 한정.
2. `packages/gui/src/lib/linkifyText.ts` — alt-5(옛 "absDoctrine")를 임의의 `file://` URI 전체로 넓혀(문서 doctrine 전용에서 확장) `docs/artifacts/*.html`을 포함한 모든 file:// 링크가 clickable해지도록 함(순수 bare `/…` 절대경로는 오탐 방지를 위해 doctrine 시그널 요구 유지). alt-4에 `docs/artifacts/*.html` 상대경로 언급도 추가(다른 루트/확장자로는 확대하지 않음). 콤마/문장부호가 나열 시 href에 섞여 들어가는 것을 막는 trailing-punctuation trim 추가(bareUrl 분기와 동일 패턴).
3. `packages/gui/src/components/workspace/chat/MdRenderer.tsx` — `routeAbsPath`/`routeLink`에 `.html` 분기 추가: doctrine 분류 다음, in-project-markdown-fallback 이전에 위치시켜 `docs/artifacts/*.html`을 `file://` browser 미리보기 탭으로 열도록 함(기존에는 markdown 텍스트 뷰어로 잘못 열렸음). tabId가 T-328/QuickOpen의 기존 `browser:${url}` 규약과 동일해 auto-surface가 이미 연 탭과 dedupe-focus됨(중복 탭 없음).

**복수 아티팩트 도달성**: 새 별도 패널/탭 UI는 만들지 않음 — 기존 워크스페이스 탭 스트립이 이미 여러 브라우저 탭을 동시에 보여주고 전환 가능하므로, 3개 mockup이 각각 독립 탭으로 열리는 것으로 "모두 도달 가능" 요건을 충족(YAGNI). `ARTIFACT_OPEN_CAP=3`는 기존 정책 그대로 유지 — 이번 리포트 시나리오(정확히 3개)는 캡 경계 안에 들어와 toast 없이 전부 열림; 4개 이상일 때의 캡 정책 재설계는 이번 스코프 밖(디자인 판단으로 보류).

**회귀 확인**: `parseArtifactFiles`의 envelope-only 4개 기존 테스트 케이스는 변경 없이 그대로 통과(순서·배열 동일성 유지); `linkifyText` 기존 doctrine/티켓/https 케이스도 무회귀. `helpers.artifactOpenType`·`browserUrl`(T-328) 관련 파일은 손대지 않음.

### QA FAIL 재작업 (2026-07-14)

**QA 발견 결함**: auto-surface/unit/build는 PASS였으나 채팅 링크 클릭이 라이브에서 전부 무반응. 원인 — `MdRenderer`가 `<ReactMarkdown>`에 `urlTransform`을 넘기지 않아 react-markdown 9.1.0의 `defaultUrlTransform` 스킴 화이트리스트(http/https/mailto 등)가 `ptn:ticket/`·`ptn:file/`·`ptn:doctrine/` **그리고 bare `file://`** href를 전부 빈 문자열로 sanitize → `MdLink`의 `if (href)` 가드가 클릭을 조용히 무시. T-345가 넓힌 링크만이 아니라 기존 doctrine/티켓 ptn: 링크까지 앱 전역이 원래부터 죽은 링크였음(잠복 결함이 이번 기능으로 표면화). 이전 unit 테스트가 이를 못 잡은 이유: `linkifyText`(문자열 전처리)까지만 검증하고 ReactMarkdown 렌더 경로(sanitize 단계)는 커버하지 않았음.

**수정**:
1. `packages/gui/src/components/workspace/chat/mdUrlTransform.ts`(신규) — 순수 transform: `ptn:`/`file:` 스킴(case-insensitive)은 무변환 통과(둘 다 `MdLink`가 preventDefault 후 내부 라우팅만 하므로 네이티브 내비게이션 없음), 그 외 전부 react-markdown이 export하는 `defaultUrlTransform`에 위임 — `javascript:`/`data:` sanitize 자세는 라이브러리 기본과 동일(전면 허용 금지 준수). `file:` 통과는 QA 제안(ptn:만)보다 한 스킴 넓힌 판단 — linkify가 verbatim 보존하는 명시적 `[text](file:///…)` md 링크는 href가 raw `file://`라서 ptn:만 통과시키면 여전히 죽은 링크로 남음(acceptance "file:// links … clickable" 직결).
2. `MdRenderer.tsx` — `<ReactMarkdown urlTransform={mdUrlTransform}>` 배선.

**검증 (TDD + 결함 재현 증명)**:
- `mdUrlTransform.test.ts`(신규, 11케이스): ptn:×3/file:// 통과, https/mailto/상대경로/fragment 무회귀, `javascript:`·`data:`·case-tricked `JavaScript:` 전부 sanitize 유지 — 모듈 부재 상태 RED 확인 후 구현 GREEN.
- `MdRenderer.href.test.tsx`(신규): **실제 렌더 DOM 검증** — `react-dom/server.renderToStaticMarkup`으로 진짜 MdRenderer를 렌더해 `linkifyText → ReactMarkdown → urlTransform → <a href>` 전 구간에서 href 생존을 단언(6케이스: file:// prose·티켓·상대경로·doctrine·명시적 file:// md링크·https) + `javascript:` href 미생존 XSS 고정 테스트. 신규 dep 없이 node env에서 동작(MdRenderer는 렌더 중 store 미접근).
- **결함 재현**: `urlTransform={mdUrlTransform}` 배선을 임시 제거하고 위 렌더 테스트 실행 → FAIL 확인(QA 발견 결함을 정확히 잡음) 후 복원 → GREEN. 이 테스트가 향후 동일 회귀를 고정함.
