## Request

**QA 격리 인프라 (shawn 요청, 2026-07-15, 이 기기 한정)**: QA 라이브 검증이 사용자 작업과 겹침 — 창 포커스 탈취, System Events 키 이벤트가 사용자 앱으로 누출(T-354 QA에서 실제 발생: 키 w/n/j 누출 + 입력소스 ~2분 한글 전환), IME 입력소스 변경 등. **CUA VM으로 QA를 옮겨 화면·포커스·IME를 호스트와 분리**하려는 것.

- 현황: cua-vm MCP 서버는 등록돼 있으나 프로브 시 연결 불가 (`192.168.64.16:8443` 접속 실패) — VM이 꺼져 있거나 네트워크 미구성.
- 필요 작업 (설계 판단):
  1. VM 기동 경로 확인/문서화 (사용자 확인 필요할 수 있음).
  2. VM 내 검증 환경: repo 접근(클론 or 공유폴더), node/pnpm/expect, GUI 빌드 가능 여부, claude CLI 필요 시 인증 방안.
  3. QA discipline 반영: 포커스/키 이벤트/IME/입력소스를 만지는 검증은 VM 필수, 그 외 로컬 격리 인스턴스 허용 — wiki fact(`fact--gui-testing-env.md`) 갱신 + QA playbook 한 줄.
  4. 중간 완화(즉시): System Events 주입 전 frontmost 체크 게이트 (T-354 QA memory note 반영).

## Acceptance

- A documented, repeatable path for QA agents to run focus/IME-class GUI verification inside the CUA VM on this machine, with zero input/focus leakage to the host (demonstrated once end-to-end).
- Verification classes that stay local vs go to VM are written down where QA discipline reads them.
- Immediate mitigation (frontmost gate before synthetic key injection) in place for local runs.
