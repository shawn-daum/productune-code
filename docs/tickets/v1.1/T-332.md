## Request

**CLI 이슈**: install 프롬프트 미화 — 화살표 키 선택 UI.

- 현재 install 프롬프트는 평문 입력(Python `input()` / bash `read`)을 사용함.
- 수정 방향: **gum/fzf**를 통한 화살표 키 선택 UI로 전환. gum/fzf가 설치되지 않은 환경을 위해 **현재의 텍스트 입력 경로로 graceful fallback**을 반드시 포함.

## Acceptance

- gum/fzf가 있는 환경에서 install 프롬프트가 화살표 키 선택 UI로 동작한다.
- gum/fzf가 없는 환경에서 기존 텍스트 입력(`input()` / `read`) 경로로 정상 fallback 한다 (설치 실패/에러 없음).
- 두 경로 모두에서 동일한 설정 값이 수집됨을 확인.

## Outcome

- 2026-07-09: 사용자 캡처(CLI 기능). 다음 버전으로 이월(백로그) — 이번 버전 스코프 아님, 버전 미배정.

## Scope addition (2026-07-14, shawn)

## Outcome — rework (2026-07-14, dev): 블라인드 메뉴 버그 수정

실사용 리포트(실터미널에서 화살표 UI 미표시, 키 입력은 먹힘) 재작업. PO 진단이 정확했음.

- **원인**: `select_choice()`의 `subprocess.run(..., capture_output=True)`가 stderr까지 파이프로 캡처 — gum은 메뉴 UI를 **stderr**에 그리고 stdout으로는 선택 결과만 내보내므로, 메뉴가 화면에 전혀 도달하지 못하는 "블라인드 메뉴"가 됨(키 입력은 정상 처리). fzf는 /dev/tty에 직접 그려서 무관했지만, 이 머신엔 gum·fzf 둘 다 설치돼 있어 gum이 우선 실행 → 사용자 증상과 일치.
- **수정**: `capture_output=True` → `stdout=subprocess.PIPE`(stderr는 tty 상속). gum·fzf 두 호출 모두 적용, 소스 주석으로 이유 고정.
- **기존 테스트가 통과시킨 이유(2중 결함)**: ① expect의 bare `expect "패턴"`은 timeout 시 조용히 다음 커맨드로 진행 — 화살표+엔터를 블라인드로 보내도 (안 보이는) 메뉴가 키를 먹어 결과값은 정상 수집됨. ② fzf 케이스들은 PATH 미격리로 실제론 gum이 실행되고 있었음(gum 우선순위) — fzf 경로는 검증된 적이 없었음.
- **테스트 보강** (`prdt-init-version-select.test.ts` 재작성):
  - 모든 expect 매치를 `mustSee()`(timeout 시 exit 1) 블록으로 전환 — silent fall-through 제거.
  - **UI 가시성 assert**: 키 전송 전에 메뉴 전용 라벨 `"validate an idea (default)"`(print 인트로 문구 "validating an idea"와 구분됨)가 pty에 실제 렌더되는지 강제. 버그 코드에 red 확인 완료 — `capture_output` 재주입 후 gum 케이스 1 failed, 수정 코드 복원 후 green.
  - PATH 격리를 `pathWithOnly(sandbox, bins[])`로 일반화: fallback=python3만 · fzf 케이스=python3+fzf(gum 제외) · gum 케이스=python3+gum+fzf(우선순위 실증).
- **검증**: 대상 테스트 4/4 green (2.3s — 기존 32s는 blind timeout 10s×3 소비의 방증) · 전체 core 스위트 63 vitest + schema-v-guard 2 green · tsc(build) clean · `py_compile` clean.
