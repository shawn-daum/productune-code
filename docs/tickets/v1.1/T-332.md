## Request

**CLI 이슈**: install 프롬프트 미화 — 화살표 키 선택 UI.

- 현재 install 프롬프트는 평문 입력(Python `input()` / bash `read`)을 사용함.
- 수정 방향: **gum/fzf**를 통한 화살표 키 선택 UI로 전환. gum/fzf가 설치되지 않은 환경을 위해 **현재의 텍스트 입력 경로로 graceful fallback**을 반드시 포함.

## Acceptance

- gum/fzf가 있는 환경에서 install 프롬프트가 화살표 키 선택 UI로 동작한다.
- gum/fzf가 없는 환경에서 기존 텍스트 입력(`input()` / `read`) 경로로 정상 fallback 한다 (설치 실패/에러 없음).
- 두 경로 모두에서 동일한 설정 값이 수집됨을 확인.

## Outcome

- 2026-07-09: 사용자 캡처(CLI 기능). 다음 버전으로 이월(백로그) — 이번 버전 스코프 아님, 버전 미배정.

## Scope addition (2026-07-14, shawn)

`prdt init`의 인터랙티브 프롬프트(특히 first version v0.1/v1 선택)도 동일하게 화살표 키 선택 UI 적용. install.sh 프롬프트와 같은 원칙: gum/fzf 있으면 화살표 선택, 없으면 기존 텍스트 입력 graceful fallback.

## Outcome (2026-07-14, dev)

- **install.sh**: 검증 결과 install.sh(및 `prdt-flip.sh`/`uninstall.sh`/`prdt-install.sh` 포워더)에는 현재 selection-type 인터랙티브 프롬프트가 없음 (`grep -n "read -p\|read -r\|input(\|select "` — 0 hits). 모든 동작이 CLI 플래그(`--statusline`/`--no-statusline`)와 기본값으로만 분기되어 변환 대상이 없었음 — 억지로 프롬프트를 신설하지 않음(YAGNI). `select_choice()` 헬퍼는 install.sh에서도 그대로 재사용 가능한 형태로 작성해둠(향후 프롬프트 추가 시 대비).
- **prdt init**: `packages/core/scripts/prdt`에 `select_choice(options, header)` 공용 헬퍼 추가 — `gum choose`(우선) → `fzf`(차순위) → 둘 다 없으면 `None` 반환(호출부가 기존 `input()` 경로로 fallback). first-version 프롬프트(`prompt_version()`)를 이 헬퍼로 교체: 옵션 3개(v0.1 / v1 / "other — type a version manually"), "other" 선택 시 기존 텍스트 입력으로 위임 — 세 경로 모두 동일한 값 형태(`v0.1`/`v1`/자유 텍스트)를 수집.
- slug 프롬프트는 지시대로 텍스트 입력 그대로 유지(free-text는 스코프 아님).
- **검증(doctrine #4, T-331 pty 제약 대응)**: `sys.stdin.isatty()` 분기라 파이프 stdin으로는 도달 불가 — macOS `expect`로 real pty 구동해 4가지 케이스를 실제 `prdt init` CLI end-to-end로 확인 (수동 1회 + 회귀 테스트 `packages/core/test/scripts/prdt-init-version-select.test.ts` 4건 모두 green):

  2. fzf만 있을 때 → 화살표 아래+Enter로 `v1` 선택.
  3. fzf "other" 선택 → 텍스트 프롬프트로 위임, 커스텀 값(`v2.custom`) 수집.
