## Acceptance

### A. state 감지 logic (po-runner.ts 보강)

- [ ] `packages/gui/electron/po-runner.ts` 에 `inferHealth(line, ctx)` 함수 추가. ctx = `{ lastToolUse, lastToolUseAt, lastEmittedState, msgId }`.
- [ ] design doc §7.2 의 9 row 매핑 모두 구현:
  - [ ] `result.subtype === 'error'` → `error-other`.
  - [ ] stderr `/rate.?limit/i || /quota/i` → `rate-limited`. parser 시도: `/resets? at ([0-9:T+\-Z]+)/i` → `detail.resetAt`. 실패 시 unset.
  - [ ] stderr `/(permission|denied|deny)/i` AND lastToolUse ∈ {Write, Edit, Bash} → `permission-blocked`.
  - [ ] assistant text `/^I (need|require) (your )?permission/i` AND tool_use 직전 → `permission-blocked`.
  - [ ] tool_use {Write, Edit, Bash} 직후 30s 내 result 없음 → provisional `permission-blocked`. 60s 도 없으면 confirmed (state 동일, dedupe).
  - [ ] envelope `compact` flag 또는 `subtype === 'compact_pre'` → `compacting`. (실측 후 §7.2 OQ close)
  - [ ] tool_use `name === 'Task'` → `delegating`. `subagent_type` 추출 → `detail.persona`.
  - [ ] child `error` event 또는 `close` non-zero non-null AND no other state set → `error-other`. errorMessage 채움.
  - [ ] healthy 복귀: result 정상 수신 시 emit `healthy` (현재 state 가 healthy 가 아닐 때만).
- [ ] dedupe — 동일 state 연속 emit 시 skip (in-process `lastEmittedState` 비교).
- [ ] `RunCallbacks` 에 `onHealth: (event: PoHealthEvent) => void` 추가.
- [ ] `emitToWebContents` 에 `po:onHealth` 채널 한 줄.
- [ ] echoFallback 도 healthy emit 1 회 (start) + healthy emit (end).

### B. UI surface

- [ ] color/icon 매핑 design doc §5.4 대로:

- [ ] Sticky `<SessionHealthBanner />` — severity == error (permission-blocked, error-other) 시만 mount. 36px height, slide-down 120ms, border-left 3px health-error, dismissible.
- [ ] `<FabPoChat />` health dot — chat 접힘 시 우상단 부착. info/warn/error 별 색상 + error 만 subtle blink (1s, opacity 1↔0.4).

### C. CTA 동작

- [ ] **Restart session** (`permission-blocked.cta`) → `<RestartSessionModal />` 열림. 본문 design doc §6.1.
  - [ ] Restart now → `window.api.po.restartSession()` IPC → main 에서 capturedSessionId reset + 활성 child kill (있으면) → renderer sessionId state null 로 reset → 다음 send 가 `--agent` 첫 turn.
  - [ ] Open settings ↗ → Settings 탭 navigate (T-P4-058 land 후 Workspace/Permissions sub-tab 진입).
  - [ ] Cancel → modal 닫힘, banner 유지.
- [ ] **Retry** (`error-other.cta`) → chat.json last user role message 를 `runPoTurn` 에 재투입. resume sessionId 유지.
- [ ] **View log ↗** (`error-other.logCta`) → T-P4-046 dispatcher 의 `terminal` tab open. T-P4-046 미 land 시 fallback: 모달로 stderr 마지막 N 줄 dump (in-memory buffer).

## Test scenarios (QA, light — 6 시나리오)

1. **healthy** — claude 정상 응답. StatusBar segment 안 보이거나 minimal dot. banner X. FAB badge X.
2. **delegating** — PO 가 designer Task 호출. StatusBar segment "Delegating to designer…" + spin. banner X.
3. **rate-limited (with reset)** — stderr 에 `rate limit, resets at 14:32` 주입 (mock). StatusBar warn icon + "Resets at 14:32". CTA X.
4. **permission-blocked (Write deny)** — Write tool_use 후 stderr `permission denied`. StatusBar error + Sticky banner 등장. Restart modal CTA → 클릭 → restartSession IPC 호출 → 다음 send 가 새 sessionId 로 시작 검증.
5. **compacting** — 30s 동안 token 무이벤트 + tool_use X 시 heuristic 으로 compacting 진입 (envelope 명시 못 받으면). 정상 응답 재개 시 healthy 복귀.
6. **error-other (spawn fail)** — claude 바이너리 mock 으로 spawn error 발생. StatusBar + banner 등장. Retry CTA → 동일 user 메시지 재전송 → 정상이면 healthy.

각 시나리오 i18n 토글 (EN ↔ KO) 1회 — 보호어 영문 유지 확인.

## Out of scope

- rate-limit 의 정확한 reset 시각 추출 (claude CLI 가 metadata 로 안 주면 unknown 표시) — best-effort regex 만.
- token usage meter / 사용량 그래프 — 별도 ticket.
- auto compact 의 정확한 진행률 (claude CLI 가 progress emit 안 함) — heuristic spinner 만.
- 페르소나 (designer/dev/qa) 의 health — PO session 만. 페르소나 health 는 PO 가 자연어로 통보.
- session crash 후 chat history 재 streaming / replay — T-P4-041 chat.json 영속화의 후속.
- 다중 health state 동시 표시 — priority cascade 1 개만.
- "백그라운드 대기" 토글 (rate-limit 시 자동 재전송) — Phase 5 후속.
- 모바일 / 좁은 viewport 의 banner 레이아웃 — Phase 4 desktop-first.

## Notes

**왜 신규 ticket** : T-P4-041 (PO Chat 본체) 은 streaming 본체. 본 ticket 은 그 위 health surface — scope 분리. T-P4-049 (persona presence bar) 는 페르소나 활동 표시이며, PO session 자체의 health 는 별 surface (StatusBar / banner) — 두 개념 합치면 칩 의미가 흐려진다.

**T-P4-058 과의 관계** : T-P4-058 은 root-cause fix (settings hygiene → 권한 deny 자체 차단). T-P4-059 는 root-cause 가 fix 되어도 발생하는 **다른 health 상태들** (rate / compact / delegate / spawn) 까지 cover + 그래도 발생할 권한 deny 의 visibility + restart escape hatch. 두 ticket 은 보완 관계.

**왜 banner 는 error 만** : info/warn 은 자연 해소 가능 (delegating/compacting 은 시간 / rate-limited 은 wait). error 는 사용자 액션 필수 → 화면 차단 정당화. banner 피로 회피.

**감지 logic 의 미확정 부분** : design doc §9 OQ 5 — claude CLI 의 envelope 패턴 (compact 명시? rate-limit reset 포맷?) 이 dev 단계에서 실측되어야 row 갱신. impl 단계에서 OQ close 후 design doc 보강 (Activity log 한 줄).

**번호 충돌 회피** : 사용 중 = 040~049 (R4 main + 049 presence bar), 051 (R5 mermaid stub), 055 (R5 hi-fi stub), 056 (i18n), 057 (locale linter), 058 (init hygiene). 다음 빈 번호 059 채택.
