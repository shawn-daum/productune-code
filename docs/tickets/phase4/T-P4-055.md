# T-P4-055: High-fidelity UI mockup preview — Build 전 현실감 있는 화면 예시 승인

**Round**: phase4-r5  **Stage**: design  **Status**: todo  **Assignee**: pdt-designer
**PRD anchor**: [docs/prd/productune.md#phase-4--개발-비숙련-기획자-모드-planner-mode-future](../../prd/productune.md#phase-4--개발-비숙련-기획자-모드-planner-mode-future)
**Estimated complexity**: L4  **Risk flags**: ux, ai-preview, expectation-management

> 사용자가 Excalidraw/wireframe 만으로는 실제 제품 느낌을 판단하기 어렵다. Build 전에 Designer 가 현실감 있는 예시 화면 mockup preview 를 함께 보여주고, 사용자가 시각 방향에 동의한 뒤 구현으로 넘어가게 한다.

## Request

Design stage 산출물에 **high-fidelity example screen mockup / generated image preview** 타입을 추가한다. Designer 는 PRD/design docs, Mermaid flow, Excalidraw seed 와 함께 현실감 있는 UI mockup preview 를 생성/첨부한다. 사용자는 이 preview 를 보고 “이 느낌으로 진행” 또는 수정 요청을 결정한 뒤 Build stage 로 넘어간다.

## Acceptance

- [ ] Design stage artifact taxonomy 에 `high_fidelity_mockup_preview` 또는 동등 타입이 추가됨
- [ ] Designer flow 가 PRD/design docs + Mermaid + Excalidraw seed + realistic UI mockup preview 를 함께 생성하도록 명시됨
- [ ] 사용자 승인 flow 에 mockup preview 검토가 포함되고, 승인 전 Build stage 진입을 막을 수 있음
- [ ] mockup preview 는 **visual agreement only** 로 표시됨
- [ ] source of truth 는 markdown / Mermaid / Excalidraw / design system 으로 유지됨
- [ ] 생성 이미지 preview 는 non-canonical artifact/cache 로 취급됨
- [ ] UI copy 또는 help text 가 “이미지는 정확한 텍스트/픽셀/최종 구현 보장 아님”을 명확히 안내함
- [ ] preview asset 저장 위치 후보가 정의됨: 초기 `docs/design/<slug>/mockups/` 또는 후속 GUI viewer cache
- [ ] 이미지 생성 실패/미지원 시에도 Mermaid/Excalidraw/design docs 만으로 디자인 승인을 계속할 수 있음
