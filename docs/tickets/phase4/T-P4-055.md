# T-P4-055: High-fidelity mockup preview — PreviewTab 디자인 스펙

**Round**: phase4-r4  **Stage**: design  **Status**: todo  **Assignee**: pdt-designer  
**Design ref**: [docs/design/design-direction.md §4.3.2](../../design/design-direction.md)  
**Estimated complexity**: L3  **Risk flags**: electron-webview, path-resolution

> 4종 디자인 산출물(`system.md` / `flow.md` / `screens/*.excalidraw.json` / `mockups/*.html`) 중 **mockup HTML** 의 main-pane viewer 스펙.  
> T-P4-046 dispatcher 에서 `preview` tab type 은 현재 `PlaceholderTab` — 본 ticket 이 실제 `PreviewTab` 컴포넌트 디자인 스펙을 정의하고, 그 결과를 impl ticket 에 전달한다.

---

## §1 Background

`design-direction §4.3.2` 에 따르면 `preview` tab type 은 `prev-chrome (URL bar + Local/Vercel toggle) + prev-body (iframe placeholder)` 로 명시됐으나, T-P4-046 구현 범위에서 `prev-body` 는 `PlaceholderTab` 으로 처리됐다.

한편 Designer 가 emit 하는 4종 산출물 중 `docs/design/<slug>/mockups/*.html` (hi-fi mockup HTML) 은 현재 **GUI 에서 열람 수단이 없다**. 설계 리뷰 / 사용자 승인 flow (T-P4-054 경로) 에서 mockup HTML 을 main-pane 에서 바로 볼 수 있어야 한다.

따라서 `preview` tab type 의 실체를 **mockup HTML renderer** 로 재정의한다. Local/Vercel live URL 렌더링은 `browser` tab type 으로 이미 커버되므로 중복 없음.

## §2 Scope

### A. PreviewTab 래퍼 — `PreviewTab.tsx`

| 영역 | 역할 |
|---|---|
| `prev-toolbar` (36px) | 파일 picker 드롭다운 + zoom controls + 오른쪽: mapping-ref 토글 버튼 |
| `prev-body` (flex 1) | mockup HTML 렌더 영역 (iframe / Electron `<webview>`) |
| `prev-mapping` (선택적 우측 패널 280px) | mockup → code 매핑 참조 표. 기본 collapsed. |

레이아웃: `flex-col` 전체 높이. `prev-toolbar` 고정, `prev-body` flex-grow. `prev-mapping` 은 토글 시 right side-by-side 분리 (`flex-row`).

### B. Mockup file source 해석 순서

렌더링 대상 파일 경로 해석 우선순위:

```
1. props.mockupPath  (openTab() 호출 시 명시적 경로 — 우선)
2. docs/design/productune/mockups/*.html  (default slug = "productune")
3. docs/design/<activeSlug>/mockups/*.html  (active ticket slug 기반)
```

- 해석 실패 또는 파일 없음 → `EmptyState` 컴포넌트:  
  icon `FileImage` (lucide), headline `"mockup 파일이 없습니다"`, description `"docs/design/<slug>/mockups/ 경로에 HTML 파일을 추가하세요."`, CTA `"Explorer 열기"` (ghost sm).

### C. Mockup file picker

```
┌─ prev-toolbar ────────────────────────────────────────────────────┐
│ [FileImage 16] [dropdown: mockup.html ▼]  [–] [100%] [+] [⊡ fit] │ [□ mapping]
└────────────────────────────────────────────────────────────────────┘
```

- 드롭다운 = `Select` (shadcn 패턴, `body-sm` 14px). 항목: `<filename>.html` 목록 (알파벳 정렬).  
- 파일 변경 → iframe/webview `src` 교체. 전환 중 `prev-body` 에 `Loader2 pdt-spin` (center) 노출, 로드 완료 시 숨김.  
- 파일 0개 → picker 비활성 + `EmptyState` 노출.

### D. Zoom / Fit-to-window controls

| 컨트롤 | 동작 | 시각 |
|---|---|---|
| `–` (ZoomOut) | 10% 단위 축소. 최소 25% | `ghost sm` 버튼, lucide `ZoomOut` 16px |
| zoom level label | `50%` / `75%` / `100%` / `150%` / `200%` — 클릭 시 100% 즉시 복귀 | `caption` 13px `code` 폰트, min-width 40px, text-center |
| `+` (ZoomIn) | 10% 단위 확대. 최대 200% | `ghost sm` 버튼, lucide `ZoomIn` 16px |
| `⊡` (fit) | `scale` 재계산 — `min(containerW / iframeW, containerH / iframeH)` | `ghost sm` 버튼, lucide `Maximize2` 16px. active 시 `primary-500` tint |

zoom 구현: iframe `transform: scale(Z)` + `transform-origin: top left`. `prev-body` overflow hidden. container resize 시 `fit` 상태면 자동 재계산 (`ResizeObserver`).

### E. Mockup → code 매핑 참조 표

`prev-mapping` 패널 토글 버튼: `ghost sm`, lucide `Table2` 16px, 라벨 `"매핑"`. active 시 `primary-500` tint.

패널 내부:
```
┌─ prev-mapping 280px ──────────────────────┐
│ "Mockup → Component 매핑"  title-3 600    │
│ ─────────────────────────────────────      │
│ HTML element ID     Component name         │
│ #rp-hdr             RightPanelHeader       │
│ #rp-msgs            MessageList            │
│ #status-bar         StatusBar              │
│ ...                                        │
│ (항목 없음 시 caption "매핑 정의 없음")    │
└────────────────────────────────────────────┘
```

- 매핑 데이터 source: `docs/design/<slug>/mockup-map.json` (선택 파일; 없으면 empty state).  
- `mockup-map.json` 스키마:

```json
{
  "file": "mockup.html",
  "mappings": [
    { "id": "rp-hdr", "component": "RightPanelHeader", "note": "35px header" }
  ]
}
```

- 표: `caption` 13px. 행 hover = `gray-800/40` bg. 클릭 행 = 해당 element 에 iframe `postMessage({ highlight: "#id" })` (opt-in; mockup HTML 미지원 시 무시).

## §3 Acceptance (impl 기준)

- [ ] `preview` tab type → `PlaceholderTab` 아닌 `PreviewTab` 렌더
- [ ] `prev-toolbar`: file picker 드롭다운 + zoom controls (–/level/+/fit) + mapping 토글 버튼 배치
- [ ] `prev-body`: mockup HTML iframe (web) / `<webview>` (Electron) 렌더링
- [ ] file source 해석 순서 A → B → C 준수; 없을 시 `EmptyState` 노출
- [ ] zoom 25–200%, fit-to-window, zoom level label 클릭 → 100% 복귀
- [ ] file 로드 중 spinner, 완료 시 숨김 (§1.5.4 Feedback)
- [ ] `prev-mapping` 패널: 토글, `mockup-map.json` 로드, 없을 시 empty state
- [ ] T-P4-046 `openTab('preview', { mockupPath?, slug? })` API 로 호출 가능

## §Open Questions

1. **Electron `<webview>` vs `<iframe>`** — 보안 정책(CSP / `nodeIntegration`) 에 따라 선택 달라짐. impl 에서 판단; 디자인 스펙은 두 경우 동일 시각 레이아웃 유지.  
2. **file picker 목록 로드 방식** — `window.api.listMockupFiles(slug)` IPC 호출인지 import.meta.glob 방식인지 impl 결정 사항.  
3. **mapping 행 click → iframe highlight** — mockup HTML 에 postMessage listener 없으면 silent fail. opt-in 기능으로 문서화 충분한지?
