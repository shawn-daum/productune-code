# T-P4-101: Fresh project entry — "아이디어 먼저" 1-input 화면 (FreshComposer + EntryGate + onboarding state)

> GUI에서 새 프로젝트를 만들거나 non-productune 폴더를 init/install한 직후에는, full workspace(ActivityBar / Sidebar / MainPanel / ChatPanel)를 즉시 보여주지 않는다. **persisted onboarding state**가 `pending`인 프로젝트는 중앙 1-input FreshComposer만 먼저 표시하고, 사용자의 **첫 real message가 send/start kick-off에 성공한 순간** onboarding을 `done`으로 전환하여 normal workspace 전체 UI를 reveal한다.

---

## §1 Background

### 1.1 사용자 요청 verbatim (2026-05-12)

> "Gui project onboarding gui으로 프로젝트 생성하거나 init했을때, 모든 UI를 다 보여주지말고 pochat에 default로 '만들고 싶은 제품 아이디어를 얘기해주세요. Idea를 PO와 인터뷰해서 PRD작성을 먼저 시작합니다.' 대충 이런 내용으로 넣어줘. Chatgpt / lovable 초기 input 화면 처럼 딱 입력창 하나만 넣어주고. 이거 입력하고나면 우리 전체 ui를 보여줘."

### 1.2 현재 상태 진단

신규 프로젝트 진입 경로 **전부**가 즉시 full workspace로 들어간다.

| 진입 경로 | 현재 동작 | 문제 |
|:--|:--|:--|
| `project:create` 성공 | `App.tsx` → `WorkspaceShell` 즉시 mount | 아이디어 1문장도 없는 상태에서 밀도 높은 IDE 운영 화면 노출 |
| `project:installAt` 성공 | 동일 | 동일 |
| `lastProject` app relaunch | localStorage raw restore → `WorkspaceShell` | T-P4-091 fix와 별개로 진입 gating 없음 |

`WorkspaceShell` mount 직후 노출 요소: ActivityBar / LeftSidebar / Breadcrumb / MainPanel / StatusBar / ChatPanel + Tickets board tab auto-open.

사용자 mental model = `아이디어 말하기 → PO 인터뷰 → PRD 시작` 순서인데, 실제 화면은 역전된 상태.

### 1.3 기존 fresh 판정 접근의 한계

`chat.json.messages.length === 0` + `po-state` cleanliness 추론 방식의 문제:

- 명시적 상태가 아닌 "여러 파일의 깨끗함 추론"에 의존 → fragile
- hydration gating이 매 mount마다 누적 복잡 → flash 위험
- "새 프로젝트 첫 진입"과 "채팅이 우연히 비어있는 기존 프로젝트"를 구분 못함

**Primary contract**로 쓰기 부적합 → 명시적 persisted onboarding state 필요.

---

## §2 목표 / 비목표

### 2.1 목표

1. fresh onboarding 여부를 **명시적 persisted state**로 관리한다.
2. `pending` 기록은 **딱 두 시점**에서만 발생한다 (Decision B).
3. workspace entry 시 persisted state가 `pending`이면 **FreshComposer** (1-input screen)를 먼저 표시한다.
4. 첫 real user message가 **send/start kick-off 성공** 시 `done` 전환 + full workspace reveal한다.
5. 첫 send 실패 시 state는 `pending` 유지, draft 보존, retry 가능.

### 2.2 비목표

- full workspace 구조 자체 재설계
- PO 응답 품질 / 첫 PRD 프롬프트 내용 변경
- Tickets board / Main pane 기본 탭 정책 재설계
- onboarding wizard (`productune.env`, language, engine, wiki) 흐름 변경
- legacy 프로젝트 일괄 onboarding migration
- onboarding 재오픈(reset) 기능
- FreshComposer animation 세부 easing 값 (dev 자유 판단)

## §3 Decisions (A–G)

### Decision A — Persisted onboarding state 저장 위치

**권장 위치**: `.productune/onboarding.json` (프로젝트 디렉터리 내부, project-scoped).

```json
{
  "status": "pending" | "done",
  "source": "gui-create" | "install-at" | "legacy-fallback",
  "updated_at": "ISO8601"
}
```

**이유**: 프로젝트를 다른 머신으로 옮겨도 상태 유지 / `.productune/` 이미 존재하는 project-scoped store와 동일 계층 / hash 기반 global file은 path 변경 시 mismatch.

**reject 대안**: `po-state.json`에 `onboarding` 필드 추가 — po-state는 PO 오케스트레이터 런타임 state(세션마다 갱신). onboarding은 생애주기 1회 전환이므로 파일 책임 분리가 맞음.

> ⚠️ 정확한 필드명·파일명은 impl 책임. 계약 핵심 = "프로젝트 단위 persisted, 앱 재실행 후 유지, 오직 두 시점에서만 pending 기록".

### Decision B — `pending` 기록 시점

`pending`은 **오직 두 순간**에만 기록한다. 매 mount 시 재계산해서 덮어쓰지 않는다.

| 시점 | IPC / 트리거 | 비고 |
|:--|:--|:--|
| GUI 새 프로젝트 생성 성공 | `project:create` IPC 성공 응답 직후 | T-P4-058 init hygiene 이후 |
| non-productune 폴더 init/install 성공 완료 | `project:installAt` IPC 성공 완료 직후 | 실패/중단 시 pending 기록 X |

workspace entry 시 persisted state를 읽어 **분기만** 함 — 재계산하거나 `pending`을 새로 쓰지 않음.

### Decision C — Workspace entry 분기 (EntryGate)

`App.tsx`의 project mount 직후 `EntryGate` 컴포넌트가 분기한다:

| `onboarding.status` | 보여줄 화면 |
|:--|:--|
| `pending` (또는 `null` + secondary fallback → fresh 신호) | **FreshComposer** |
| `done` | 기존 `WorkspaceShell` full UI |
| onboarding field 없음 (legacy) | secondary fallback — 작업 흔적 없으면 FreshComposer, 흔적 있으면 WorkspaceShell |
| state resolve 전 (loading) | blank dark shell (`--surface-body` `#0F0F0F`) — full grid X, flash 방지 |

`loading-entry` 동안 Tickets board auto-open side effect 실행 **금지**.

### Decision D — FreshComposer UI spec

**레이아웃**:
- 전체 화면 단독 표시 (`position: absolute; inset: 0` 또는 root-level replace)
- background: `--surface-body` (`#0F0F0F`)
- 중앙 정렬 (`align-items: center; justify-content: center; flex-direction: column`)
- 콘텐츠 영역 max-width: 680px

**Hero copy** (UI text — `chat.json` synthetic assistant message로 저장 **X**):
- headline: `만들고 싶은 제품 아이디어를 얘기해주세요.`
  - i18n en: `Tell us the product idea you want to build.`
  - 토큰: `--text-primary` (`#E8E8EA`), ~22px semi-bold
- supporting copy: `Idea를 PO와 인터뷰해서 PRD 작성을 먼저 시작합니다.`
  - i18n en: `PO will interview the idea first and start by drafting the PRD.`
  - 토큰: `--text-secondary` (`#C8C8CC`), ~14px regular
  - `PO`, `PRD` literal 양 locale 동일 유지 (T-P4-057 보호어)

**Composer 요소 (only)**:
- textarea 1개 — autofocus, placeholder = supporting copy 동일 또는 단축 variant, 기존 ChatPanel textarea 스타일 token reuse
- Send CTA 버튼 1개 — primary, `--accent` (`#FF6B2B`), lucide `SendHorizonal` 아이콘 또는 텍스트 "시작하기" (dev 판단)
- **없는 것**: 파일 첨부, persona selector, quick prompts, recent list, sidebar chrome, breadcrumb, status bar, ActivityBar

**접근성**:
- keyboard-only send 가능 (`Enter` = send, `Shift+Enter` = 개행, `Cmd+Enter` 도 동작)
- 한국어 IME 조합 중 (`isComposing === true`) Enter submit 금지
- focus ring: `--accent` (`#FF6B2B`) 2px

### Decision E — Send 트리거: `pending → done` 전이 + full workspace reveal

첫 submit 성공 판정 순서 (순서 보장 필수):

1. 사용자 idea-entry에 첫 real text 입력 후 submit
2. user message persist 성공 (`.productune/chat/...` 기록)
3. `po:sendMessage` / send-start handshake 성공 (IPC 왕복 확인)
4. **여기서** onboarding status `pending → done` persisted 기록
5. FreshComposer unmount → WorkspaceShell mount (기존 full UI)
6. PO Chat에 방금 보낸 첫 user message + 이어지는 stream 표시

중요: step 4는 반드시 step 3 이후. reveal(step 5)은 assistant 답변 완료 대기 **없음** — WorkspaceShell mount와 stream 표시가 동시 진행.

### Decision F — Send 실패 경로

IPC 오류 / `po:sendMessage` 실패 시:
- onboarding status → `pending` 유지 (전이 없음)
- FreshComposer 유지 (full workspace reveal X)
- draft 텍스트 보존 (textarea value 초기화 금지)
- inline 1-line error (`--health-error` 색, 비기술적 문구): `"잠시 문제가 생겼어요. 다시 시도해주세요."`
- 재시도 CTA — Send 버튼 재활성 (spinner → error → 다시 Send 상태)
- 재시도 → send/start 성공 시 그때 `done` 전환 + reveal

### Decision G — `project:create` / `project:installAt` IPC 갱신

| IPC | 추가 작업 | 시점 |
|:--|:--|:--|
| `project:create` | `onboarding.json` write (`status: 'pending', source: 'gui-create'`) | `initProject()` 성공 완료 직후 |
| `project:installAt` | 동일 write (`source: 'install-at'`) | install 성공 완료 직후 |

**실패 시 기록하지 않는다** — install 중단/실패 = onboarding contract 미개시.

**EntryGate state machine**:

```
project mount
  │
  ├─ onboarding:read IPC ──→ { loading }  →  blank dark shell (#0F0F0F)
  │       │
  │    resolved
  │       ├─ status === 'pending'  ──→  <FreshComposer />
  │       ├─ status === 'done'     ──→  <WorkspaceShell />
  │       └─ no field (legacy)     ──→  secondary fallback
  │               ├─ no work traces  → <FreshComposer />
  │               └─ has traces      → <WorkspaceShell />
```

## §5 Acceptance Criteria

- [ ] GUI 새 프로젝트 생성 성공 직후, 프로젝트 onboarding state가 persisted `pending`으로 기록된다.
- [ ] non-productune 폴더 init/install 성공 완료 직후도 동일하게 `pending` 기록된다.
- [ ] workspace entry의 primary 판정은 persisted onboarding state다 (`chat.json` / `po-state` cleanliness 재계산 아님).
- [ ] `onboarding.status = pending`인 프로젝트는 ActivityBar / Sidebar / MainPanel / StatusBar / ChatPanel 대신 **중앙 FreshComposer**를 먼저 본다.
- [ ] `onboarding.status = done`인 프로젝트는 기존 full workspace로 바로 진입한다.
- [ ] onboarding field가 없는 legacy 프로젝트만 secondary fallback을 사용한다. fallback은 보수적(기존 작업 흔적 조금이라도 있으면 full workspace 우선).
- [ ] FreshComposer에는 textarea 1개 + Send CTA 1개만 있다. sidebar chrome / breadcrumb / status bar / ActivityBar 없음.
- [ ] textarea autofocus. Enter = send, Shift+Enter = 개행. IME isComposing 중 Enter submit 금지.
- [ ] Send 클릭 즉시 버튼 disabled + spinner 표시 (≤100ms feedback).
- [ ] 첫 입력 전에는 Tickets board auto-open이 실행되지 않는다.
- [ ] 첫 real user input이 user message persist + send/start kick-off에 성공하면 onboarding `done` persisted + full workspace reveal.
- [ ] reveal은 assistant 첫 응답 완료를 기다리지 않는다 (send/start 성공 직후).
- [ ] 첫 입력 send/start 실패 시 onboarding `pending` 유지 + FreshComposer 유지 + draft 보존 + inline error + 재시도 가능.
- [ ] hero 문구는 UI text로만 표시되며 `chat.json`에 synthetic assistant message로 저장되지 않는다.
- [ ] app relaunch / Cmd+R 후에도 onboarding `pending`이면 FreshComposer, `done`이면 full workspace.
- [ ] hydration 중 full UI flash가 없다 (loading-entry = blank dark shell).

## §6 Edge Cases

1. **project created, app reopened before first send** — onboarding이 이미 `pending`으로 persisted. 재오픈해도 FreshComposer 표시.
2. **first send failure after draft entered** — IPC/CLI 오류로 po:sendMessage 실패 시 `pending` 유지, draft 보존, retry 가능.
3. **user message persisted but send start failed** — partial success만으로 `done` 전환 금지. idempotent retry 가능해야 함.
4. **legacy project without onboarding field** — secondary fallback 사용. 빈 chat만 보고 적극적으로 onboarding 보내기보다, 기존 작업 흔적 있으면 full workspace 우선.
5. **existing project with manually cleared chat** — chat이 비어 있어도 onboarding이 이미 `done`이면 FreshComposer로 돌아가지 않는다.
6. **non-productune project opened before install completes** — onboarding `pending` 기록은 open 시점이 아니라 init/install **성공 완료** 시점. 실패/중단 시 기록 없음.
