# T-P4-002: 기존 CLI core (agents, po, scripts, config) → packages/core 이관 (zero behavior change)

**Round**: phase4-r0  **Stage**: impl  **Status**: done  **Assignee**: pdt-developer
**PRD anchor**: [docs/prd/productune.md#phase-4--개발-비숙련-기획자-모드-planner-mode-future](../../prd/productune.md#phase-4--개발-비숙련-기획자-모드-planner-mode-future)
**Estimated complexity**: L5  **Risk flags**: migration, regression

> Round 0 의 핵심 이관 작업. T-P4-001 에서 설정된 monorepo 골격 위에 기존 root-level CLI core (`agents/`, `po/`, `scripts/`, `config/`, `codex/`) 를 `packages/core/` 로 이동하고, CLI entry point 를 `packages/cli/` 로 분리. 이 티켓의 목표는 **행동 변화 없는 구조 이동** — 기존 `claude --agent pdt-po` 등 모든 CLI 호출이 완전히 동일하게 동작해야 함.

---

## Request

T-P4-001 완료 후 진행. 이관 범위와 절차:

### 1. `packages/core` 로 이동할 디렉터리

| 기존 경로 (root) | 이동 후 경로 |
|---|---|
| `agents/` | `packages/core/agents/` |
| `po/` | `packages/core/po/` |
| `scripts/` | `packages/core/scripts/` |
| `config/` | `packages/core/config/` |
| `codex/` | `packages/core/codex/` |

### 2. `packages/cli` 로 이동할 진입점

기존 root-level CLI entry point (있다면) 또는 `scripts/` 내 entry shell 스크립트 → `packages/cli/` 하위로 이동. `packages/cli` 가 `@productune/core` 를 workspace 의존으로 참조하도록 경로 업데이트.

### 3. 경로 참조 수정

이관으로 인해 변경되는 모든 상대 경로 수정:
- `agents/*.md` / `po/*.md` 내부의 상대 경로 (`../scripts/`, `../config/` 등)
- hook 스크립트 (`~/.productune/`) 가 참조하는 경로
- `install.sh` 의 복사/symlink 경로 — 신규 구조 기준으로 업데이트
- `docs/testing.md` 의 경로 참조 (있다면)

### 4. 심볼릭 링크 / hook 경로

`~/.productune/sections/*.md`, `~/.productune/hooks/` 등 사용자 홈 디렉터리에 설치된 파일들이 새 패키지 경로를 가리키도록 `install.sh` 갱신. 기존 설치 사용자는 `install.sh` 재실행으로 업데이트.

## Notes

- **회귀 위험 높음 (L5)**: 경로 참조가 많고, hook 스크립트의 하드코딩된 경로가 숨어있을 수 있음. 이관 전 `grep -r "agents/" .` / `grep -r "po/" .` 등으로 참조 전수 조사 권장.
- `install.sh` 재실행이 필요한 변경이므로, CHANGELOG 또는 README 에 "install.sh 재실행 필요" 안내 1줄 추가.
- 이관 후 `pnpm install` 재실행 필수 — workspace symlink 재구성.
- 이 티켓 완료가 Round 0 합격의 핵심 조건: "기존 CLI 동작 100% 보존". T-P4-003 과 병렬 진행 가능하지만 Round 0 통합 테스트는 둘 다 완료 후 수행.
