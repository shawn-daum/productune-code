# T-P4-113: 사용자 TODO 노출 — ChatPanel todo chip + 확장 패널

> PO 가 사용자에게 dogfood / manual smoke / confirm 을 요청할 때 chat 텍스트에만 묻혀 있던
> 할 일을 **시각화**한다. ChatPanel 에 todo chip (미완 count badge) 을 추가하고, 클릭 시
> 확장 패널에서 항목별 체크 / text-input 을 제공. 사용자 완료 처리 → PO chat 에 자동 메시지 inject.

---

## §1 Background

**사용자 dogfood (2026-05-14)**:

> "사용자 TODO 노출하기. 채팅창 위에 user todo 띄워주고, 클릭하면 user가 해줘야할 todo들 정리.
> user input이 따로 필요없는건 유저가 하고 체크 표시하면 po가 그거 input으로 받아서 그거에 맞는
> 행위를 진행. User input이 따로 필요한건 text input 제공"

**현재 상태 (drift root cause)**:

PO 가 sub-agent 응답 envelope 에 `manual_steps_pending` / `pending_user_actions` 를 내보내거나,
smoke gate / dogfood 요청을 chat 텍스트로 직접 삽입한다. 사용자 입장에선:

| 문제 | 증상 |
|:--|:--|
| 할 일이 chat 텍스트에 묻힘 | 스크롤 올려야 확인, 누락 위험 |
| 완료 여부를 별도로 알릴 방법 없음 | "했어요" 를 직접 타이핑 |
| 복수 todo 누적 추적 불가 | 어떤 항목이 남았는지 불명확 |

PO chat 이 단방향 보고 채널이 되는 anti-pattern → **§1.5 Feedback** 위반.

## §2 Scope

### A. ChatPanel — `rp-todo-chip` 행 삽입

위치: `<PersonaPresenceBar />` 와 `{/* rp-msgs */}` 사이 (기존 5-row layout 에서 6번째 행으로 추가).

```
┌──────────────────────────────────┐
│ rp-hdr        35 px              │
├──────────────────────────────────┤
│ rp-ctx       ~28 px              │
├──────────────────────────────────┤
│ rp-persona-bar 24 px             │
├──────────────────────────────────┤
│ rp-todo-chip  ~28 px   ← NEW     │  open count badge + "할 일" label
├──────────────────────────────────┤  (hidden when openCount === 0)
│ rp-msgs       flex-1, scroll     │
├──────────────────────────────────┤
│ rp-input      auto               │
└──────────────────────────────────┘
```

- `openCount === 0` → `rp-todo-chip` 행 `display: none` (공간 차지 없음).
- `openCount > 0` → chip 노출. 좌측 `ClipboardList` 아이콘 (lucide-react) + `"할 일 N"` 텍스트 + 주황색 count badge (`--persona-po` 토큰, `#FF6B2B`).
- chip 자체 클릭 → expanded panel 토글 (`todoExpanded: boolean` in `useUserTodo`).

### B. `TodoListPanel` — 확장 패널

- `rp-todo-chip` 바로 아래 accordion-style 삽입 (flex 레이아웃, rp-msgs 를 아래로 밀음).
- `max-height: 200px`, `overflow-y: auto`, `background: #161616`, `border-bottom: 1px solid var(--border)`.
- 빈 상태 (open todo 없음): `"할 일 없음"` caption + `display: none` (chip 과 연동).
- 각 todo row:

  | 필드 | 표시 방법 |
  |:--|:--|
  | `id` | `font-size: 10px`, gray caption (`#707070`), 앞에 `#` prefix |
  | `description` | 본문 텍스트, `font-size: 12px`, `--txt` |
  | `type: 'check'` | 왼쪽 체크박스 (lucide `Square` / `CheckSquare`). 클릭 → done 처리 |
  | `type: 'text-input'` | 체크박스 없음. description 아래 `<input type="text">` + submit 버튼 |
  | `type: 'link'` | description 이 클릭 가능 링크 (`ChevronRight` 아이콘). URL / 파일 경로 → main pane 오픈 (기존 `openTab` action) |
  | `status: 'done'` | row opacity 0.4, description `text-decoration: line-through`, 체크박스 채워짐 |
  | `status: 'dismissed'` | todo list 에서 미표시 (PO 가 dismiss 발행 시 자동 hide) |

### C. 체크 완료 → PO chat 메시지 inject

`type: 'check'` todo 사용자 클릭 시:

1. `useUserTodo.completeTodo(id)` → status `'done'` 전환.
2. `injectUserMessage("[user] done: <description>")` — 아래 §D 의 helper 호출.
3. `rp-todo-chip` badge 수 즉시 감소 (파생 selector `openCount`).

### D. text-input 제출 → PO chat 메시지 inject

`type: 'text-input'` todo — 사용자가 텍스트 입력 후 Enter 또는 submit 버튼 클릭 시:

1. `useUserTodo.completeTodo(id)`.
2. `injectUserMessage("[user]: <inputText>")`.

`injectUserMessage(text: string)` 공통 helper (`packages/gui/src/lib/injectUserMessage.ts`):

```ts
// pseudo-spec (구현 참고용)
export async function injectUserMessage(text: string) {
  const project = useWorkspace.getState().project
  if (!project) return
  const streaming = useWorkspace.getState().streaming
  if (streaming) return   // 스트리밍 중 — inject 큐잉 미지원 (Out of scope)

  const msg: Message = {
    id: `u-todo-${Date.now()}-${Math.random().toString(36).slice(2, 7)}`,
    role: 'user',
    kind: 'user',
    text,
    status: 'done',
    created_at: new Date().toISOString(),
  }
  useWorkspace.getState().appendMessage(msg)
  try { await (window as any).api.chatAppendMessage(project.projectDir, msg) } catch { /* ignore */ }
  useWorkspace.getState().setStreaming(true)
  try {
    await (window as any).api.poSendMessage({
      projectDir: project.projectDir,
      text,
      resume: useWorkspace.getState().claudeSessionId,
    })
  } catch {
    useWorkspace.getState().setStreaming(false)
  }
}
```

> **Note**: `streaming === true` 일 때 inject 는 이번 scope 에서 skip (사용자에게 "PO 처리 중 — 완료 후 시도" 토스트 표시 또는 버튼 disabled). 큐잉 / 직렬화는 별 ticket.

### E. PO sub-agent envelope → 자동 todo push

po-runner (main process, `packages/main/src/po-runner.ts` 또는 유사 파일) 의 `poOnDone` 처리 지점에서
PO 응답 JSON 을 파싱해 `manual_steps_pending` / `pending_user_actions` 배열을 detect, 새 IPC
이벤트 `po:todo-items` 로 emit.

```ts
// main process — pseudo-spec
// 파싱 위치: poOnDone 직전 finalText JSON.parse 시도
interface TodoItemRaw {
  id?: string
  description: string
  type?: 'check' | 'text-input' | 'link'
  href?: string   // type=link 일 때
}

// emit 형식 (IPC channel: 'po:todo-items')
ipcMain.on('po:todo-items', ...) // renderer side
mainWindow.webContents.send('po:todo-items', items: TodoItemRaw[])
```

Renderer `ChatPanel.tsx` 에 `useEffect` 추가 — `api.poOnTodoItems(items => useUserTodo.getState().pushItems(items))`.

**envelope 파싱 우선순위**:

1. 응답 텍스트가 JSON block (`\`\`\`json … \`\`\`` 또는 raw `{...}`) 을 포함하고 `manual_steps_pending` 키 존재 → 배열 파싱.
2. `pending_user_actions` 키도 동일하게 처리.
3. 파싱 실패 / 키 없음 → noop (기존 동작 유지).

### F. Todo 4-state lifecycle

| State | 전환 방법 | 표시 |
|:--|:--|:--|
| `created` | `pushItems()` 호출 직후 (PO 발행) | open 과 동일하게 표시 |
| `open` | 기본 상태 (badge count 포함) | 정상 row |
| `done` | 사용자 체크 / text-input submit | opacity 0.4 + strikethrough, badge 감소 |
| `dismissed` | PO 가 추후 `po:todo-dismiss` IPC emit (본 ticket: 수신 채널만 준비, PO side emit 은 별 ticket) | list 에서 hidden |

`useUserTodo` store 는 `dismissed` 항목도 배열에 보존 (필터링으로 숨김). 재시작 시 초기화 (in-memory only — §Out of scope).

## §Out of scope

- **cross-session todo 보존** — 재시작 시 todo 초기화 (`in-memory only`). persist 는 별 ticket.
- **todo priority sorting / 순서 변경** — 삽입 순서(fifo) 고정. 정렬 UI 별 ticket.
- **todo 알림 / notification** — badge 시각화만. OS 알림 별 ticket.
- **streaming 중 inject 큐잉** — 현재 streaming 완료 후 수동 재시도. 직렬 큐 별 ticket.
- **PO side `po:todo-dismiss` emit** — 수신 채널만 준비. PO 응답에서 dismiss 발행은 별 ticket.
- **todo item 편집 / 삭제 (사용자)** — done / dismissed 만. 항목 직접 편집 별 ticket.

## §6 §1.5 UX self-check

| Principle | 준수 여부 | 근거 |
|:--|:--|:--|
| **Few Things Per Page** | ✅ | todo chip 은 count 만 노출 (progressive disclosure). 세부 항목은 클릭 후 expand. rp-msgs 영역 압박 최소화 (empty → hidden). |
| **Familiar** | ✅ | 알림 badge + chip 패턴은 모바일/데스크톱 모두 친숙. `ClipboardList` 아이콘 의미 명확. |
| **Predictability** | ✅ | badge 숫자 = open todo count. 체크 → badge -1 + PO 응답. text submit → same. 사용자가 예상 가능한 흐름. |
| **Feedback** | ✅ | 체크 클릭 즉시 row strikethrough + badge 감소 (optimistic UI). PO chat 에 user bubble 삽입 → "PO 가 받았다" 시각 확인. |
| **Escape** | ✅ | chip 재클릭 → 패널 닫힘. streaming 중 버튼 disabled (stuck 상태 없음). |

## §8 Open questions

1. **po-runner 파일 경로 확인** — `packages/main/src/po-runner.ts` 가 실제 경로인지, 또는 `packages/main/src/runner/` 하위인지 impl 시 glob 확인 필요.
2. **envelope JSON 파싱 위치** — po-runner 에서 `finalText` 를 파싱할지, 또는 renderer `poOnDone` 핸들러에서 처리할지. 권장: main process 에서 파싱 후 `po:todo-items` emit (renderer 오염 최소화). 구현자 판단 허용.
3. **`streaming === true` UX** — inject 시도 시 버튼 `disabled` 처리로 충분한지, 아니면 toast `"PO 처리 중"` 이 더 나은지. 현재는 disabled 로 spec. 필요 시 toast 추가 (L1 범위).
4. **TodoListPanel 위치** — accordion (flex push-down) vs absolute overlay. 현재 spec = accordion (flex). 340px 패널에서 rp-msgs 공간이 지나치게 줄어든다면 overlay 로 변경 허용 (구현자 판단).
