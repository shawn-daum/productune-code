# T-P4-091: Stale `lastProject` guard + Onboarding cleanup

> Renderer 의 `localStorage.productune.lastProject` 가 `~/.productune/settings.json` 과 분리된 Chromium storage 에 잔존하여, 사용자가 settings.json + project 폴더를 삭제해도 다음 실행에 deleted path 로 active project 진입하는 dogfood 발견. **A) lazy init guard** (App.tsx) + **B) Onboarding cleanup** 둘 다 적용해 reset 의도 정합 + 잔재 자동 정리.

## §1 Background

사용자 dogfood (2026-05-11):

> "테스트하려고 ntf-games 프로젝트 지우고 온보딩 설정 지우고 gui 재시작했는데 온보딩 후에 ntf-games 가 나오는 문제가 있어."

### Root cause

`packages/gui/src/App.tsx:29` 의 `useState` lazy init 이 `localStorage.getItem('productune.lastProject')` raw JSON 을 그대로 state 로 set. 이는 Electron renderer 의 Chromium localStorage 로, `~/.productune/settings.json` 과 별 storage. 사용자가 다음 셋을 정리해도:

- `~/productune/projects/ntf-games/` 폴더 삭제
- `~/.productune/settings.json` 삭제 (onboarding 재진입 의도)
- GUI 재시작

localStorage 의 `productune.lastProject` 는 살아있어 → onboarding wizard 통과 후 deleted path 의 ntf-games 진입 시도 → 빈 폴더 / 깨진 상태.

### 사용자 결정 = 옵션 (c) 둘 다

1. **lazy init guard** — `fs.existsSync(projectDir)` IPC check 추가, 없으면 `localStorage.removeItem` + home 화면
2. **Onboarding cleanup** — Onboarding 진입 시 (또는 first-run 감지 시) localStorage 도 같이 clear

## §2 결정 사항 (designer 판단)

| OQ | 결정 |
|---|---|

WorkspaceShell 이 첫 frame 잠깐 mount 되어도 IPC 한 turn (수 ms) 이라 시각적 임팩트 미미; 정상 path 이면 effect noop |
| IPC 이름 | **`project:exists`** 신규. payload = `{ projectDir: string }`, 반환 = `boolean`. main process 에서 `fs.existsSync(projectDir) && fs.existsSync(path.join(projectDir, '.productune/config.json'))` (단순 폴더 존재가 아니라 productune project 마커까지 확인 — 사용자가 폴더만 만들고 init 안 했으면 home 으로 빠지는 게 정합). preload 에 `api.checkProjectExists(projectDir): Promise<boolean>` 노출 |
| (B) cleanup trigger | **First-run 감지 시 (init effect 의 `!envExists \|\| !hasLangPref` 분기 = onboarding 진입 조건) localStorage 도 같이 clear**. onboarding 완료 (`onDone`) 시점이 아니라 진입 시점 — 사용자 의도 "onboarding 설정 지움 = 깨끗히 reset" 의 의미 정합. envExists false 이면 settings.json 부재 = first-run = lastProject 도 stale 일 확률 압도적 |
| Cleanup 범위 | **`localStorage.removeItem('productune.lastProject')` 만**. 다른 키 (i18n, theme 등) 는 본 ticket scope X. (현재 GUI 에서 다른 localStorage 키 없음 — 추후 추가 시 cleanup 정책 별도 doctrine 후보) |
| 정상 path 동작 | **변경 X**. lastProject path 가 유효 (config.json 존재) 하면 기존 자동 복원 동작 유지. Cmd+R 시 WorkspaceShell 즉시 mount (flash 회피) 동작 보존 |
| 상호작용 | (A) 와 (B) 가 **둘 다 적용되어도 안전** — onboarding 진입 시 (B) 가 clear → lazy init 다음 mount 에서 (A) 가 추가 check (이미 clear 됐으니 noop). race condition 없음 |
| HomeView fallback | 잘못된 project 감지 후 `setProject(null)` → 기존 HomeView 자동 표시. 사용자에게 별 알림 X (silent recovery). Home recent projects 목록 (T-P4-013) 에 stale entry 도 있을 수 있으나 본 ticket scope X (recent projects 의 exists check 는 T-P4-013 의 책임) |

## §4 Acceptance

### A) IPC `project:exists` 신규

- [ ] `packages/gui/electron/po-runner.ts` (또는 main process IPC handler 파일) 에 `ipcMain.handle('project:exists', (_e, payload: { projectDir: string }) => boolean)` 추가
  - [ ] `fs.existsSync(projectDir)` 폴더 존재 + `fs.existsSync(path.join(projectDir, '.productune/config.json'))` 둘 다 true 일 때 `true`
  - [ ] 예외 (path 비어있음 / 권한 에러) → `false`
- [ ] `packages/gui/electron/preload.ts` `api.checkProjectExists(projectDir: string): Promise<boolean>` exposed
- [ ] `packages/gui/dist-electron/*` 빌드 후 일관

### B) App.tsx lazy init guard

- [ ] `useEffect` (mount once) 안에 stale check 추가:
  - [ ] `project` state 가 lazy init 으로 채워진 경우 (`project?.projectDir` 존재)
  - [ ] `await (window as any).api.checkProjectExists(project.projectDir)` 호출
  - [ ] false → `localStorage.removeItem('productune.lastProject')` + `setProject(null)` (HomeView 로 fallback)
  - [ ] true → noop (기존 동작 유지)
  - [ ] catch → noop (IPC 미가용 browser dev mode 호환)
- [ ] 기존 `useState` lazy init 자체는 변경 X (Cmd+R flash 회피 보존)
- [ ] 기존 persist effect (`useEffect(() => { setItem/removeItem }, [project])`) 변경 X

### C) Onboarding cleanup

- [ ] init effect 안 `setShowOnboarding(!envExists || !hasLangPref)` 직후, onboarding 진입 조건 true 면:
  - [ ] `localStorage.removeItem('productune.lastProject')` 호출
  - [ ] `setProject(null)` (lazy init 으로 채워졌어도 wipe — onboarding 화면이 mount 되니 시각적 변화는 onboarding 만 노출)
- [ ] 또는 더 단순 방식: `if (!envExists || !hasLangPref) { localStorage.removeItem('productune.lastProject'); setProject(null); setShowOnboarding(true) }` 으로 한 블록 정리
- [ ] Onboarding 완료 (`onDone`) 시점은 변경 X — 진입 시점 cleanup 으로 충분

### D) 회귀

- [ ] 정상 진입 (lastProject path 가 유효 + config.json 존재) — Cmd+R 시 WorkspaceShell 즉시 mount (flash 없음) 동작 보존

- [ ] HomeView fallback (recent projects 카드) 표시 정합 — T-P4-013 의 recent list 정상 노출

## §5 QA scenarios (light)

1. **Stale project guard (사용자 dogfood)** — project 폴더 + `~/.productune/settings.json` 삭제 → GUI 재시작 → onboarding wizard 통과 → home 화면 노출 (deleted project 자동 진입 X). localStorage 의 `productune.lastProject` 도 비어있음
2. **First-run cleanup only** — settings.json 만 삭제 (project 폴더는 존재) → GUI 재시작 → onboarding 진입 → home 화면 (lastProject 자동 복원 X — onboarding 의 reset 의도 우선)
3. **정상 자동 복원** — settings.json 존재 + lang pref 존재 + lastProject path 유효 → GUI 재시작 → WorkspaceShell 즉시 mount (flash 없음) + 기존 project 자동 진입
4. **Project 폴더만 삭제 (settings.json 살아있음)** — settings.json 그대로 + ntf-games 폴더만 삭제 → GUI 재시작 → lazy init 으로 일순간 mount 시도 → mount effect 의 `project:exists` false → `setProject(null)` → HomeView fallback. 사용자에게 깨진 빈 화면 X
5. **`project:exists` IPC false 케이스 분기** — projectDir 존재하지만 `.productune/config.json` 부재 (사용자가 다른 폴더로 confused) → false 반환 → home fallback
6. **Browser dev mode** — `(window as any).api` 미가용 환경 (vite dev server 직접 접근) → catch 분기 → 기존 lastProject state 유지 (production parity 는 Electron 에서만)
7. **HomeView recent projects 회귀** — T-P4-013 의 recent list 가 stale entry 포함하더라도 click 시점에 별 verify (T-P4-013 책임). 본 ticket 은 `lastProject` 단일 entry 만 책임
