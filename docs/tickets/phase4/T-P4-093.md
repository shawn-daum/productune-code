# T-P4-093: PresenceBar PO chip working blink — T-P4-076 정책 reversal (PO active turn 동안 working)

## Background

사용자 dogfood (2026-05-12) — T-P4-076 ~ T-P4-083 R4 fix line land 후 manual 검증
중 발견:

> "Status bar에 po도 있는데 po는 작업중인 표시가 안떠."

**현행 정책 (T-P4-076 §Acceptance.A "persona scope")**: PO 는 derive 대상 X —
PO 는 전경 chat 이고 sub-agent 가 아니므로 useBackgroundTasks 가 source 가
아님. 결과 = PO chat 응답이 stream 중이어도 PresenceBar PO chip 영구 idle.

**사용자 의도**: PO 가 사용자 메시지를 받아 응답 stream 중이면 (= PO 의 active
turn) PO chip 도 working blink. PO 도 다른 페르소나처럼 "지금 일하고 있어요"
시각 신호. T-P4-076 의 "영구 idle 유지" 정책 reversal.

본 ticket = 그 reversal 의 spec gap fill. 단 PO 의 working source 는 sub-agent
와 다른 path — useBackgroundTasks 가 아닌 **PO turn state** (`workspace` store
의 `streaming: boolean` 이 가장 자연스러운 SoT — PO turn 진입 시 true, 응답
완료 시 false 로 stream-json 흐름이 set).

## Acceptance

### A) PO working source — `workspace.streaming` 구독 (단방향 derive)

PO 의 working 표시는 sub-agent 와 별 source — `useBackgroundTasks` 가 아닌
`useWorkspace.streaming: boolean`. `PersonaPresenceBar.tsx` 의
`usePersonaPresenceDerive` hook 안에 sub-derive 추가 또는 별 useEffect 로 처리
(dev 판단 — designer 권고 = 같은 hook 안 별 useEffect 로 분리해서 sub-agent
derive 와 결합 X).

- [ ] **subscribe**: `const streaming = useWorkspace((s) => s.streaming)` (이미
      WorkspaceShell 이 같은 selector 사용 중 — re-render 비용 미세)
- [ ] **working transition**: `streaming === true` 이고 PO state 가 working 이
      아니면 → `setPersonaState('po', 'working')` 호출
- [ ] **idle transition**: `streaming === false` 이고 PO state 가 working 이면
      → `setPersonaState('po', 'idle')` 호출 (done 분기 X — §B 참조)
- [ ] PO state 가 이미 working 인 상태에서 streaming 이 계속 true 면 noop
      (store idempotent — updatedAt 만 refresh)
- [ ] **direction**: 단방향 `workspace.streaming → personaPresence.po`. 다른
      caller 없음 (sub-agent derive 의 PO 항목 = 기존대로 derive 대상 X —
      `DERIVE_PERSONAS` array 는 변경 X)

### B) done state 정책 — PO 는 즉시 idle (sub-agent 와 다른 정책)

PO turn done 후 chip color/state 처리:

- [ ] **즉시 idle 복귀** — `streaming` false 전환 시 즉시 `setPersonaState('po',
      'idle')`. done state 거치지 X.
- [ ] 이유:
  - PO 의 done artifact = 사용자 답변 텍스트 자체 — ChatPanel 의 bubble 이
    이미 보존. PresenceBar tooltip 에 다시 노출 시 정보 중복.

## QA scenarios (light)

1. **PO turn 진입** — chat input 에 메시지 입력 + send → PO chip working blink
   즉시 (응답 첫 token 보다 빠르거나 동시)
2. **PO turn 종료** — PO 응답 완료 → PO chip idle 회색 즉시 복귀 (done ✓ flash
   X)
3. **PO turn 중 sub-agent dispatch** — PO 응답 중 PO 가 designer 호출 → PO chip
   working + designer chip working 동시
4. **PO turn 종료 후 sub-agent 계속** — PO 응답 끝났는데 sub-agent 가 아직
   working → PO chip idle, sub-agent chip working
5. **PO chip hover popup 차단** — PO chip 에 hover → popup open X (sub-agent
   chip hover 와 다른 동작)
6. **session restart 중 PO turn** — PO 응답 stream 중 restart click → 모달
   confirm 후 모든 chip idle (PO 포함). streaming false 로 resetAll 한 번 → PO
   idle 정합.
7. **streaming flicker 방지** (만약 §F.7 의 chunk 흐름이 jitter 가 있는 경우)
   — PO 응답 chunk 분리 (T-P4-079) 동안 chip blink 끊김 없이 유지. dev 가 실제
   동작 확인 후 debounce 결정.
8. **PO done dismiss noop** — PO chip 은 done state 안 거치므로
   `dismissDone('po')` 호출 source 없음. T-P4-076 의 outside click dismiss
   handler 가 PO 에 대해서는 idle 상태일 때 trigger X 정합.
