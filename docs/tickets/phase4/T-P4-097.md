# T-P4-097: Side panel master = "현재 버전" + "Version history" 2-section split

> Project tab side panel 의 VERSIONS master 를 **"현재 버전"** + **"버전 히스토리"** 2 sp-section 으로 분리. 현재 버전 click → `version-current:{id}` tab (title = `v1`), 과거 click → `version-history:main` tab (title = `버전 히스토리`). tab type 단일 (`version-history`) reuse — T-P4-023 1.5차 isCurrentVersion 분기 그대로. v1 default init 시드 + rename in-place tab id swap + transient close auto-move 포함.

## §1 Background

사용자 2026-05-12 dogfood feedback:

> 프로젝트 side panel 구성
> 현재 버젼 (처음 init 하면 v1을 디폴트로 설정 이후 prd 작성하면서 version naming 바뀔 수 있음)
> {version-title} {phase name-hover시 전체 phase 표시} → 클릭시 main panel에 {version title} 탭 (기존 ticket tab 재사용) 표시
> Version history
> 현재 버젼 제외한 이전 버젼 listup
> {version-title} {phase-아마 close겠지?} → 클릭시 version history (ticket completed at sort)

현 `SidePanelVersionList.tsx` = 단일 VERSIONS sp-section (current + past 섞임, isLatest 만 시각 강조). 사용자 mental model = "현재 작업" vs "지난 기록" 두 객체 분리 — 같은 list 에 섞이면 작업 컨텍스트 추적 어려움.

본 ticket = **사이드바 2 sp-section split + main tab id 분리** (component 단일 reuse). 자세한 design rationale + decisions (a)–(g) + §1.5 self-check 는 plan 참조: `docs/design/T-P4-097/plan.md` v2.

## §2 Scope — sub-area

### A. SidePanelCurrentVersion (신규 컴포넌트)

- `packages/gui/src/components/workspace/SidePanelCurrentVersion.tsx` (신규).
- props = `{ poState, selectedVersionId, onSelect }`.
- 1-row section. row 라벨 = `poState.current_version` id + 현재 phase label + ticket·deploy count + 날짜.
- **Transient close determination**:
  ```ts
  const currentVer = poState?.versions?.find(v => v.id === poState?.current_version)
  const isCurrentClosed = !!currentVer?.outcome || !!currentVer?.ended_at
  ```
  - `isCurrentClosed === true` → row 표시 X, 대신 read-only fallback row ("다음 버전 시작 대기 중 — PO 와 새 PRD 시작 시 활성화됩니다").
  - versions[] 비어있고 current_version 도 없으면 → read-only fallback row ("v1 (대기 중) — PRD 작성 시작 시 활성화됩니다").
- sec-hdr 우측 = 현재 phase 색 dot only (label 은 row 메타에 있음).
- click → `onSelect(versionId)` → upper-level `handleVersionClick(versionId, isCurrent=true)`.

### B. SidePanelPastVersions (신규 컴포넌트, 기존 SidePanelVersionList 일부 흡수)

- `packages/gui/src/components/workspace/SidePanelPastVersions.tsx` (신규).
- props = `{ poState, selectedVersionId, unassignedCount, pastTicketCounts, pastDeployCounts, onSelect }`.
- N-row section. **현재 버전 제외** + transient close 된 version 은 top 으로.
- Row 정렬: `(ended_at ?? started_at) desc` (T-P4-023 의 `started_at` desc 에서 보강 — closed 직후 top 으로 올라가야 함).
- 미배정 (`__unassigned__`) bucket 은 맨 아래.
- sec-hdr 우측 = "{N}개 · 배포 {M}" (기존 `SidePanelVersionList` 의 `headerRight` 패턴 재사용, 단 N 은 과거만 count).
- click → `onSelect(versionId)` → `handleVersionClick(versionId, isCurrent=false)`.

### E. workspace store — `updateTabId` helper (OQ-5 resolution)

- `packages/gui/src/store/workspace.ts` 에 helper 추가:
  ```ts
  updateTabId: (oldId: string, newId: string, newTitle?: string) => void
  ```
- 동작:
  - pane tree (`paneTree`) 재귀 walk — leaf 의 `tabs[]` 에서 `id === oldId` 매칭 시 `id = newId` + (newTitle ?? title) 갱신.
  - 해당 leaf 의 `activeTabId === oldId` 이면 `activeTabId = newId` 도 swap.
  - props 는 보존.
  - 매칭 없으면 no-op (silent).
- LeftSidebar 또는 별 effect 위치에서 `current_version` 변경 감지 → `updateTabId(\`version-current:${prev}\`, \`version-current:${next}\`, next)` 호출.
- prev tracking = `useRef<string | null>` (rename 케이스 한정 — 새 version 시드 / 첫 mount 는 swap 대상 아님).

### H. handleVersionClick — tab dispatch logic

- `LeftSidebar.tsx` (또는 `SidePanelCurrentVersion` / `SidePanelPastVersions` 공통 helper) 에 추가:
  ```ts
  function handleVersionClick(versionId: string, isCurrent: boolean) {
    setSelectedVersionId(versionId)
    if (isCurrent) {
      openTab(
        `version-current:${versionId}`,
        'version-history',
        { mode: 'current' },
        versionId,  // tab title = "v1"
      )
    } else if (versionId === '__unassigned__') {
      openTab(
        `version-unassigned:main`,
        'version-history',
        { mode: 'past' },
        t('workspace.versionHistory.unassigned.label'),
      )
    } else {
      openTab(
        `version-history:main`,
        'version-history',
        { mode: 'past' },
        t('workspace.versionHistory.title'),
      )
    }
    window.dispatchEvent(new CustomEvent('version-select', { detail: { versionId } }))
  }
  ```
- `VersionHistoryView` 의 `isCurrentVersion` 분기 그대로 (T-P4-023 1.5차 land). props.mode 는 hint only.

## §6 Design system §1.5 self-check

| Sub-rule | 검증 | 결과 |
|---|---|---|
| 2-1 Few Things | 1 row = pill + phase + count + date = 4 토큰 (마지노선). primary action = click open. 3 sp-section (Phase / Current / History). | ✓ |
| 2-2 Familiar | Master-detail 패턴 (VS Code SCM / GitHub branches). 2 sp-section split = 동일 sec-hdr 톤. | ✓ |
| 3-1 Predictability | row click = 항상 tab open. selected = orange left border. empty/transient/v1-default fallback 3 종 모두 명시. rename = in-place swap (컨텍스트 보존). | ✓ |
| 3-2 Feedback | row hover = bg 변경 + CSS-only popover opacity transition. click = tab open + selected 표식 즉시 변경. | ✓ |
| 3-3 Escape | tab X = 닫기. side panel collapse = Activity Bar 재클릭. row click 비-destructive. transient close 시 자동 tab close 안 함 (사용자 직접 닫음). | ✓ |

**Anti-patterns 점검**:
- ❌ row 클릭 후 무반응 → 없음 (즉시 tab open + selected).
- ❌ rename 시 작업 컨텍스트 손실 → 없음 (`updateTabId` in-place).
- ❌ Close phase 끝났는데 현재 자리에 박혀있음 → 없음 (transient determination).
