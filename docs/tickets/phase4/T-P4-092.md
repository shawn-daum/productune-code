# T-P4-092: PO ticket 발행 → `worktree:create` 자동 wire + base-dirty 모달 + ChatPanel trace — T-P4-020 sub-e 보강

## Background

T-P4-020 (worktree + base 보호) land 완료. design plan §9.6 (sub-e PO 흐름 통합)
은 별 PO doctrine task 로 분리 명시 — sub-a/b/c/d (worktree manager / branch
namer / hook installer / IPC bridge) 만 본체에 포함되고 **actual caller (PO 가
ticket 발행 후 자동 wire) + base-dirty 사용자 모달**이 미구현 상태. 결과:
ticket 발행해도 worktree directory 가 자동 생성되지 않고 ticket md 의
`worktree_path:` / `branch:` 필드가 계속 null. 자동저장 (T-P4-021) / 배포 게이트
(T-P4-022) 가 이 필드 의존 — sub-e 까지 완료되어야 R2 ticket-단위 worktree
체인 전체 동작.

본 ticket = sub-e forward fix. 3 sub-area (PO doctrine + GUI base-dirty 모달 +
ChatPanel trace).

### OQ-T092-1 — BaseDirtyModal "Set aside" backend = `git stash` vs `git stash -u`

| 옵션 | 장점 | 단점 |
|---|---|---|
| (a) `git stash` (tracked only) | 사용자 명시 add 한 untracked 파일 보호 안 됨 risk — 의도된 .gitignore X 파일 등. | tracked 변경만 stash → untracked 파일은 base 에 남음 — worktree 생성 시 base 의 untracked 도 함께 영향 가능. |
| **(b) `git stash -u` (untracked 포함)** (designer 잠정 권고) | 모든 사용자 변경 보존. base 가 진짜 깨끗 상태로 worktree 분기. | 외부 도구 (예: VS Code 의 .vscode/) untracked 도 stash 됨 — 사용자 의도와 어긋날 가능 미세. |
| (c) 사용자 추가 모달 ("untracked 파일도 보관할까요? Y/N") | 사용자 통제. | onboarding 부담 ↑. "untracked" 어휘 노출 risk. |

**designer 권고**: **(b) `git stash -u`**. 이유:
- "보관" 카피의 사용자 mental model = "지금 모든 변경 안전하게 옆에 둠" — partial
  stash 는 직관 위반.
- (c) 의 모달 = "untracked" 어휘 노출 (R2 §1.2 어휘 정책 위반).
- Phase 5 candidate = "보관 옵션 세분화" sub-Settings (별 ticket).

### OQ-T092-2 — BaseDirtyModal "Save now" 옵션 → commit 메시지 입력
