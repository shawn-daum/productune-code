# T-P4-109 — `productune init` shell 경로에 user-global doctrine bootstrap wire

## §1 Background

### 1.1 Root cause — paepyeong PO doctrine 사고

v0.4-meta-dogfood dogfood 중 paepyeong 프로젝트에서 PO 실행 시 `~/.productune/po-instructions.md` 부재로 doctrine 강제 실패. 사용자 직접 디버깅 (2026-05-14) 으로 원인 확인.

코드 탐색 결과 누락 지점 세 곳:

| Location | 내용 | Gap |
|:--|:--|:--|
| `packages/core/scripts/productune` L208–299 | `init)` handler: git init + `.productune/po-state.json` + `docs/pdt-*/` dirs + `.gitignore` → `exit 0` (L299) | **doctrine bootstrap 호출 없음** — handler 는 project-level scaffold 만 수행하고 종료 |
| `packages/core/scripts/install.sh` L602–630 | po-instructions.md hash compare/backup/copy + sections/ wipe+copy + po-memory.md seed-only | Doctrine 로직 **inline** — named function 없음. `productune init` 에서 재사용 불가 |
| `packages/core/src/init.ts` L248–300 (`bootstrapUserGlobalDoctrine`) + L331 (`initProject`) | TypeScript 구현 완전함. `initProject()` 가 `!opts.skipDoctrine` 시 `bootstrapUserGlobalDoctrine()` 호출 | `initProject()` 는 Electron IPC path 에서만 호출됨 — CLI `productune init` 진입점 없음 |

### 1.2 실패 경로

```
사용자 $ productune init
  → shell init handler (L208) 실행
  → git init ✓ / po-state.json ✓ / docs/pdt-*/ ✓ / .gitignore ✓
  → exit 0  ← 여기서 종료
  → ~/.productune/po-instructions.md  미설치  ← paepyeong PO doctrine 실패 root cause
  → ~/.productune/sections/*.md       미설치
  → ~/.productune/po-memory.md        미설치
```

TypeScript `bootstrapUserGlobalDoctrine()` 는 잘 작성되어 있으나 CLI path 에서 진입 불가. T-P4-106 에서 wire 됐다고 간주했으나 Electron IPC 경로만 연결된 상태였음 — **shell `productune init` 는 wire 누락**.

## §2 Scope

Option C 채택 (plan §2(a) 결정 — bash lib 단일화, 두 bash script source + call):

### A. `packages/core/scripts/lib/bootstrap-doctrine.sh` 신규 CREATE

`bootstrap_user_global_doctrine()` 함수 정의. `install.sh` L602–630 inline 로직 추출.

- **인자**: `$1` = `DOCTRINE_ROOT` (`packages/core/` 절대경로). 함수 내부에서 `PO_SRC="$1/po"` 파생.
- **`say`/`warn` helper**: sourced 환경 전제 — 재정의 안 함 (caller script 에서 정의).
- **파일별 idempotent 정책**:

| 파일 | 정책 |
|:--|:--|
| `po-instructions.md` | `cmp -s` 동일 → skip. 다르면 `.bak.$TS` 백업 + 덮어쓰기 |
| `po-memory.md` | `[ ! -e ]` guard — **절대 overwrite 금지**. 없을 때만 template 에서 seed |
| `sections/*.md` | stale 파일 `rm -f` 선처리 → 전체 sweep 복사 (install.sh 기존 wipe+copy 패턴 유지) |
| `productune.env` | `[ ! -e ]` guard — 없을 때만 `engine=claude\n` 1줄 seed |

- **소스 디렉터리 부재 시**: `warn` + `return 0` (non-fatal) — 부분 설치 환경 보호.
- **OQ-1 해소**: `#!/usr/bin/env bash` 쓰되 상단 주석 `# source-only — do not execute directly` 명시. standalone 호출 감지 가드 (`[[ "${BASH_SOURCE[0]}" == "$0" ]]`) 선택 추가 가능 — **구현자 판단**.
- **OQ-4 해소**: `productune.env` seed = `engine=claude\n` 1줄만. `PRODUCTUNE_REPO` 는 install.sh 전담 (함수 범위 밖).

### B. `packages/core/scripts/install.sh` L602–630 갱신

기존 inline doctrine 로직 → 아래 2줄로 대체:

```bash
# ROOT 는 install.sh L20 기존 정의 사용
source "$ROOT/scripts/lib/bootstrap-doctrine.sh"
bootstrap_user_global_doctrine "$ROOT"
```

- install.sh 의 productune.env interactive engine selection (L648+) 은 **무변경** — 함수 범위 밖. 함수 호출 후 정상 실행됨.
- 기존 모든 동작 (PRODUCTUNE_REPO export + agents wire + codex config + wiki backend + legacy codex migrate L562) 보존.

### C. `packages/core/scripts/productune` `init)` handler 갱신

`exit 0` 직전에 doctrine bootstrap 추가:

1. **진입 직후** flag parse (`--skip-doctrine`) — git init 로직 전.
2. 기존 scaffold 로직 **무변경**.
3. scaffold 완료 후 SCRIPTS_DIR / DOCTRINE_ROOT 유도:

```bash
SCRIPTS_DIR="$(cd "$(dirname "${BASH_SOURCE[0]:-$0}")" && pwd -P)"
DOCTRINE_ROOT="$(cd "$SCRIPTS_DIR/.." && pwd)"
```

4. `source "$SCRIPTS_DIR/lib/bootstrap-doctrine.sh"`
5. `bootstrap_user_global_doctrine "$DOCTRINE_ROOT"` 호출 (`SKIP_DOCTRINE=0` 일 때)

### D. `--skip-doctrine` flag 처리

```
usage: productune init [--skip-doctrine]

  --skip-doctrine   user-global doctrine bootstrap 건너뜀.
                    CI / 커스텀 doctrine 환경용 escape hatch.
                    project-level scaffold (.productune/, docs/pdt-*/, .gitignore)는 정상 실행.
```

`set -euo pipefail` 환경에서 `for _arg in "$@"` 순회로 안전하게 파싱. `init)` 분기 진입 직후, git init 전에 수행.

### E. 사용자 trace

신규 설치 완료 시 1회:
```
[productune] doctrine 시스템 파일 설치 완료.
```
(stderr, `say()` / `warn()` 기존 prefix 스타일 유지)

`--skip-doctrine` 사용 시:
```
[productune] doctrine bootstrap skipped (--skip-doctrine)
```

## §6 §1.5 Self-Check

CLI install flow 가 대상 — GUI screen 없음. 운영자/개발자 UX (터미널 출력) 에 원칙 적용.

| Principle | 적용 | 상태 |
|:--|:--|:--|
| **Few Things** | 변경 파일 5개 (CREATE 1 + UPDATE 3 + APPEND 1). 사용자 체감 변화는 `productune init` 실행 후 doctrine 파일 생성 1가지. flag 1개 추가 (`--skip-doctrine`). 기존 명령 인터페이스 무변경. | ✓ |
| **Familiar** | `productune init` 문법 무변경. scaffold 출력 형식 (`[productune] created: ...`) 기존과 동일. doctrine bootstrap 출력도 같은 `say()` prefix 스타일. `--skip-doctrine` 는 `git init --bare` 류의 관례적 flag 네이밍. | ✓ |
| **Predictability** | idempotent 재실행 시 po-memory.md / productune.env 절대 덮어쓰지 않음 — 예측 가능 보존 정책. `cmp -s` 동일이면 silent — 재실행해도 노이즈 없음. `--skip-doctrine` 은 one flag = one effect (doctrine 만 skip, scaffold 정상). | ✓ |
| **Feedback** | 신규 설치 시 파일별 `say` 출력 + 종합 완료 메시지. `--skip-doctrine` 사용 시 명시적 skip 메시지. lib 파일 미발견 시 `warn` + graceful continue (non-fatal). | ✓ |
| **Escape** | `--skip-doctrine` 제공 — CI / 커스텀 환경 완전 탈출 경로. lib 파일 부재 = non-fatal warn + return 0 (init 전체 실패 없음). po-memory.md 불변 보장 — "실수로 지워진다" 공포 없음. | ✓ |
