# T-P4-076: PersonaPresenceBar wiring — useBackgroundTasks derive (T-P4-049 spec gap fix)

## Background

사용자 dogfood 발견 (2026-05-08, T-P4-068 land 직후 manual 검증 중): PO 가 sub-agent 를 dispatch 해도 PersonaPresenceBar 의 페르소나 dot 이 회색 idle 그대로 머무름. T-P4-068 BackgroundTaskSegment 는 task 정상 표시 — 같은 spawn 이벤트가 한쪽엔 도달하지만 PresenceBar 까지는 안 가는 상태.

**Root cause**: `packages/gui/src/store/personaPresence.ts` 의 `setPersonaState` action 이 정의만 되어 있고 caller 가 0. T-P4-049 spec 에 명시된 `persona-status:update` IPC bridge 가 구현 누락된 채 049 가 done 마킹된 pre-existing bug (회귀 X).

**사용자 결정 (2026-05-08)**: **store derive 방식** 채택 — 별 IPC 채널 신설 X. `useBackgroundTasks.tasks` 의 running persona 를 watch 해서 `personaPresence` 자동 sync. po-runner 변경 X. T-P4-049 spec 의 IPC + 산출물 경로 추출 (designer `design_doc_path` 등) artifact extraction 은 본 ticket 범위 밖, 별 follow-up ticket 으로 미룸. Task tool 의 `description` 이 done tooltip 에 노출되는 정도면 충분.

## Acceptance

### A) Store derive (PresenceBar 측 useEffect)

`PersonaPresenceBar.tsx` (또는 별 hook `usePersonaPresenceFromTasks` 로 분리해도 OK — dev 판단) 에 `useBackgroundTasks.tasks` subscribe 후 derive 로직 적용:

- [ ] **persona scope**: `designer` / `dev` / `qa` 3 종 (PO 자체는 derive 대상 X — PO 는 전경 chat, sub-agent 아님). `unknown` persona task 는 PresenceBar 갱신에 사용 X (경고 무시).
- [ ] **working transition**: persona 별 `running` 카운트 ≥ 1 → `setPersonaState(persona, 'working')` 호출. 이미 working 상태면 noop (updatedAt 만 갱신 — store 가 idempotent 처리).
- [ ] **done transition**: 직전 turn 까지 `running` 이었다가 이번 turn 에 0 으로 떨어지고 그 transition 직후 done/error 로 전환된 task 가 있으면 → `setPersonaState(persona, 'done', artifact)` 호출. `artifact` = 마지막 done task 의 `description` (이미 80 chars truncate 되어 있음 → 60 chars 추가 truncate 권장, ellipsis 동일 패턴).
  - 같은 useEffect tick 안에 done 발생 + 새 working 시작이 겹치면 working 우선 (running 0 → done 분기에 안 들어감).
  - error status 도 done 분기에 포함 (error 시 done 색이 아닌 처리는 별 enhancement — 본 ticket 은 done state 로만 표기).
- [ ] **idle 유지**: running 0 + done transition 발생 X → idle 유지 (transition 없음, set 호출 X — 불필요 re-render 회피).
- [ ] **direction**: 이 derive 는 `useBackgroundTasks → personaPresence` 단방향. PresenceBar 에서 직접 setPersonaState 호출하는 기존 호출자 (없음 확인 — caller 0) 와 충돌 X.

### B) Done dismiss 정합

- [ ] 기존 done dismiss 로직 (chip outside click → idle, `dismissDone(persona)`) 그대로 유지.
- [ ] dismiss 후에도 `useBackgroundTasks` 의 done task 가 살아 있으면 derive useEffect 가 다시 done 으로 set 하지 않도록 가드 — 즉 derive 는 "running → 0 transition 직후 1 회만 done 마킹". 이미 같은 done task 를 처리했으면 skip. 구현은 dev 판단 (`useRef<Set<string>>` 으로 처리한 task id 캐시 권장).

### C) Session restart 정합

- [ ] `WorkspaceShell.tsx` 의 session restart handler (line ~116 부근, `useBackgroundTasks.resetAll()` 호출 지점) 에서 **`personaPresence.resetAll()` 도 같이 호출**.
- [ ] 둘이 동시에 비워지므로 derive useEffect 가 다음 tick 에서 idle 상태로 안정.

### D) 회귀

- [ ] **T-P4-068 BackgroundTaskSegment 정합**: 같은 store (`useBackgroundTasks`) 가 source — 시각만 두 군데 표시 (StatusBar segment + PresenceBar dot). count, popup, focus-aware 5s countdown 등 기존 동작 영향 X.
- [ ] **PresenceBar count badge (≥2) 정합**: T-P4-068 에서 추가된 14px count badge 가 working 상태에서 정상 표시 — derive 로직이 setPersonaState 호출 시 store updatedAt 만 변경하지 count badge 로직과 무관.
- [ ] **PO chip**: PO 는 derive 대상 아님이므로 store 의 PO entry 는 다른 source (없음 — 기존에도 caller 0) 또는 영구 idle 유지. PO chip 시각 = 항상 idle.

## QA scenarios (light)

1. **single working** — sub-agent 1 호출 → 해당 persona dot blink (working 색)
2. **multi working** — designer × 2 동시 → designer dot blink + count badge "2"
3. **done transition** — task complete → dot done ✓ 색 + tooltip 에 description 60 chars 표시
4. **outside click dismiss** — done chip hover 후 외부 click → idle 회색 복귀 + derive 가 다시 done 으로 set 하지 않음
5. **session restart** — restart click → 모든 dot idle 회색 (BackgroundTaskSegment 와 동시 reset)
6. **PO autonomy** — PO 자체는 derive 대상 아님 → PO chat 내내 PO chip idle 유지
7. **error status** — sub-agent 가 error 로 끝나도 done state 로 표기 (별 색 분기는 본 ticket 범위 X)
8. **rapid spawn-complete** — sub-agent 가 매우 빠르게 완료 (< 100ms) → working 표시 skip 가능, 최소 done state 는 노출
