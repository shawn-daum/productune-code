## §1 Request

**Origin**: T-P4-124 OQ-K gap candidate G2 — Phase 4 (Deploy / Ops) has no skill loaded at dispatch time. Deploy operations (env var management, build validation, smoke verification, rollback) are ad-hoc. G2 fills the gap with a productune-native `deploy-playbook` skill.

**Scope**: author `~/.claude/skills/productune/deploy-playbook/SKILL.md` — self-executed by pdt-designer at impl turn (doctrine doc, no code). Once shipped, pdt-developer + pdt-po can load this skill on Phase 4 dispatch.

**Why needed**: productune Phase 4 (the "Deploy & Validate" phase in po-loop.md) has no structured checklist. A `deploy-playbook` skill provides:
- Pre-deploy gate (env vars set, build clean, migration state checked)
- Build + typecheck command sequence
- Smoke verification steps (boot → one endpoint / one route / one CLI call)
- Rollback trigger criteria + restore steps
- productune-specific paths (`packages/gui/`, `packages/core/`, `packages/cli/`)

## §2 Acceptance

### A1. Skill file authored
`~/.claude/skills/productune/deploy-playbook/SKILL.md` exists with valid frontmatter:
```yaml
name: deploy-playbook
description: >
  Productune Phase 4 deploy checklist. Pre-deploy gate (env / build / migration),
  smoke verification steps, rollback criteria. Load when executing or reviewing
  a deploy / release operation.
personas: [po, developer]
```

### A2. Skill body covers 5 sections
1. **Pre-deploy gate** — env var audit (`PRODUCTUNE_*`, `GRAPHITI_*`, `ANTHROPIC_*`), build clean check, migration status
2. **Build sequence** — ordered command list: typecheck → build → unit tests (changed files only) → bundle size delta check
3. **Smoke verification** — per surface: GUI (dev server boot → one route load), CLI (one invocation), Core (one API round-trip)
4. **Rollback criteria + steps** — trigger conditions (build fail / smoke fail / P0 regression), restore steps (`git revert` + env restore note)
5. **productune-specific paths** — workspace layout (`packages/gui/`, `packages/core/`, `packages/cli/`), shared config roots

### A3. po-loop.md Phase 4 section references skill
`~/.productune/sections/po-loop.md` (or equivalent lifecycle doc) Phase 4 block includes:
> `skill: productune/deploy-playbook — load at Phase 4 deploy dispatch.`

If po-loop.md structure does not have a named Phase 4 block, impl turn designer adds a note to `docs/designer/decisions.md` instead (no-op on po-loop.md).

After file is authored, SkillMatrixTab shows `deploy-playbook` row with persona scope = po + developer (both checked).
