## §1 Request

**사용자 dogfood verbatim:**
> "신규 프로젝트 onboarding 끝나고 FreshComposer 에 첫 메시지를 보내면 PO 답변이 영영 안 떠."

### Root cause (요약)

`FreshComposer.handleSend` → `api.poSendMessage()` → main process `runPoTurn` 이 **첫 줄에서**
`cb.onMsgId(msgId)` → `wc.send('po:onMsgId', msgId)` 동기 발사.
이 시점 `ChatPanel` 은 아직 mount 전 (WorkspaceShell reveal 이전) → Electron 은 IPC
buffer 가 없으므로 listener 미등록 이벤트를 **drop**. 이후 `po:onToken` 들은
placeholder bubble (msgId 매칭) 을 못 찾아 setState 가 모두 no-op → PO 응답 영구
미표시. user 메시지는 `chatAppendMessage` 가 await 돼 정상 persist 됨 (반쪽 동작).

### 채택안: B — renderer listener uplift

ChatPanel 의 `useEffect` 안에서 등록되던 PO/QA/Todo/Browser IPC subscription 을
**`packages/gui/src/store/poEvents.ts` (신규)** 모듈 top-level 로 uplift. App.tsx 가
`import './store/poEvents'` 한 줄로 side-effect import → JS load 시점에 1회 등록 →
**listener-before-send 가 구조적으로 보장**.

`inFlightMsgId` / `inFlightKind` 는 ChatPanel 의 useRef 에서 `useWorkspace` store
state 로 승격 — module-level handler 가 `getState/setState` 로 접근.

### 거부안 (plan §2 참조)
- **A** main onMsgId 발사 지연: race window 폭만 늘림. 빠른 머신 / echo / 짧은 응답에서 재발.
- **C** FreshComposer 직접 구독: 중복 구독, role 비대화, entry 화면마다 복붙 부채.

전체 설계는 → **`docs/design/T-P4-119/plan.md`** 참조 (이 ticket 의 source of truth).

## §2 Scope

### A. 신규 — `packages/gui/src/store/poEvents.ts`

- 모듈 top-level `register()` 1회 호출. `let registered = false` flag 로 idempotent.
- 등록 listener (현재 ChatPanel.tsx 에서 옮겨오는 것):
  - `poOnMsgId` — placeholder Message 생성 + `inFlightMsgId` set.
  - `poOnToken` — msgId 매칭 후 text concat.
  - `poOnAnnounce` — system `trace` 메시지 push.
  - `poOnDone` — done 표시 + `chatAppendMessage` persist + `chatSetClaudeSessionId` + `inFlightMsgId` null + `streaming` false.
  - `poOnTodoItems` / `poOnTodoDismiss` — `useUserTodo.getState()` 액션 호출.
  - `onBrowserOpen` / `onUserVerify` / `onQaLoopUpdate` — `useWorkspace.getState().openTab` / `useUserTodo` / `useQaLoop` 액션 호출.
- 추가로 grep 으로 다른 컴포넌트(WorkspaceShell 등)에 등록된 IPC listener 발견 시 동일 이동:
  - `poOnHealth`
  - `poOnTicketFocus`
  - `poOnArtifactOpen`
  발견 안 되면 본 티켓 §Persona Activity 에 "grep 결과: 해당 위치 없음" 기록만 남김.
- `useWorkspace.subscribe` 로 `project.projectDir` 변경 감지 → `inFlightMsgId/Kind/streaming` reset.
- `import.meta.hot.dispose` 에서 `offFns` 일괄 호출 + `registered = false`.

→ 전체 코드 sketch 는 plan §3.1 참조 (그대로 사용 가능).

### B. 수정 — `packages/gui/src/App.tsx`

기존 import 블록 마지막에 1줄 추가:

```ts
import './store/poEvents'  // T-P4-119: PO IPC subscriptions registered at module load.
```

다른 변경 없음.

### C. 수정 — `packages/gui/src/store/workspace.ts`

- `WorkspaceState` 에 `inFlightMsgId: string | null` + `inFlightKind: MessageKind` 추가.
- initial: `inFlightMsgId: null`, `inFlightKind: 'po'`.
- setter: `setInFlightMsgId`, `setInFlightKind`.
- `resetSession()` 도 두 필드 reset 포함.
- `MessageKind` import 추가 (필요 시).

### D. 수정 — `packages/gui/src/components/workspace/ChatPanel.tsx`

**제거:**
- `inFlightMsgIdRef` / `inFlightKindRef` useRef 선언 (Line 65–66 부근).
- PO subscribe `useEffect` 블록 전체 (Line 82–160 부근 — poOnMsgId / poOnToken / poOnAnnounce / poOnDone).
- Todo subscribe `useEffect` 블록 (Line 162–180 — poOnTodoItems / poOnTodoDismiss).
- QA/Browser/Verify subscribe `useEffect` 블록 (Line 186–240 — onBrowserOpen / onUserVerify / onQaLoopUpdate) + 그 위의 `openTabFn` 변수.

**유지:**
- `chatGetSession` 로 messages 로드하는 `useEffect`.
- auto-scroll / textarea autosize 등 순수 UI effect.
- `handleSubmit` 본체 (단, 아래 2 곳 수정).

**수정:**
- `inFlightKindRef.current = 'po'` → `useWorkspace.getState().setInFlightKind('po')`.
- `catch { setStreaming(false); inFlightMsgIdRef.current = null }` →
  `catch { setStreaming(false); useWorkspace.getState().setInFlightMsgId(null) }`.
- 미사용 import (`MessageKind`, `useUserTodo`, `useQaLoop`, `createPortal` 일부 등) 정리 — 컴파일 에러 없도록.

### E. 다른 컴포넌트 IPC 점검 (grep)

`packages/gui/src` 전역 grep 으로 다음 keyword 가 ChatPanel.tsx 외에 사용되는지 확인:
- `poOnHealth` `poOnTicketFocus` `poOnArtifactOpen` `onBrowserOpen` `onUserVerify` `onQaLoopUpdate`

발견 시: 해당 컴포넌트의 `useEffect` 에서 listener 등록 부분을 제거하고 `store/poEvents.ts` 에 통합.

| AC10 | `pnpm build` + `pnpm tsc --noEmit` + `pnpm dev` 모두 pass. |

## §Out of scope

- **Echo mode 동작 변경** — main process `runPoTurn` 의 echo fallback 로직 그대로.
- **Claude spawn 자체 로직** — `claude --output-format stream-json` 호출, stream parse 변경 없음.
- **Health banner 동작 미변경** — `po:onHealth` listener 위치만 옮김 (발견 시). 표시 UX / 임계값 / dismiss 동작 동일.
- **Main process 의 onMsgId 발사 시점 조정** (A안 — plan §2 거부).
- **FreshComposer 직접 IPC 구독** (C안 — plan §2 거부).
- **"Stop generation" UX** 같은 `inFlightMsgId` 활용 신규 기능 — 별도 티켓.
- **Streaming 도중 프로젝트 전환 시 main side abort** — 현재는 renderer 가 silently drop. 추후 별도 검토.
