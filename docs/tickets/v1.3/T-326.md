## Request

**productune 제품 기능 (v1.x, b안)**: PO(및 필요시 워커)의 **어투·어휘 수위를 대상 사용자에 맞추는 "기획자/개발자 모드"** 를 (재)도입. 도그푸딩(enneagram-mentor)에서 관측: 현 PO 어투가 파워유저엔 좋지만 타겟(비개발 기획자)엔 인지부하 큼 — 스키마명·영어 jargon(out-of-scope·YAGNI·resonance rate)·조밀한 옵션표.

배경: 예전에 기획자/개발자 모드가 있었음 → 그 구현을 참고자료로 되살림.

### 방향 (Define/PRD에서 확정)
- **모드**: `planner`(기본, 평이한 어휘·jargon 최소·progressive disclosure — 결론 먼저, 깊은 근거·표·용어는 요청 시) / `developer`(현행 — 기술 어휘 OK).
- **설정 지점**: 온보딩에서 선택 + 설정(settings)에서 변경.
- **구현 메커니즘 (핵심 구분)**:
  - 고정 UI 문자열(버튼·라벨·온보딩 카피) → **i18n** (기존).
  - PO의 **대화 출력**은 모델 생성 프로즈라 i18n 불가 → **discipline/prompt harness**로: audience-mode를 PO 컨텍스트에 주입(현 user-override 주입과 동일 메커니즘). "planner면 기획자 어휘·jargon 최소·점진적 공개."
  - persona 표시명 매핑(`prdt-designer`→"Designer")은 고정 라벨이라 **별개** — register 해결책 아님.

## Acceptance (Define/PRD에서 상세화)

- 온보딩에서 기획자/개발자 모드 선택, 설정에서 변경 가능. 선택이 저장됨.
- planner 모드에서 PO 출력이 평이한 어휘·jargon 최소·progressive disclosure로 나옴(대화 register가 실제로 바뀜). developer 모드는 현행 유지.
- UI 고정 문자열은 i18n, PO 대화 register는 컨텍스트-주입 harness로 — 두 경로 분리.

- 모드 수: 2개(planner/developer)면 충분? 그 이상?

- 예전 기획자/개발자 모드 구현 위치·형태(참고자료) — 어디에 있었는지 추적.
