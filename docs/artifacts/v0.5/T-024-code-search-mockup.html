① 검색 위치 — Explorer 내부 섹션

VS Code 는 검색을 별도 activity-bar view 로 둔다. productune 은 ticket 범위(AC-1)대로 Explorer pane 안의 접이식 "Search in files" 섹션으로 배치 — rail 아이콘을 늘리지 않아 §1.5.1 Few-Things 를 지킨다. 입력 후 FILES 트리는 자동 접힘.

② 옵션 토글 — VS Code 관용

Aa 대소문자 · |ab| 전체 단어 · .* 정규식. 입력란 우측 정사각 토글(22px), on = accent 테두리 + 18% fill. 같은 화면 색상 요소 ≤ 4 (§1.2) 준수: accent 한 종만 추가.

③ 결과 그루핑 + 라인

파일별 group(파일명 + 경로 + match 수 badge) → 펼치면 라인번호 + 코드 + match 하이라이트(mark = accent 30% alpha). mono 폰트. group 헤더 클릭 = 접기/펼치기, summary 의 collapse-all 로 일괄.

④ open-at-match (AC-3)

match 라인 클릭 → 기존 openTab 경로로 파일 탭 열고 해당 라인으로 스크롤 + 줄 하이라이트(좌측 2px accent bar). 활성 match 는 더 진한 하이라이트(55% alpha)로 출처 표시.

⑤ 상태 4종 (§1.5.3 / §8.9)

Empty 입력 전 placeholder + 단축키 안내 · Loading skeleton shimmer + aria-live("검색 중") · Results summary(건수·파일수) + 목록 · No-result Empty-pane 패턴 + 옵션/범위 조정 제안(출구, §1.5.5).

⑥ scope + ignore (AC-4)

scope 선택자: Whole project ↔ 현재 폴더. node_modules / .git / build 항상 제외 — hint 로 명시. 입력은 debounce(설계 의도, 240ms), 결과 streaming 표시로 UI freeze 방지(impl 노트).
