Tab overflow shrink + drag-to-edge auto-split

Two coupled behaviors for the workspace pane system, drawn against the productune R4 design system (dark-only, --accent #8B5CF6 brand purple, lucide icons). The mockup is interactive — toggle tab counts, hover the drop-zones. Annotations call out the load-bearing decisions for sign-off.

#4a

Chrome-style tab overflow shrink

Tabs flex to fit the strip so all stay visible — none are pushed off. As more open, each tab shrinks toward a min-width; titles truncate with an ellipsis; below thresholds the per-tab close × and leading icon drop (the active tab always keeps its ×). The right-side control cluster (splitButtons: split-right / split-down / close-pane) is a protected zone — flex-shrink:0 — so it can never be shrunk, moved, or covered. When tabs hit min-width, the strip becomes horizontally scrollable instead of overflowing.

Shrink rule

Tab basis = (strip width − controls) / N, clamped to [min 34px … max 200px]. Each tab is flex:1 1 auto; min-width:34px; the active tab keeps priority for legibility.

Progressive truncation

≥120px: title + icon + ×. tight (<120px): hide inactive ×. min (≤56px): hide leading icon too; title ellipsis only. Active tab is exempt — always shows title + ×.

Protected control zone

The split / close-pane cluster is flex-shrink:0 with a guard shadow. It never yields width to tabs at any count or window size — AC-2. Tabs overflow into scroll, not over the controls.

#4b

Drag-tab-to-edge → auto-split (cmux / VS Code style)

While dragging a tab over a pane body, an overlay of drop-zones appears: four half bands (left / right / top / bottom), four quarter corners, and a center "add as tab" zone. Hovering a zone highlights it and renders a preview of the resulting layout; the drag ghost trails the cursor. Dropping calls the existing store primitives — edge → splitRight / splitDown + moveTab; center → plain moveTab into this pane. Reorder-DnD inside the bar is untouched (AC-5).
